# 0.3 Ressourcen-Planung (RAM Allocation)

## Strategie der Speicherzuweisung

Beide physischen Hosts verfügen über jeweils 40 GB Arbeitsspeicher. Um eine optimale Performance aller virtuellen Maschinen zu gewährleisten, wird zwischen **statischer** (fest zugewiesener) und **dynamischer** Speicherverwaltung unterschieden. Infrastruktur-Kernelemente (Firewall, Domain Controller) erhalten fixen RAM, während Clients zur besseren Auslastung Dynamic Memory nutzen.

## Host 1 (Hauptquartier) – Gesamtkapazität: 40 GB RAM

| **Hostname** | **VM-Rolle** | **RAM** | **Zuweisungstyp / Notiz** |
| --- | --- | --- | --- |
| FW-HQ-01 | OPNsense Firewall | 4 GB | Statisch (Kein Swapping für Routing) |
| SRV-DC-01 | Primärer DC (PDC) | 4 GB | Statisch (AD-Datenbank-Caching) |
| SRV-WEB-01 | Apache Web (DMZ) | 2 GB | Dynamisch (Max. 4 GB) |
| CL-WIN-01 | Windows 11 Client | 8 GB | Dynamisch (Desktop-Performance) |
| CL-UBU-01 | Ubuntu Client | 4 GB | Dynamisch (Standard-Office-Nutzung) |
| **Reserviert für Host-OS (Hyper-V)** |  | ~ **18 GB** | Puffer für Snapshots und File-Transfers |

## Host 2 (Filiale) – Gesamtkapazität: 40 GB RAM

| **Hostname** | **VM-Rolle** | **RAM** | **Zuweisungstyp / Notiz** |
| --- | --- | --- | --- |
| FW-FIL-01 | OPNsense Firewall | 4 GB | Statisch (VPN-Verschlüsselung) |
| SRV-DC-02 | Sekundärer DC | 4 GB | Statisch (Replikation) |
| CL-KALI-01 | Kali Linux (KI / Ollama) | 24 GB | Statisch (Extremer Bedarf für LLM-Modelle) |
| **Reserviert für Host-OS (Hyper-V)** |  | ~ **8 GB** | Ausreichend, da wenig IOPS auf Host-Ebene |

## Wichtige architektonische Hinweise

- **KI-Ressourcen:** Die Ausführung lokaler Sprachmodelle (LLMs wie LLaMA3 oder Mistral) via Ollama erfordert massive Arbeitsspeicherkapazitäten, um die Modelle in den RAM zu laden. Daher erhält `CL-KALI-01` mit 24 GB den Löwenanteil des Filial-Hosts.
- **Dynamic Memory (Modul 1.7):** Für die Clients im HQ wird Dynamic Memory in Hyper-V aktiviert. Die angegebenen Werte entsprechen dem Start-RAM.
