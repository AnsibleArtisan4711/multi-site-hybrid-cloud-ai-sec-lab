# 0.2 Namenskonvention

## Standardisierte Hostnames

Eine konsistente Namenskonvention ist für die saubere Administration, die DNS-Auflösung und die Verwaltung im Active Directory essenziell. Folgende Nomenklatur wird für die Systeme im Projekt festgelegt:

| **Kategorie** | **Hostname** | **Beschreibung / Rolle** |
| --- | --- | --- |
| **Netzwerk & Security** | FW-HQ-01 | OPNsense Firewall im Hauptquartier (Host 1) |
|  | FW-FIL-01 | OPNsense Firewall in der Filiale (Host 2) |
| **Infrastruktur (AD)** | SRV-DC-01 | Primärer Domain Controller (PDC) im HQ |
|  | SRV-DC-02 | Sekundärer / Zusätzlicher Domain Controller in der Filiale |
| **Server & Dienste** | SRV-WEB-01 | Apache Webserver in der DMZ (Ubuntu) |
|  | STO-NAS-01 | 40TB NAS Storage (Backup & Shares) |
| **Clients & Endgeräte** | CL-WIN-01 | Windows 11 Client im HQ |
|  | CL-UBU-01 | Edubuntu/Ubuntu Client im HQ |
|  | CL-KALI-01 | Kali Linux (Ollama / KI-Analyse) in der Filiale |

## Regelwerk der Nomenklatur

Um ein Ausufern der Bezeichnungen zu verhindern, folgt das Naming-Schema strikten Regeln:

- **Präfixe (Systemtyp):** `FW` (Firewall), `SRV` (Server), `STO` (Storage), `CL` (Client).
- **Standort oder Rolle:** `HQ` (Hauptquartier), `FIL` (Filiale), `DC` (Domain Controller), `WEB` (Webserver).
- **Zähler:** Zweistellige Nummerierung (`01`, `02`,...), um sofortige Skalierbarkeit für zukünftige Erweiterungen ohne Namensbrüche zu gewährleisten.
