# 8.2 Ollama Installation & Modell-Management

## Konzept: Die lokale KI-Engine

Um eine datenschutzkonforme und performante Log-Analyse ohne Cloud-Anbindung zu realisieren, nutzen wir **Ollama**. Dies ist eine Open-Source-Plattform, die es ermöglicht, Large Language Models (LLMs) lokal auszuführen.

Dank der 24 GB RAM auf dem `CL-KALI-01` können wir Modelle mit bis zu 8 Milliarden Parametern (8B) vollständig in den Arbeitsspeicher laden, was eine nahezu verzögerungsfreie Analyse der in Phase 7 gesammelten JSON-Logs erlaubt.

## Schritt 1: Installation von Ollama

Ollama bietet ein automatisiertes Installationsskript für Linux an, das alle Abhängigkeiten auflöst und die Engine als System-Dienst einrichtet.

**Ollama One-Liner Installation**

```bash
# Download und Installation ausführen
curl -fsSL https://ollama.com/install.sh | sh
```

## Schritt 2: Dienst-Status verifizieren

Nach der Installation sollte Ollama automatisch im Hintergrund laufen.

**Systemd Status Check**

```bash
sudo systemctl status ollama
```

*Ergebnis:* Der Status muss **active (running)** anzeigen. Ollama lauscht standardmäßig auf `127.0.0.1:11434`.

## Schritt 3: Download der LLM-Modelle

Wir laden zwei komplementäre Modelle herunter: Eines für die allgemeine Analyse und eines, das speziell auf technisches Verständnis optimiert ist.

**3.1 Llama 3 (8B):** Das Flaggschiff von Meta. Ideal für komplexe Zusammenhänge.

```bash
    ollama pull llama3
```

**3.2 Mistral:** Ein sehr schnelles und effizientes Modell aus Europa.

```bash
    ollama pull mistral
```

## Schritt 4: Kapazitäts-Check (RAM-Auslastung)

Wir prüfen, wie effizient die 24 GB RAM genutzt werden. Starten Sie das Modell interaktiv:

**Interaktiver KI-Test**

```bash
ollama run llama3
```

Geben Sie eine Testfrage ein (z. B. *„Was ist der Windows Event ID 4624¿‘*). Öffnen Sie währenddessen ein zweites Terminal und prüfen Sie die Auslastung:

```bash
top  # oder 'htop', falls installiert
```

*Beobachtung für das Portfolio:* Ein 8B-Modell belegt ca. 4,8 GB bis 5,5 GB RAM. Dank Ihrer 24 GB Architektur können Sie sogar mehrere Instanzen oder deutlich größere Modelle (bis zu 13B oder 20B bei hoher Quantisierung) parallel betreiben.

## Schritt 5: Erster Security-Smoke-Test

Wir testen, ob die KI strukturierte JSON-Logs aus Phase 7 interpretieren kann. Kopieren Sie ein Beispiel-Log in den Prompt:

> **Test-Prompt:**\
> *„Analysiere folgendes JSON Log auf Anomalien: {“Timestamp“: „2023-12-04T10:00:00“, „ID“: 4625, „User“: „Administrator“, „Msg“: „Anmeldefehler“}“*

*Erwartete Antwort:* Die KI sollte erkennen, dass ID 4625 für einen fehlgeschlagenen Login steht und den Benutzer „Administrator“ als kritisches Ziel identifizieren.

> [!NOTE]
> **Portfolio-Check: KI-Infrastruktur-Design**\
> Dokumentieren Sie diesen Meilenstein: Sie haben erfolgreich eine **lokale Inference-Engine** etabliert. Erklären Sie, dass Ollama als API-Gateway fungiert, über das wir in Modul 8.3 automatisierte Python-Skripte anbinden, um die Log-Dateien vom NAS-Archiv im Batch-Verfahren zu scannen. Dies ist die moderne Antwort auf die Flut an Sicherheitsereignissen in Multi-Site Umgebungen.
