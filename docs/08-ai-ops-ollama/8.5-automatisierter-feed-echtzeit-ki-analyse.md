# 8.5 Automatisierter Feed (Echtzeit-KI-Analyse)

## Konzept: Vom statischen Skript zum SIEM-Dienst

Bisher mussten wir die Log-Analyse manuell anstoßen. In einer Multi-Site-Umgebung mit DMZ-Webservern und zwei Domain Controllern ist eine kontinuierliche Überwachung zwingend. Wir implementieren nun einen **KI-Watcher**.

**Der automatisierte Prozess:**

1. **Ingestion:** Neue JSON-Logs landen in der Dropzone (Samba/rsyslog).
2. **Trigger:** Ein Python-Dienst erkennt die neuen Dateien sofort.
3. **Inference:** Die Daten werden mit dem Security-Prompt (Modul 8.4) an Ollama gesendet.
4. **Archivierung:** Analysierte Dateien werden in den Archiv-Ordner verschoben, um Doppel-Analysen zu vermeiden und Token zu sparen.

## Schritt 1: Der Enhanced KI-Watcher (Python)

Dieses Skript nutzt die Bibliothek `watchdog`, um das Dateisystem in Echtzeit zu überwachen.

**Python-Skript: ki\_siem\_daemon.py**

```python
import os
import time
import shutil
import requests
from watchdog.observers import Observer
from watchdog.events import FileSystemEventHandler

# Pfade definieren
WATCH_DIR = "/var/lib/siem-hub/windows-json/"
ARCHIVE_DIR = "/var/lib/siem-hub/analysis/archive/"
OLLAMA_URL = "http://localhost:11434/api/generate"

class LogHandler(FileSystemEventHandler):
    def on_created(self, event):
        if event.is_directory: return
        if event.src_path.endswith(".json"):
            print(f"[*] Neue Log-Datei erkannt: {event.src_path}")
            self.process_log(event.src_path)

    def process_log(self, file_path):
        with open(file_path, 'r') as f:
            content = f.read()

        # API Call an Ollama (mit Security Context aus 8.4)
        payload = {
            "model": "llama3",
            "prompt": f"Analysiere auf Brute Force oder Privilege Escalation: {content}",
            "stream": False
        }

        try:
            response = requests.post(OLLAMA_URL, json=payload)
            analysis = response.json().get('response')

            # Ergebnis sichern
            report_name = os.path.basename(file_path).replace(".json", "_report.txt")
            with open(f"/var/lib/siem-hub/analysis/{report_name}", "w") as r:
                r.write(analysis)

            # Datei archivieren
            shutil.move(file_path, os.path.join(ARCHIVE_DIR, os.path.basename(file_path)))
            print(f"[+] Analyse abgeschlossen fuer {report_name}")
        except Exception as e:
            print(f"[!] Fehler: {e}")

if __name__ == "__main__":
    if not os.path.exists(ARCHIVE_DIR): os.makedirs(ARCHIVE_DIR)
    observer = Observer()
    observer.schedule(LogHandler(), WATCH_DIR, recursive=False)
    observer.start()
    try:
        while True: time.sleep(1)
    except KeyboardInterrupt:
        observer.stop()
    observer.join()
```

## Schritt 2: Einrichtung als Systemd-Service

Damit die KI-Analyse auch nach einem Neustart des Kali-Clients sofort wieder läuft, erstellen wir einen Linux-Dienst.

**2.1** Erstellen Sie die Service-Datei:

```bash
    sudo nano /etc/systemd/system/ki-siem.service
```

**2.2** Fügen Sie folgenden Inhalt ein:

```bash
   [Unit]
    Description=Kali AI SIEM Log Analyzer
    After=ollama.service

   [Service]
    ExecStart=/usr/bin/python3 /home/kali/scripts/ki_siem_daemon.py
    WorkingDirectory=/home/kali/scripts
    StandardOutput=inherit
    StandardError=inherit
    Restart=always
    User=kali
   [Install]
    WantedBy=multi-user.target
```

**2.3** Aktivieren und Starten des Dienstes:

```bash
    sudo systemctl daemon-reload
    sudo systemctl enable ki-siem.service
    sudo systemctl start ki-siem.service
```

## Schritt 3: Monitoring der Pipeline

Sie können nun live beobachten, wie die KI arbeitet, indem Sie das System-Log von Kali mitverfolgen:

```bash
journalctl -u ki-siem.service -f
```

> **Portfolio-Check: Das autonome SOC**\

> Besonderes Highlight für die Projektdokumentation: Die Entkopplung durch den Systemd-Service (*Dependency Management*). Die KI-Analyse wartet automatisch, bis die Ollama-Engine geladen ist, bevor sie mit dem Scannen der Logs beginnt. Dies ist ein Zeichen für professionelles System-Engineering.
