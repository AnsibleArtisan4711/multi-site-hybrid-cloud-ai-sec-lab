# 8.7 Simulation & Verifizierung (KI-Attack-Test)

## Konzept: Validierung der gesamten Security-Pipeline

In diesem Modul schlüpfen wir in die Rolle des Angreifers (Red Team), um die Wirksamkeit der Verteidigung (Blue Team / AI-Ops) zu beweisen. Wir testen die komplette Kette:

1. **Angriff:** Kali-VM startet einen Brute-Force-Angriff auf den Domain Controller.
2. **Detection:** Windows generiert Event-ID 4625 (Fehlgeschlagener Login).
3. **Transport:** WEF sendet das Log an DC-01, PowerShell konvertiert es zu JSON und pusht es zu Kali.
4. **Analysis:** Der KI-Daemon erkennt die neue Datei und lässt Ollama (Llama 3) die Bewertung vornehmen.
5. **Response:** Das System sendet einen Alert an Microsoft Teams.

## Schritt 1: Start des Simulations-Angriffs

Wir nutzen das Tool `hydra` auf der **`CL-KALI-01`**, um hunderte Login-Versuche gegen den `SRV-DC-01` zu simulieren.

**SMB Brute Force Simulation auf Kali**

```bash
# Installation von Hydra (falls nicht vorhanden)
sudo apt update && sudo apt install hydra -y

# Start des Angriffs gegen den Domain Controller im HQ
# Wir nutzen eine kleine Passwortliste, um Rauschen zu erzeugen
hydra -l Administrator -P /usr/share/wordlists/fasttrack.txt smb://10.0.10.10
```

## Schritt 2: Überwachung des Log-Eingangs

Während der Angriff läuft, prüfen wir auf dem Kali-Hub, ob die JSON-Datenpakete in der Dropzone ankommen.

**Live-Monitoring der Ingestion**

```bash
# Beobachten des Eingangsordners
ls -lh /var/lib/siem-hub/windows-json/
```

*Ergebnis:* Sie sollten neue Dateien wie `WinEvents_1430.json` sehen, die massenhaft Einträge mit der ID 4625 enthalten.

## Schritt 3: KI-Verarbeitungs-Log prüfen

Wir kontrollieren den Status des in Modul 8.5 erstellten Daemons, um zu sehen, wie die KI reagiert.

**KI-Daemon Log-Analyse**

```bash
journalctl -u ki-siem.service -f
```

**Erwartete Ausgabe:**

- `[*] Neue Log-Datei erkannt...`
- `[*] Sende Daten an Ollama (Llama3)...`
- `[!] Bedrohung erkannt: BRUTE FORCE ATTACK von IP 10.0.30.20`
- `[+] Alert an Teams/M365 versendet.`

## Schritt 4: Verifizierung der Alarmierung

Prüfen Sie nun Ihre Benachrichtigungskanäle:

**a.) Microsoft Teams:** Öffnen Sie den Lab-Kanal. Dort muss eine Nachricht vom *Ollama SIEM Bot* mit der Zusammenfassung des Angriffs stehen.

**b.) E-Mail:** Prüfen Sie das Postfach von `mika.varga@example.com` auf den Security-Alert von `schulung@example.com`.
