# 8.6 Alarmierung & Benachrichtigung (Incident Response)

## Konzept: Von der Erkennung zur Reaktion

Bisher hat unser KI-Daemon (`ki_siem_daemon.py`) Berichte lokal gespeichert. Im Ernstfall zählt jedoch jede Sekunde. Wir implementieren nun eine **Alerting-Engine**, die das Analyseergebnis von Ollama scannt. Enthält die Antwort Schlüsselwörter wie „Malicious“, „Brute Force“ oder „Critical“, löst das System automatisch zwei Aktionen aus:

1. **Teams-Alert:** Eine Sofortnachricht in den Channel Ihres Lab-Projekts.
2. **E-Mail-Alert:** Eine formale Benachrichtigung über Ihren M365-Account `schulung@example.com`.

## Schritt 1: Microsoft Teams Webhook vorbereiten

Wir nutzen einen „Incoming Webhook“, um Nachrichten von Kali direkt in einen Teams-Kanal zu pushen.

**1.1** Öffnen Sie Microsoft Teams und navigieren Sie zu Ihrem Team **Lab-Projekt-Alpha**.

**1.2** Klicken Sie auf die drei Punkte (…) neben dem Kanal *Allgemein* → **Connectors**.

**1.3** Suchen Sie nach **Incoming Webhook** und fügen Sie ihn hinzu.

**1.4** Vergeben Sie einen Namen (z. B. *Ollama SIEM Bot*) und kopieren Sie die erzeugte **Webhook-URL**.

## Schritt 2: Erweiterung des Python-Daemons

Wir fügen dem Skript aus Modul 8.5 eine Alarm-Funktion hinzu. Hier ist die Logik für den automatisierten Versand:

**Python-Funktion für Teams & E-Mail Alerts**

```python
import smtplib
from email.message import EmailMessage

TEAMS_WEBHOOK_URL = "https://contoso.webhook.office.com/..." # Ihre URL

def send_alerts(analysis_text, log_file):
    # Nur alarmieren, wenn die KI eine Gefahr erkennt
    keywords = ["CRITICAL", "MALICIOUS", "WARNING", "BRUTE FORCE"]
    if not any(word in analysis_text.upper() for word in keywords):
        return
    # 1. Teams Nachricht senden
    alert_payload = {
        "text": f"*** AI-SEC ALERT ***\nAnomalie in {log_file} erkannt!\n\nAnalyse:\n{analysis_text}"
    }
    requests.post(TEAMS_WEBHOOK_URL, json=alert_payload)

    # 2. E-Mail via M365 senden
    msg = EmailMessage()
    msg.set_content(f"Die lokale KI hat eine Bedrohung erkannt.\nDatei: {log_file}\n\n{analysis_text}")
    msg['Subject'] = f"SECURITY ALERT: {log_file}"
    msg['From'] = "schulung@example.com"
    msg['To'] = "mika.varga@example.com"

    try:
        with smtplib.SMTP("smtp.office365.com", 587) as server:
            server.starttls()
            server.login("schulung@example.com", "IHR_PASSWORT")
            server.send_message(msg)
    except Exception as e:
        print(f"Mail-Error: {e}")
```

## Schritt 3: Integration in den Workflow

Rufen Sie die Funktion `send_alerts` am Ende des `process_log`-Abschnitts in Ihrem Daemon auf (siehe Modul 8.5). Damit wird jede abgeschlossene Analyse sofort auf Alarm-Kriterien geprüft.

## Schritt 4: Der „Red Team“ Testlauf

Um die Kette zu verifizieren, simulieren wir einen Angriff.

**4.1** Erstellen Sie manuell eine Datei `attack.json` im Dropzone-Ordner auf Kali.

**4.2** Inhalt: `{"ID": 4625, "Msg": "Failed login for Administrator from 192.168.1.100", "Count":` `50}`

**4.3 Beobachtung:**

- Der Daemon erkennt die Datei.
- Ollama analysiert und stuft es als „Brute Force“ ein.
- Sekunden später poppt in Ihrem Teams-Client am PC oder Handy eine Benachrichtigung auf.
