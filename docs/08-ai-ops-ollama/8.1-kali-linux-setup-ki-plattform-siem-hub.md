# 8.1 Kali Linux Setup (KI-Plattform & SIEM-Hub)

## Konzept: Die Rolle von CL-KALI-01

In dieser Phase transformieren wir den Kali-Client von einem reinen Pentesting-Tool zum zentralen **Security-Hub** Ihrer Infrastruktur. Auf diesem System läuft die lokale KI (**Ollama**), welche die in Phase 7 aggregierten Log-Daten analysiert.

Aufgrund der hohen Anforderungen von Large Language Models (LLMs) erfolgt die Installation auf dem performanten **Host 2** in der Filiale mit maximaler Ressourcen-Zuweisung.

## Schritt 1: Hyper-V VM Konfiguration (Host 2)

Erstellen Sie die VM auf Host 2 strikt nach diesen Spezifikationen, um Engpässe bei der KI-Analyse zu vermeiden.

| **Einstellung** | **Wert / Vorgabe** |
| --- | --- |
| **Name** | `CL-KALI-01` |
| **Generation** | Generation 2 (UEFI) |
| **Arbeitsspeicher** | **24.576 MB (24 GB) - Statisch** (Haken bei Dynamisch entfernen) |
| **Prozessoren** | Mindestens 4 virtuelle Kerne (vCPUs) |
| **Netzwerk** | Verbunden mit `vSwitch-LAN` (Filiale) |
| **Festplatte** | 100 GB VHDX auf der internen SSD des Hosts |

> [!WARNING]
> **Kritisch: UEFI & Secure Boot Anpassung**\
> Nach der Erstellung der VM (vor dem ersten Start):
>
> 1. Rechtsklick auf `CL-KALI-01` → **Einstellungen**.
> 2. Unter **Sicherheit**: Ändern Sie die Vorlage für den sicheren Start von *Microsoft Windows* auf ***Microsoft UEFI Certificate Authority***.
> 3. Ohne diese Änderung verweigert der Kali-Bootloader (GRUB) den Start.

## Schritt 2: Installation von Kali Linux

Binden Sie das aktuelle Kali Rolling ISO ein und starten Sie die Installation.

**2.1 Installations-Typ:** Wählen Sie *Graphical Install*.

**2.2 Netzwerk:**

- **Hostname:** `cl-kali-01`
- **Domain:** `ad.example.com`

**2.3 Benutzer:** Erstellen Sie einen administrativen Benutzer (z. B. `kali-admin`).

**2.4 Software-Auswahl:**

- Desktop-Umgebung: XFCE (Ressourcenschonend) oder GNOME.
- Tools: Wählen Sie *Default* und zusätzlich *Large* (um wichtige Python-Bibliotheken für die KI-Analyse direkt an Bord zu haben).

## Schritt 3: Post-Installation & OS-Tuning

Nach dem ersten Login müssen wir das System für die KI-Last optimieren.

**System-Update und Optimierung**

```bash
# 1. System auf den neuesten Stand bringen
sudo apt update && sudo apt full-upgrade -y

# 2. Hyper-V Integration Services pruefen (fuer Grafik und Performance)
sudo apt install hyperv-daemons -y

# 3. Swap-Space kontrollieren
# Da wir 24GB RAM haben, sollte die Swap-Datei minimal sein,
# um unnötige SSD-Schreibzugriffe zu vermeiden.
sudo swapon --show
```

## Schritt 4: Verifizierung der Ressourcen

Stellen Sie sicher, dass Kali den zugewiesenen RAM auch korrekt erkennt.

**Ressourcen-Check**

```bash
free -m
```

*Ergebnis:* Unter „Total“ sollten ca. 24.000 MB angezeigt werden. Dies ist die notwendige Kapazität, um Modelle wie LLaMA3-8B vollständig in den Arbeitsspeicher zu laden.

> [!NOTE]
> **Portfolio-Check: Architektur der kurzen Wege**\
> Dokumentieren Sie, warum Kali in der Filiale (Host 2) steht: Durch die Platzierung auf Host 2 zusammen mit dem `SRV-DC-02` minimieren wir den Replikations-Traffic über den VPN-Tunnel während der Analyse-Phase. Zudem nutzt Kali die freien Ressourcen des zweiten Hosts optimal aus, während Host 1 durch den Webserver und den Primär-DC bereits stärker ausgelastet ist.
