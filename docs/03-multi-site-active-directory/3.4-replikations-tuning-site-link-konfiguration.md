# 3.4 Replikations-Tuning & Site-Link Konfiguration

## Zweck des Replikations-Tunings

Die Replikation zwischen dem Hauptquartier (`HQ`) und der `Filiale` erfolgt über den in Phase 2 etablierten VPN-Tunnel. Um eine optimale Balance zwischen Datensynchronität und Netzwerkauslastung zu finden, müssen die Parameter des *Inter-Site Transports* feinjustiert werden. Ohne dieses Tuning nutzt Windows konservative Standardwerte (180 Min. Intervall), was zu veralteten Benutzerdaten an entfernten Standorten führen kann.

## Schritt 1: Konfiguration des IP-Site-Links

Der Site-Link ist die logische Verbindung zwischen den Standorten im Active Directory.

**1.1** Öffnen Sie auf `SRV-DC-01` das Tool **Active Directory-Standorte und -Dienste**.

**1.2** Navigieren Sie zu **Sites** → **Inter-Site Transports** → **IP**.

**1.3** Klicken Sie mit der rechten Maustaste auf **DEFAULTIPSITELINK** (oder Ihren spezifischen Link) → **Eigenschaften**.

**1.4 Kosten (Cost) festlegen:** Setzen Sie den Wert für *Kosten* auf **100**.

- *Hintergrund:* In komplexeren Netzen mit mehreren Tunneln bestimmt dieser Wert den bevorzugten Pfad (niedrigere Kosten = höhere Priorität).

**1.5 Replikationsintervall:** Ändern Sie den Wert von 180 auf **15 Minuten**.

- Da Ihr WireGuard-Tunnel performant ist, gewährleistet dies eine fast zeitnahe Synchronisation von Passwortänderungen oder neuen Objekten.

## Schritt 2: Replikationszeitplan (Schedule)

Hier legen wir fest, zu welchen Uhrzeiten die Replikation stattfinden darf.

**2.1** Klicken Sie im selben Eigenschaftsfenster auf die Schaltfläche **Zeitplan ändern...** (Change Schedule).

**2.2** Standardmäßig ist „Replikation verfügbar“ (blau markiert) für 24/7 aktiv.

**2.3** *Best Practice:* Lassen Sie die Replikation für dieses Lab-Projekt auf **24/7**, um bei Tests nicht auf Zeitfenster warten zu müssen. In realen Umgebungen mit sehr schwachen Leitungen würde man hier die Geschäftszeiten aussparen oder einschränken.

## Schritt 3: Erzwungene Replikationsprüfung (CLI)

Um sicherzustellen, dass die Replikation nicht nur theoretisch konfiguriert ist, sondern auch praktisch funktioniert, nutzen wir das Tool `repadmin`.

**PowerShell Replikations-Diagnose**

```bash
# Status aller Replikationspartner anzeigen
repadmin /showrepl

# Replikation vom HQ zur Filiale sofort anstoßen
repadmin /syncall /A /e /d
```

## Schritt 4: Monitoring der Replikations-Latenz

Erstellen Sie ein Test-Objekt (z. B. eine Test-OU oder einen Benutzer) im HQ und prüfen Sie, wie lange es dauert, bis dieses Objekt auf dem `SRV-DC-02` in der Filiale erscheint.

**4.1 HQ:** Erstellen Sie die OU `OU_ReplTest` in *Active Directory-Benutzer und -Computer*.

**4.2 Filiale:** Öffnen Sie dort die Konsole und nutzen Sie:

```powershell
        Get-ADOrganizationalUnit -Filter "Name -eq 'OU_ReplTest'"
```

**4.3** Wenn das Objekt sofort erscheint, greift die *Change Notification* (sofern aktiviert), ansonsten erfolgt das Update nach spätestens 15 Minuten.

> [!NOTE]
> **Experten-Tipp: Change Notification aktivieren**\
> Normalerweise warten Site-Links stur auf das Intervall (15 Min.). Sie können den Site-Link aber so konfigurieren, dass er wie eine LAN-Replikation reagiert (sofortige Benachrichtigung bei Änderungen).
>
> **Vorgehen:** ADSI-Editor → Configuration Partition → Sites → Inter-Site Transports → IP → Eigenschaften des Links → Attribut `options` auf **1** setzen. Dies ist die absolute Königsdisziplin im Multi-Site AD Tuning.
