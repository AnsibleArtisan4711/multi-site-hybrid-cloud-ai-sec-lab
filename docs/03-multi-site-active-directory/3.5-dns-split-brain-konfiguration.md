# 3.5 DNS Split-Brain Konfiguration

## Konzept: Split-Brain DNS

Normalerweise ist das Active Directory für die Zone `ad.example.com` zuständig. Wenn ein interner Client jedoch die Adresse `example.com` aufruft, würde er ohne Split-Brain DNS den DNS-Server im Internet fragen und die öffentliche WAN-IP Ihrer OPNsense erhalten.

Durch die Erstellung einer lokalen Kopie der Zone `example.com` auf den Domain Controllern können wir interne Anfragen gezielt steuern. Dies ist essenziell, wenn Dienste wie der Webserver sowohl intern (DMZ) als auch extern (IONOS) verteilt sind.

## Schritt 1: Erstellen der Forward-Lookupzone

Führen Sie diese Schritte auf dem PDC (`SRV-DC-01`) aus.

**1.1** Öffnen Sie den **DNS-Manager** (`dnsmgmt.msc`).

**1.2** Rechtsklick auf **Forward-Lookupzonen** → **Neue Zone...**

**1.3 Zonentyp:** Primäre Zone (Haken bei *„Zone im Active Directory speichern“* setzen).

**1.4 Zonenname:** Geben Sie **`example.com`** ein.

**1.5** Schließen Sie den Assistenten ab.

## Schritt 2: Manuelle Records für Interne Ressourcen (DMZ & NAS)

Hier definieren wir die Ziele, die sich innerhalb Ihres Labors befinden.

| **Hostname** | **Typ** | **Ziel / IP** | **Zweck** |
| --- | --- | --- | --- |
| `www` | A | `10.0.20.80` | Aufruf des Apache-Webservers in der DMZ. |
| `nas` | A | `10.0.10.250` | Zugriff auf UGreen NAS im LAN. |
| `cloud` | CNAME | `nas.example.com` | Alias für den NAS-Zugriff. |

## Schritt 3: Manuelle Records für Externe Ressourcen (IONOS Hosting)

Falls Sie bestimmte Subdomains oder Dienste bei IONOS hosten, müssen diese im internen DNS manuell auf die **öffentliche IONOS-IP** zeigen.

| **Hostname** | **Typ** | **Ziel / IP** | **Bedeutung** |
| --- | --- | --- | --- |
| `shop` | A | *[IONOS-IP]* | Ihr Webshop, der bei IONOS gehostet wird. |
| `dev` | A | *[IONOS-IP]* | Staging-Umgebung bei IONOS. |
| `ftp` | A | *[IONOS-IP]* | FTP-Zugang für Web-Updates bei IONOS. |

| **Praxis-Tipp: IONOS Hosting IP schnell finden** Um die korrekte Ziel-IP für die obige Tabelle zu ermitteln, gibt es zwei Wege: |
| --- |
| a) **IONOS Cloud Panel:** Loggen Sie sich unter `my.ionos.at` ein. Navigieren Sie zu *Hosting* → *Verwalten* → *SFTP/SSH*. Dort wird unter „Host“ oft direkt die IP-Adresse oder ein Servername (den man pingen kann) angezeigt. |
| b) **Über die Konsole (Schnellster Weg):** Wenn die Domain extern bereits live ist, öffnen Sie eine CMD an Ihrem PC und tippen Sie: `ping example.com`. Die angezeigte IP in den Klammern ist die Adresse Ihres IONOS-Webspaces. |

## Schritt 4: Spiegelung der Cloud-Dienste (Microsoft 365)

Damit Outlook und Entra ID intern funktionieren, müssen diese CNAMEs vorhanden sein:

| **Hostname** | **Typ** | **Ziel (Alias)** | **Bedeutung** |
| --- | --- | --- | --- |
| `autodiscover` | CNAME | `autodiscover.outlook.com` | Outlook-Konfiguration |
| `enterpriseregistration` | CNAME | `enterpriseregistration.windows.net` | Entra ID Join |

> [!IMPORTANT]
> **Spezialfall: MX-Records & IONOS Mail**\
> Wenn Sie E-Mails über IONOS empfangen (und nicht über M365), müssen Sie in dieser internen Zone unbedingt den **MX-Record** von IONOS anlegen (z. B. `mx00.kundenserver.de`). Ohne diesen Eintrag können interne Server (wie Ihr Webserver in der DMZ) keine E-Mails an `@example.com` versenden, da sie den Mailserver nicht finden würden.
