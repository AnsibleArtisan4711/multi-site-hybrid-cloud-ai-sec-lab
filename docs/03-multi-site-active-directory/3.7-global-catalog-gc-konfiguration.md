# 3.7 Global Catalog (GC) Konfiguration

## Konzept: Warum Global Catalog an jedem Standort?

Der Globale Katalog (GC) ist ein Domain Controller, der nicht nur die Objekte seiner eigenen Domäne verwaltet, sondern auch einen durchsuchbaren Teilkatalog aller Objekte der gesamten Gesamtstruktur (Forest) bereithält.

In Ihrem Multi-Site-Szenario (`ad.example.com`) ist die Aktivierung des GC auf **beiden** DCs (`SRV-DC-01` und `SRV-DC-02`) aus folgenden Gründen zwingend:

- **Anmelde-Performance:** Der GC wird benötigt, um die Mitgliedschaft in universellen Gruppen während des Logins zu prüfen. Ohne lokalen GC müsste die Filiale diese Info über den VPN-Tunnel vom HQ abfragen.
- **Ausfallsicherheit (Survivability):** Sollte der VPN-Tunnel ausfallen, können sich Benutzer in der Filiale weiterhin problemlos anmelden, da der lokale `SRV-DC-02` alle notwendigen Informationen im eigenen Globalen Katalog hält.

## Schritt 1: Aktivierung via GUI

Obwohl der GC bei der Heraufstufung (Modul 3.1 und 3.2) meist standardmäßig aktiviert wurde, muss dies in einer Multi-Site-Umgebung verifiziert und ggf. manuell korrigiert werden.

**1.1** Öffnen Sie auf einem beliebigen DC das Tool **Active Directory-Standorte und -Dienste**.

**1.2** Navigieren Sie zu **Sites** → **[Standort-Name]** → **Servers** → **[DC-Name]** → **NTDS Settings**.

**1.3** Klicken Sie mit der rechten Maustaste auf **NTDS Settings** → **Eigenschaften**.

**1.4** Stellen Sie sicher, dass der Haken bei **Globaler Katalog** gesetzt ist.

**1.5** Wiederholen Sie diesen Vorgang für beide Standorte (HQ und Filiale).

## Schritt 2: Verifizierung per PowerShell

Um sicherzugehen, dass das Active Directory den Server auch wirklich als GC-Server erkennt, nutzen wir die PowerShell.

**GC-Status abfragen**

```powershell
# Liste aller Global Catalog Server im Forest anzeigen
Get-ADForest | Select-Object -ExpandProperty GlobalCatalogs
```

*Soll-Ergebnis:* In der Liste müssen sowohl `SRV-DC-01` als auch `SRV-DC-02` mit ihrem vollqualifizierten Domänennamen (FQDN) erscheinen.

## Schritt 3: Prüfung des DNS-Eintrags

Der GC registriert sich mit einem speziellen SRV-Record im DNS, damit Clients ihn finden können.

**3.1** Öffnen Sie den **DNS-Manager**.

**3.2** Navigieren Sie zu **Forward-Lookupzonen** → **\_msdcs.ad.example.com** → **gc**.

**3.3** Dort müssen für beide DCs entsprechende Einträge unter dem Hostnamen vorhanden sein.

> [!TIP]
> **Spezialfall: Infrastructure Master vs. GC**\
> Ein klassischer Merksatz in der IT lautet: *„Der Infrastructure Master darf kein GC sein.“*\
> **Entwarnung für Ihr Projekt:** Diese Regel gilt **nur**, wenn Sie mehrere Domänen in einem Forest haben UND nicht alle DCs Global Catalogs sind. In Ihrer Single-Domain-Umgebung, in der wir alle DCs zu GCs machen, ist dieser Konflikt technisch ausgeschlossen. Sie können also beide Rollen gefahrlos auf demselben Server betreiben.
