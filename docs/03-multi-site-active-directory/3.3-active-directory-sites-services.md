# 3.3 Active Directory Sites & Services

## Zweck der Standort-Konfiguration

In einer Multi-Site-Umgebung wie der Domäne `ad.example.com` ist es entscheidend, dass das Active Directory die Netzwerktopologie kennt. Ohne diese Konfiguration betrachten Clients alle Domain Controller als „gleich weit entfernt“.

- **Anmelde-Optimierung:** Clients melden sich bevorzugt an DCs im eigenen Subnetz an.
- **Replikations-Steuerung:** Die Synchronisation der Datenbank zwischen HQ und Filiale erfolgt komprimiert und nach einem Zeitplan, um den VPN-Tunnel nicht zu überlasten.

## Schritt 1: Standorte (Sites) definieren

Standardmäßig liegen alle Server im *Default-First-Site-Name*. Diesen lösen wir nun auf.

**1.1** Öffnen Sie auf dem PDC (`SRV-DC-01`) das Tool **Active Directory-Standorte und -Dienste**.

**1.2 HQ anpassen:** Klicken Sie mit der rechten Maustaste auf *Default-First-Site-Name* unter dem Ordner *Sites* und wählen Sie **Umbenennen**. Nennen Sie den Standort **`HQ`**.

**1.3 Filiale erstellen:** Rechtsklick auf den Überordner *Sites* → **Neuer Standort**.

- **Name:** `Filiale`
- **Link-Name:** Wählen Sie `DEFAULTIPSITELINK` aus.

## Schritt 2: Subnetze zuweisen (IP-Mapping)

Dies ist der wichtigste Schritt: Hier verknüpfen wir die physischen IP-Bereiche mit den logischen Standorten.

**2.1** Navigieren Sie zum Ordner **Subnets**. Rechtsklick → **Neues Subnetz**.

**2.2 Subnetz HQ:**

- **Präfix:** `10.0.10.0/24`
- **Standort:** Wählen Sie `HQ`.

**2.3 Subnetz Filiale:**

- **Präfix:** `10.0.30.0/24`
- **Standort:** Wählen Sie `Filiale`.

## Schritt 3: Server an die Standorte verschieben

Stellen Sie sicher, dass die DC-Objekte in den richtigen Containern liegen.

**3.1** `SRV-DC-01` sollte bereits unter *HQ* → *Servers* gelistet sein.

**3.2** Suchen Sie `SRV-DC-02` (falls er noch unter HQ oder Default liegt).

**3.3** Klicken Sie mit der rechten Maustaste auf `SRV-DC-02` → **Verschieben** und wählen Sie den Standort **Filiale** aus.

## Schritt 4: Replikations-Intervall anpassen

Da der VPN-Tunnel stabil ist, können wir die Standard-Replikationszeit (180 Min.) verkürzen.

**4.1** Navigieren Sie zu *Inter-Site Transports* → *IP*.

**4.2** Rechtsklick auf **DEFAULTIPSITELINK** → **Eigenschaften**.

**4.3** Ändern Sie das Intervall *„Replizieren alle...“* auf **15 Minuten**.

> [!TIP]
> **Verifizierung der Topologie (KCC):**\
> Der *Knowledge Consistency Checker* (KCC) erstellt automatisch die Verbindungen. Sie können dies erzwingen und prüfen:
>
> **a.)** Öffnen Sie *HQ* → *Servers* → *SRV-DC-01* → *NTDS Settings*.
>
> **b.)** Klicken Sie rechts auf das automatisch generierte Objekt → **Replikation jetzt synchronisieren**.
>
> **c.)** Nutzen Sie in der PowerShell den Befehl `repadmin /istg * /verbose`, um zu sehen, welcher DC die Rolle des *Inter-Site Topology Generator* (ISTG) für den jeweiligen Standort übernommen hat.
