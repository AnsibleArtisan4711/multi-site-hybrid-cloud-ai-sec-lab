# 3.6 FSMO-Rollen & Verifizierung

## Hintergrund: Was sind FSMO-Rollen?

Das Active Directory arbeitet nach dem *Multi-Master*-Prinzip (alle DCs sind gleichberechtigt). Es gibt jedoch fünf spezifische Aufgaben, die zu einem Zeitpunkt nur von **einem** einzigen DC im gesamten Forest bzw. in der Domain übernommen werden dürfen, um Konflikte zu vermeiden. Diese werden als FSMO-Rollen bezeichnet.

## Die 5 Rollen im Überblick

| **Rolle** | **Ebene** | **Funktion** |
| --- | --- | --- |
| **Schema Master** | Forest | Erlaubt Änderungen am AD-Schema (z. B. für Exchange oder SCCM). |
| **Domain Naming Master** | Forest | Verwaltet das Hinzufügen oder Entfernen von Domänen im Forest. |
| **PDC Emulator** | Domain | Zeitquelle, Passwortänderungen, Bearbeitung von GPOs. |
| **RID Master** | Domain | Vergibt Eindeutige IDs (Relative IDs) für neue Objekte an alle DCs. |
| **Infrastructure Master** | Domain | Abgleich von Objekt-Referenzen über Domänengrenzen hinweg. |

## Schritt 1: Verifizierung per Kommandozeile (Empfohlen)

Der schnellste und zuverlässigste Weg, den Inhaber aller Rollen zu identifizieren, führt über die Konsole.

**1.1** Öffnen Sie die PowerShell oder CMD auf dem **`SRV-DC-01`**.

**1.2** Geben Sie folgenden Befehl ein:

```bash
        netdom query fsmo
```

**1.3 Soll-Ergebnis:** In allen fünf Zeilen muss der Hostname **`SRV-DC-01.ad.example.com`** erscheinen.

## Schritt 2: Verifizierung via GUI (Grafisch)

Um die Rollen in den Verwaltungswerkzeugen zu sehen, müssen Sie drei verschiedene Konsolen nutzen:

- **RID, PDC, Infrastructure:** *AD Benutzer und Computer* → Rechtsklick auf Domäne → **Betriebsmaster...**
- **Domain Naming Master:** *AD Domänen und Vertrauensstellungen* → Rechtsklick auf den obersten Knoten → **Betriebsmaster...**
- **Schema Master:** Hierfür muss erst die DLL registriert werden (`regsvr32 schmmgmt.dll`). Danach kann das *AD-Schema* Snap-In in einer leeren MMC hinzugefügt werden.

> [!NOTE]
> **Architektur-Check: Warum liegen alle Rollen im HQ?**\
> Im aktuellen Ausbauzustand Ihres Projekts ist es absolut korrekt, dass der PDC (`SRV-DC-01`) alle Rollen hält.\
> **Best Practice:** Bei nur zwei DCs im Forest sollten die Rollen nicht getrennt werden. Erst bei sehr großen Umgebungen mit hunderten DCs macht eine Trennung (z. B. PDC und RID Master auf verschiedene Server) Sinn. In Ihrem Szenario bleibt das HQ der „Master-Standort“.

> [!WARNING]
> **Achtung beim Ausfall von DC1:**\
> Sollte `SRV-DC-01` dauerhaft ausfallen, kann `SRV-DC-02` in der Filiale die Rollen nicht automatisch übernehmen. Sie müssten diese dann mit dem Befehl `ntdsutil` manuell „beschlagnahmen“ (*Seize*), um die volle Handlungsfähigkeit der Domäne wiederherzustellen.
