# 4.4 Zertifikate (Let’s Encrypt) & SSL-Verschlüsselung

## Architektur-Exkurs: Warum Certbot trotz IONOS-Zertifikat?

Viele Domain-Provider wie IONOS bieten ein „Inklusiv-Zertifikat“ an. Es ist jedoch wichtig zu verstehen, wo dieses Zertifikat technisch „lebt“:

- **Das IONOS-Zertifikat** schützt Daten, die auf den IONOS-Webservern liegen.
- **Ihr Projekt** leitet den Traffic jedoch via Port-Forwarding (NAT) an Ihre OPNsense und schließlich an die VM `SRV-WEB-01` weiter.

Da Ihr lokaler Ubuntu-Server der physische Endpunkt der HTTPS-Verbindung ist, muss er selbst über ein gültiges Zertifikat verfügen, um den TLS-Handshake mit dem Browser des Besuchers durchzuführen. Certbot (Let’s Encrypt) ist hierfür die ideale Lösung, da es das Zertifikat direkt auf dem Zielsystem installiert und automatisch erneuert.

## Voraussetzungen

Bevor Certbot ein Zertifikat ausstellen kann, müssen folgende Punkte erfüllt sein:

- **Port 80/443:** In der OPNsense (Modul 2.7) muss das Port-Forwarding auf den Webserver aktiv sein.
- **Öffentliches DNS:** Der A-Record für `www.example.com` bei IONOS muss auf die WAN-IP Ihrer OPNsense zeigen.
- **Webserver-Dienst:** Apache muss laufen (Modul 4.2).

## Schritt 1: Installation von Certbot

Melden Sie sich per SSH am Webserver an und installieren Sie den Certbot-Client sowie das Apache-Plugin.

**Certbot Installation auf Ubuntu**

```bash
# Repository aktualisieren und Certbot installieren
sudo apt update
sudo apt install certbot python3-certbot-apache -y
```

## Schritt 2: Zertifikat anfordern & Konfigurieren

Der Certbot-Client automatisiert den Validierungsprozess und passt die Apache-Konfiguration selbstständig an.

**Zertifikatserstellung**

```bash
# Zertifikat anfordern
sudo certbot --apache -d example.com -d www.example.com
```

*Wichtige Abfragen während des Assistenten:*

- **E-Mail:** Für Benachrichtigungen zum Ablaufdatum.
- **Redirect:** Wählen Sie die Option **2 (Redirect)**, um HTTP automatisch auf HTTPS umzuleiten.

## Schritt 3: Automatische Erneuerung prüfen

Zertifikate von Let’s Encrypt sind nur 90 Tage gültig. Der Ubuntu-Server prüft zweimal täglich automatisch, ob eine Erneuerung ansteht.

**Testlauf der Erneuerung**

```bash
sudo certbot renew --dry-run
```

## Schritt 4: Verifizierung (Der „Schloss“-Check)

Rufen Sie die Website von Ihrem physischen Host oder dem HQ-Client auf:

**a.)** Adresse: `https://www.example.com`

**b.) Soll-Ergebnis:** Ein geschlossenes Vorhängeschloss in der Adresszeile.

**c.) Zertifikatsdetails:** Unter „Zertifikat“ muss Let’s Encrypt als Aussteller gelistet sein.

> [!NOTE]
> **Besonderheit: Split-Brain DNS & Zertifikate**\
> Dank Ihres Split-Brain DNS (Modul 3.5) lösen interne Clients `www.example.com` auf die IP `10.0.20.80` (DMZ) auf. Da das Zertifikat auf den **Namen** ausgestellt ist, bleibt es auch intern gültig. Der Browser prüft nur die Namensübereinstimmung im Zertifikat – die IP-Adresse spielt für die SSL-Gültigkeit keine Rolle.
