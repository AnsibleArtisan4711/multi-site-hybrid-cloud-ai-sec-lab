# 4.6 Deployment-Prozess (Updates & Web-Content)

## Herausforderung: DMZ Isolation

Durch das Hardening in Modul 4.3 ist der Webserver (`SRV-WEB-01`) netzwerktechnisch isoliert. Er kann keine Dateien (z. B. via SMB/CIFS) vom internen NAS abrufen, da die DMZ nicht in das LAN kommunizieren darf. Daher benötigen wir sichere, unidirektionale Prozesse, um Betriebssystem-Updates und neuen Web-Content auf den Server zu bringen.

## \1. Betriebssystem-Updates (OS Patching)

Dank der Firewall-Regel *„DMZ to Any: Pass“* (Modul 4.3) hat der Webserver direkten Zugriff auf das Internet. OS-Updates erfordern daher keinen manuellen Eingriff aus dem LAN.

- **Manuell:** `sudo apt update && sudo apt upgrade -y`
- **Automatisiert (Empfohlen):** Wie bereits in Modul 4.3 eingerichtet, sorgt das Paket `unattended-upgrades` dafür, dass Sicherheits-Patches nachts automatisch installiert werden.

**2. Methode A: Content-Push via SFTP (LAN** → **DMZ)**

Die klassische Methode: Da das LAN in die DMZ kommunizieren darf (nicht umgekehrt), können Sie Daten aktiv vom Administrator-Client auf den Webserver schieben. Wir nutzen dafür **SFTP** (SSH File Transfer Protocol), da es verschlüsselt ist und keinen zusätzlichen FTP-Server (wie vsftpd) benötigt.

1. **Vorbereitung auf dem Webserver:**\
   Vergeben Sie dem Standard-Benutzer (z. B. `mvarga`) Schreibrechte für das Web-Verzeichnis, damit Sie Dateien hochladen können, ohne sich als root anmelden zu müssen.

```bash
         sudo chown -R mvarga:www-data /var/www/html
         sudo chmod -R 775 /var/www/html
```

1. **Verbindung vom Client (CL-WIN-01) herstellen:**\
   Laden Sie das Tool **WinSCP** herunter.

   - **Protokoll:** SFTP
   - **Hostname:** `10.0.20.80` (IP des Webservers)
   - **Port:** 22
2. Sie können nun Ihre lokal entwickelten HTML/PHP-Dateien einfach per Drag-and-Drop in das Verzeichnis `/var/www/html` kopieren.

## \3. Methode B: Content-Pull via Git (DevOps-Ansatz)

In modernen Infrastrukturen (und für ein starkes Portfolio) lädt man Dateien nicht manuell per SFTP hoch. Man nutzt ein Versionskontrollsystem wie **Git** (z. B. GitHub oder GitLab).

1. **Git auf dem Server installieren:**

```bash
         sudo apt install git -y
```

1. **Repository klonen:** Anstatt Dateien hochzuladen, weisen Sie den Webserver an, den Code direkt aus dem Internet zu laden (was durch die DMZ-Internet-Regel erlaubt ist).

```bash
         cd /var/www
         # Sichern Sie das alte Verzeichnis
         sudo mv html html_backup
         # Klonen Sie Ihr Web-Projekt (Beispiel)
         sudo git clone https://github.com/IhrName/MeinWebProjekt.git html
```

1. **Updates einspielen (Deployment):** Wenn Sie an Ihrem Desktop-PC Änderungen am Code vornehmen und zu GitHub pushen, loggen Sie sich einfach per SSH auf dem Webserver ein und rufen das Update ab:

```bash
         cd /var/www/html
         sudo git pull origin main
```

> [!NOTE]
> **Portfolio-Highlight: CI/CD Pipeline (Optional)**\
> Um diesen Prozess zu perfektionieren, können Sie erwähnen, dass Sie eine *Continuous Integration / Continuous Deployment (CI/CD)* Pipeline einsetzen. Ein GitHub-Action-Script loggt sich (mittels SSH-Key) bei einem Commit automatisch auf der OPNsense-WAN-IP (Port 22, forwarded zur DMZ) ein und führt den Befehl `git pull` selbstandig aus. Das ist modernes, automatisiertes Server-Management (DevOps).
