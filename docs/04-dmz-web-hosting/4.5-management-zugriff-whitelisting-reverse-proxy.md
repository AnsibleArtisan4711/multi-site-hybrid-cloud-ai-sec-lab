# 4.5 Management-Zugriff, Whitelisting & Reverse Proxy

## Konzept: Sichere Administrations-Zugänge

Um die Infrastruktur effizient zu verwalten, ohne die Sicherheit zu gefährden, kombinieren wir zwei strategische Ansätze in diesem kombinierten Modul:

1. **IP-Whitelisting:** Der direkte, eingeschränkte Zugriff vom physischen Host auf die OPNsense Firewall.
2. **Reverse Proxy:** Ein zentraler, verschlüsselter Zugriffspunkt in der DMZ für interne Dienste wie das NAS oder das Firewall-Dashboard.

Standardmäßig ist das Web-Interface (WebGUI) der OPNsense am WAN-Interface gesperrt. Um den Zugriff vom physischen Host (dem Rechner, auf dem Hyper-V läuft) zu ermöglichen, ohne die Firewall für das gesamte Internet zu öffnen, nutzen wir eine **Whitelisting-Regel**.

### IP-Adresse des physischen Hosts festlegen

Damit die Firewall-Regel dauerhaft funktioniert, darf sich die IP Ihres physischen Rechners im Heimnetz (z. B. FritzBox-Netz) nicht ändern.

**1. DHCP-Reservierung:** Gehen Sie in Ihren Heimrouter und stellen Sie sicher, dass Ihr PC immer die gleiche IP erhält (z. B. `192.168.1.50`).

**2. IP notieren:** Öffnen Sie auf Ihrem PC die CMD und tippen Sie `ipconfig`. Notieren Sie sich die IPv4-Adresse.

### Firewall-Regel auf der OPNsense (WAN)

Loggen Sie sich über eine interne VM (z. B. `CL-WIN-01`) in die OPNsense ein.

**1.** Navigieren Sie zu **Firewall** → **Rules** → **WAN**.

**2.** Klicke auf das Plus-Symbol (+), um eine neue Regel zu erstellen:

- **Action:** Pass
- **Interface:** WAN
- **Protocol:** TCP
- **Source:** `Single host or Network` → Tragen Sie hier die IP Ihres PCs ein (z. B. `192.168.1.50`).
- **Destination:** `WAN address`
- **Destination Port Range:** `HTTPS` (443)
- **Description:** Allow Management from Physical Host

**3. Ganz wichtig:** Schieben Sie diese Regel ganz nach **oben** in der Liste und klicken Sie auf **Apply Changes**.

### Das Admin-Handy (VPN statt Whitelisting)

Da sich die IP Ihres Handys im Mobilfunknetz bei jedem Funkzellenwechsel ändert, ist ein IP-Whitelisting hier unmöglich.

**1.** Installieren Sie die **WireGuard App** auf Ihrem Handy.

**2.** Erstellen Sie in der OPNsense unter **VPN** → **WireGuard** einen neuen Peer für Ihr Handy.

**3.** Scannen Sie den generierten QR-Code mit dem Handy ab.

**4.** Sobald der Tunnel aktiv ist, hat Ihr Handy eine Tunnel-IP (z. B. `10.254.254.3`).

**5. Sicherheitsvorteil:** Da Sie die Regel *„Pass any from WireGuard net“* erstellt haben, können Sie nun vom Handy aus einfach `https://10.0.10.1` aufrufen – egal wo Sie sich befinden.

> [!NOTE]
> **Portfolio-Tipp: Sicherheit durch Einschränkung**\
> Erwähnen Sie in Ihrer Dokumentation, dass Sie den Zugriff am WAN-Interface bewusst auf eine **einzelne Quell-IP** eingeschränkt haben. Ein Angreifer aus dem Internet müsste nun erst Ihre interne Heimnetz-IP fälschen (Spoofing), was über das Internet technisch nicht möglich ist.

**Reverse Proxy Konfiguration (Apache)**

Ein Reverse Proxy nimmt Anfragen aus dem Internet an und leitet diese an Server im Hintergrund (wie das NAS) weiter. Nur der Webserver benötigt dabei Zertifikate, interne IPs bleiben maskiert.

### Apache Module aktivieren

Damit Apache als Proxy fungieren kann, müssen die entsprechenden Module geladen werden.

```bash
# Notwendige Module aktivieren
sudo a2enmod proxy
sudo a2enmod proxy_http
sudo a2enmod proxy_balancer
sudo a2enmod lbmethod_byrequests

# Apache neu starten
sudo systemctl restart apache2
```

### VirtualHost für das NAS erstellen

Wir konfigurieren Apache so, dass Anfragen für `nas.example.com` an die interne IP des UGreen NAS (`192.168.x.x`) weitergeleitet werden.

**1.** Erstellen Sie eine neue Konfigurationsdatei:

`sudo nano /etc/apache2/sites-available/nas-proxy.conf`

**2.** Fügen Sie folgenden Inhalt ein:

```html
<VirtualHost *:80>
    ServerName nas.example.com

    ProxyPreserveHost On
    ProxyPass / http://192.168.x.x/
    ProxyPassReverse / http://192.168.x.x/

    ErrorLog ${APACHE_LOG_DIR}/nas_error.log
    CustomLog ${APACHE_LOG_DIR}/nas_access.log combined
</VirtualHost>
```

### Firewall-Anpassung (Kritisch!)

Da wir den Zugriff von der DMZ ins LAN blockiert haben, müssen wir eine **Ausnahme** in der OPNsense definieren.

- Gehen Sie zu **Firewall** → **Rules** → **DMZ**.
- Erstellen Sie eine Regel **OBERHALB** der Block-Regel:

  - **Action:** Pass \| **Protocol:** TCP
  - **Source:** `10.0.20.80` (Webserver)
  - **Destination:** `192.168.x.x` (NAS)
  - **Destination Port:** 80/443 (oder spezifischer NAS-Port)

### Aktivierung & Test

```bash
sudo a2ensite nas-proxy.conf
sudo systemctl reload apache2
```

**Deep Dive – Certbot Automatisierung**

Wenn Sie `sudo certbot --apache` ausführen, übernimmt Certbot die Validierung bei Let’s Encrypt, legt die Schlüssel in `/etc/letsencrypt/live/example.com/` ab und klont Ihre Apache-Konfiguration.

### Vor dem Certbot-Lauf (Ihre manuelle Datei)

```html
<VirtualHost *:80>
    ServerName nas.example.com
    ProxyPass / http://192.168.x.x/
    ProxyPassReverse / http://192.168.x.x/
</VirtualHost>
```

### Nach dem Certbot-Lauf (Die Automatisierung)

Certbot fügt in Ihre ursprüngliche Port-80-Datei eine **permanente Umleitung** ein:

```html
<VirtualHost *:80>
    ServerName nas.example.com
    # Certbot hat diese Zeilen eingefuegt:
    RewriteEngine on
    RewriteCond %{SERVER_NAME} =nas.example.com
    RewriteRule ^ https://%{SERVER_NAME}%{REQUEST_URI} [END,NE,R=permanent]
</VirtualHost>
```

Zusätzlich erstellt Certbot die Datei `nas-proxy-le-ssl.conf` für Port 443:

```html
<VirtualHost *:443>
    ServerName nas.example.com
    ProxyPass / http://192.168.x.x/
    ProxyPassReverse / http://192.168.x.x/

    SSLEngine on
    SSLCertificateFile /etc/letsencrypt/live/example.com/fullchain.pem
    SSLCertificateKeyFile /etc/letsencrypt/live/example.com/privkey.pem
</VirtualHost>
```

| --- |
| **1.** Erstellen Sie eine Datei `fw-proxy.conf` mit `ServerName fw.example.com`. |
| **2.** Setzen Sie die `ProxyPass`-Ziele auf `https://10.0.10.1/`. (Achtung: Firewall-Ausnahme für `10.0.10.1` in der DMZ nicht vergessen!) |
| **3.** Aktivieren Sie die Seite mit `sudo a2ensite fw-proxy.conf`. |
