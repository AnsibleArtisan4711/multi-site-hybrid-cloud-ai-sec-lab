# 4.1 Ubuntu Server Setup (DMZ)

## Rolle des Webservers in der DMZ

Der Server `SRV-WEB-01` ist das primäre Ziel für externes Webhosting (Apache) innerhalb Ihres Labors. Da er in der DMZ (`10.0.20.0/24`) platziert wird, fungiert er als Puffer: Selbst bei einer erfolgreichen Kompromittierung des Webservers verhindern die Firewall-Regeln (siehe Modul 2.5) einen Übergriff auf das interne LAN oder das Active Directory.

## Schritt 1: Hyper-V VM Vorbereitung

Stellen Sie sicher, dass die in Phase 1 angelegte VM korrekt konfiguriert ist.

**1.1 Generation:** Generation 2.

**1.2 Arbeitsspeicher:** 2048 MB (Dynamisch aktiviert, siehe Modul 1.7).

**1.3 Netzwerk:** Verbunden mit **`vSwitch-DMZ`**.

**1.4 Secure Boot:** In den VM-Einstellungen unter *Sicherheit* muss die Vorlage ***Microsoft UEFI Certificate Authority*** ausgewählt sein, damit Ubuntu booten kann.

**1.5 Medium:** Binden Sie das Ubuntu Server ISO (z. B. 22.04 oder 24.04 LTS) ein, das auf dem NAS unter `\\STO-NAS-01\ISOs` liegt.

## Schritt 2: Installation des Betriebssystems

Starten Sie die VM und folgen Sie dem Installer.

- **Sprache/Layout:** Deutsch / Deutsch.
- **Type of Install:** Ubuntu Server (Minimal reicht für einen reinen Webserver aus).
- **Netzwerk:** Überspringen Sie die automatische Konfiguration (DHCP) oder wählen Sie *Edit IPv4*, um die IP direkt statisch zu setzen (siehe Schritt 3).
- **Storage:** *Use an entire disk*. Deaktivieren Sie „Set up this disk as an LVM group“, um die Partitionierung für das Lab einfach zu halten, oder übernehmen Sie den Standard.
- **Profile Setup:**

  - Rechnername: `SRV-WEB-01`
  - Benutzer: Ihr Standard-Admin (z. B. `mvarga`)
- **SSH Setup:** Aktivieren Sie ***Install OpenSSH server***, um den Server später remote verwalten zu können.

## Schritt 3: Statische IP-Konfiguration (Netplan)

In der DMZ gibt es keinen DHCP-Server. Die Konfiguration erfolgt über YAML-Dateien in Netplan.

**Netplan Konfiguration (/etc/netplan/00-installer-config.yaml)**

```yaml
network:
  ethernets:
    eth0:  # Bezeichner kann abweichen, z.B. enp0s13
      addresses:
        - 10.0.20.80/24
      nameservers:
        addresses: [10.0.10.10, 8.8.8.8]
      routes:
        - to: default
          via: 10.0.20.1
  version: 2
```

Wenden Sie die Einstellungen mit `sudo netplan apply` an.

## Schritt 4: Konnektivitätstest & Hardening

Prüfen Sie die Verbindung und bringen Sie das System auf den neuesten Stand.

```bash
# 1. Test zum Gateway (OPNsense DMZ Interface)
ping 10.0.20.1

# 2. Test ins Internet (Sollte durch OPNsense erlaubt sein)
ping 8.8.8.8

# 3. System-Update
sudo apt update && sudo apt upgrade -y
```

> [!NOTE]
> **Architektur-Hinweis: DNS-Auflösung in der DMZ**\
> Obwohl der Webserver isoliert ist, nutzt er als primären DNS den Domain Controller im HQ (`10.0.10.10`). Dies ist notwendig, damit der Webserver interne Namen (wie das NAS für Backups) auflösen kann. Die OPNsense-Firewall muss so konfiguriert sein (Modul 2.5), dass sie DNS-Anfragen (Port 53) von der DMZ ins LAN zum DC zulässt.
