# 4.2 Apache Webserver & Test-Website

## Zweck des Moduls

Der Webserver `SRV-WEB-01` soll Dienste für das Internet (via Port-Forwarding) und das interne Netzwerk bereitstellen. In diesem Schritt installieren wir den Apache-HTTP-Server und erstellen eine initiale Landingpage, um die Erreichbarkeit der DMZ-Ressourcen zu validieren.

## Schritt 1: Installation von Apache2

Melden Sie sich per SSH (z. B. via PuTTY vom HQ-Client) an den Webserver (`10.0.20.80`) an.

**Apache Installation**

```bash
# Paketlisten aktualisieren
sudo apt update

# Apache2 Webserver installieren
sudo apt install apache2 -y

# Status des Dienstes prüfen (sollte "active (running)" sein)
sudo systemctl status apache2
```

## Schritt 2: Konfiguration der Host-Firewall (UFW)

Obwohl die OPNsense bereits den Netzwerkzugriff regelt, sollte jedes Linux-System zusätzlich eine eigene Firewall (*Uncomplicated Firewall*) aktiv haben (**Defense in Depth**).

**UFW Konfiguration**

```bash
# SSH erlauben (Wichtig, um sich nicht selbst auszusperren!)
sudo ufw allow OpenSSH

# HTTP (Port 80) und HTTPS (Port 443) erlauben
sudo ufw allow 'Apache Full'

# Firewall aktivieren
sudo ufw enable

# Status prüfen
sudo ufw status
```

## Schritt 3: Erstellen der Test-Website

Wir ersetzen die Standard-Apache-Seite durch eine projektbezogene HTML-Seite.

**3.1 Alte Index-Datei sichern:**

`sudo mv /var/www/html/index.html /var/www/html/index.html.bak`

**3.2 Neue Index-Datei erstellen:**

`sudo nano /var/www/html/index.html`

**HTML-Inhalt für index.html**

```html
<!DOCTYPE html>
<html lang="de">
<head>
    <meta charset="UTF-8">
    <title>Multi-Site Hybrid Cloud & AI-Sec Operations Project</title>
    <style>
        body { font-family: sans-serif; background-color: #f4f4f4; text-align: center; padding-top: 50px; }
        .container { background: white; padding: 30px; border-radius: 10px; display: inline-block; box-shadow: 0 0 10px rgba(0,0,0,0.1); }
        h1 { color: #2c3e50; }
        .status { color: green; font-weight: bold; }
    </style>
</head>
<body>
    <div class="container">
        <h1>Multi-Site Hybrid Cloud & AI-Sec Operations Project</h1>
        <p>Infrastruktur-Status: <span class="status">ONLINE</span></p>
        <p>Dies ist der Webserver <b>SRV-WEB-01</b> in der DMZ (VLAN 20).</p>
        <hr>
        <small>Routing & NAT-Forwarding erfolgreich getestet.</small>
    </div>
</body>
</html>
```

## Schritt 4: Verifizierung des Zugriffs

Testen Sie den Zugriff von verschiedenen Punkten aus:

- **Intern (HQ-Client):** Öffnen Sie im Browser `http://10.0.20.80`.
- **Intern via DNS (Modul 3.5):** Öffnen Sie `http://www.example.com`.
- **Extern (Physischer Host):** Öffnen Sie die WAN-IP Ihrer OPNsense (z. B. `http://192.168.1.50`). Dank des Port-Forwardings aus Modul 2.7 sollte die neue Testseite erscheinen.

> [!TIP]
> **Portfolio-Check:**\
> Die Anzeige der Test-Website über die öffentliche WAN-IP beweist, dass die gesamte Kette funktioniert: *Physikalisches Netzwerk* → *Hyper-V vSwitch* → *OPNsense NAT* → *DMZ-VLAN* →
>
> *Ubuntu Host-Firewall* → *Apache Service*. Dies ist ein exzellenter Meilenstein für Ihre Dokumentation.
