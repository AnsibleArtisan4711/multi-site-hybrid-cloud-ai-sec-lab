# 7.3 Linux Log Export (rsyslog zum Kali-Hub)

## Konzept: Telemetrie-Einbindung der Linux-Systeme

Neben den Windows-Events sind die Logs der Linux-Systeme (Webserver in der DMZ, Clients im LAN) essenziell für die Erkennung von Angriffsszenarien wie Brute-Force-Attacken oder Web-Exploits.

In unserer Architektur dient der **`CL-KALI-01`** **(10.0.30.20)** als zentraler SIEM-Hub. Wir konfigurieren den Dienst **rsyslog** auf den Ubuntu-Systemen so, dass er alle relevanten Ereignisse in Echtzeit über das Netzwerk an den Kali-Client sendet.

## Schritt 1: Konfiguration auf den Quellen (Ubuntu)

Führen Sie diese Schritte auf dem `SRV-WEB-01` (DMZ) und dem `CL-UBU-01` (HQ-LAN) aus.

**1.1 Dienst prüfen:** Stellen Sie sicher, dass rsyslog installiert ist:

```bash
    sudo apt update && sudo apt install rsyslog -y
```

**1.2 Export-Konfiguration erstellen:** Wir erstellen eine separate Datei, um die Hauptkonfiguration sauber zu halten.

```bash
    sudo nano /etc/rsyslog.d/60-siem-export.conf
```

**1.3 Ziel-Server definieren:** Fügen Sie die folgende Zeile ein, um alle Logs via UDP an den Kali-Hub zu senden:

```bash
    *.* @10.0.30.20:514
```

*Erklärung:* Das einzelne **`@`** steht für das UDP-Protokoll. Die IP **`10.0.30.20`** ist die Adresse Ihres Kali-SIEMs in der Filiale.

**1.4 Dienst neu starten:** Wenden Sie die Änderungen an:

```bash
    sudo systemctl restart rsyslog
```

## Schritt 2: Firewall-Voraussetzung (OPNsense)

Damit der Webserver aus der DMZ und der Client aus dem HQ-LAN den Kali-Hub in der Filiale erreichen können, müssen die Regeln aus **Modul 7.2** aktiv sein.

- **Regel-Check:** UDP Port 514 muss von `10.0.20.80` und `10.0.10.0/24` in Richtung `10.0.30.20` erlaubt sein.

## Schritt 3: Verifizierung – Der „Live-Beweis“

Wir testen die Kette durch das Erzeugen eines künstlichen Ereignisses.

### A. Auf dem Ubuntu-System (Absender)

Senden Sie eine Testnachricht mit dem Tool `logger`:

**Testnachricht generieren**

```bash
logger "TEST-MESSAGE: SIEM-Anbindung von SRV-WEB-01 erfolgreich"
```

### B. Auf dem Kali-Hub (Empfänger)

Prüfen Sie auf dem `CL-KALI-01`, ob die Nachricht im konfigurierten Log-Verzeichnis (siehe Modul 7.4) ankommt.

**Echtzeit-Monitoring auf Kali**

```bash
# Die letzten Zeilen des zentralen Netzwerk-Logs beobachten
tail -f /var/lib/siem-hub/syslog/network.log
```

*Ergebnis:* Sie sollten die Zeile mit dem Inhalt *„TEST-MESSAGE...“* und der Quell-IP des Ubuntu-Systems sehen.

> [!IMPORTANT]
> **Sicherheits-Hinweis: Apache Access-Logs**\
> Standardmäßig loggt rsyslog nur Systemereignisse. Um die Webzugriffe des Apachen (DMZ) für die KI sichtbar zu machen, müssen Sie den Apache anweisen, ebenfalls an rsyslog zu senden.
>
> **Konfiguration in /etc/apache2/apache2.conf:**\
> Ersetzen Sie die `CustomLog` Zeile durch:\
> `CustomLog "|/usr/bin/logger -t apache2 -p local6.info" combined`

> [!NOTE]
> **Portfolio-Check: Revisionssicherheit durch Kali-Hub**\
> Dokumentieren Sie, dass durch diesen zentralen Export die Logs vor Manipulation geschützt sind. Selbst wenn ein Angreifer Root-Rechte auf dem Webserver erlangt und dort `/var/log/auth.log` löscht, befinden sich die Beweise bereits sicher auf dem Kali-Client in der Filiale, auf den der Webserver keinen Zugriff hat.
