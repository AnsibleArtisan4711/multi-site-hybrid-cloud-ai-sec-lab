# 7.4 Zentraler Speicherort (Kali-SIEM & Share-Setup)

## Konzept: Kali Linux als aktiver Security-Hub

In unserem Architektur-Modell übernimmt der **`CL-KALI-01`** (`10.0.30.20`) die Rolle eines SIEM-Systems (Security Information and Event Management). Er dient als primärer Landeplatz für alle Log-Datenströme.

**Vorteile dieser Architektur:**

- **Performance:** Die Analyse der JSON-Daten durch Ollama findet direkt im RAM der Kali-VM statt (keine Netzwerk-Latenz beim Parsen).
- **Sicherheit durch Isolation:** Der Windows-DC „sieht“ das NAS-Backup-System nicht. Er interagiert nur mit dem Kali-Hub.
- **Daten-Hoheit:** Kali entscheidet nach der Analyse, welche Daten komprimiert zur NAS (Archiv) verschoben werden.

## Schritt 1: Lokale SIEM-Struktur anlegen

Wir erstellen auf Kali ein dediziertes Verzeichnis für die unterschiedlichen Datenquellen.

**SIEM-Verzeichnisstruktur erstellen**

```bash
# Hauptverzeichnis fuer alle SIEM-Daten
sudo mkdir -p /var/lib/siem-hub/{syslog,windows-json,analysis}

# Rechte fuer den aktuellen Benutzer setzen
sudo chown -R $USER:$USER /var/lib/siem-hub
sudo chmod -R 755 /var/lib/siem-hub
```

## Schritt 2: Samba-Share (Dropzone) für Windows-Logs

Damit der Windows-DC seine JSON-Files per Netzwerk kopieren kann, konfigurieren wir eine Samba-Freigabe.

**2.1 Samba installieren:**

```bash
    sudo apt update && sudo apt install samba -y
```

**2.2 Share konfigurieren:** Editieren Sie `/etc/samba/smb.conf` und fügen Sie am Ende Folgendes hinzu:

```bash
   [LogDropzone]
       comment = SIEM Ingestion Point
       path = /var/lib/siem-hub/windows-json
       read only = no
       browsable = yes
       valid users = siem-upload
```

**2.3 Upload-Benutzer erstellen:** Erstellen Sie einen lokalen User (ohne Shell-Zugriff) und vergeben Sie das Samba-Passwort für die Windows-Authentifizierung:

```bash
    sudo useradd -M -s /sbin/nologin siem-upload
    sudo smbpasswd -a siem-upload
    sudo systemctl restart smbd
```

## Schritt 3: rsyslog-Empfang aktivieren

Kali soll auch die Syslog-Pakete der OPNsense-Firewalls entgegennehmen.

**3.1** Öffnen Sie `/etc/rsyslog.conf` und aktivieren Sie den UDP-Modul-Lader:

```bash
    module(load="imudp")
    input(type="imudp" port="514")
```

**3.2** Definieren Sie die Ziel-Datei für Netzwerk-Logs am Ende der Datei:

```bash
    *.* /var/lib/siem-hub/syslog/network.log
```

**3.3** `sudo systemctl restart rsyslog`

## Schritt 4: Host-Firewall (ufw) auf Kali

Schalten Sie die notwendigen Ports auf Kali frei.

**Firewall-Ports auf dem SIEM-Hub**

```bash
sudo ufw allow 514/udp       # Syslog (Firewalls)
sudo ufw allow 445/tcp       # Samba (Windows JSON Push)
sudo ufw enable
```

> [!NOTE]
> **Portfolio-Check: Das SIEM-Gateway Prinzip**\
> Dokumentieren Sie, dass Kali hier als **Security Gateway** fungiert. Anstatt die NAS (welche Ihre Backups hält) direkt dem Traffic aus dem LAN oder der DMZ auszusetzen, dient Kali als Filter. Erst wenn die Logs analysiert und für „sauber“ oder „archivierungswürdig“ befunden wurden, werden sie über einen separaten Prozess (Modul 7.5) verschlüsselt an die NAS übergeben. Dies schützt das Backup-Konzept vor Ransomware-Angriffen, die versuchen könnten, Logs auf dem Zielsystem zu löschen.
