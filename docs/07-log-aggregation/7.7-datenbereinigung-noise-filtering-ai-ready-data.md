# 7.7 Datenbereinigung (Noise-Filtering & AI-Ready Data)

## Konzept: Signal-to-Noise Ratio (SNR)

In einem Netzwerk fallen pro Sekunde hunderte Logs an. Davon sind ca. 95 % „Hintergrundrauschen“ (System-Heartbeats, reguläre Dateizugriffe, bekannte Dienst-Starts). Wenn die KI in Phase 8 das gesamte Rauschen verarbeiten muss, sinkt die Erkennungsrate für echte Anomalien.

**Ziele der Datenbereinigung:**

- **Token-Effizienz:** Reduzierung der Datenmenge für das Large Language Model (LLM).
- **Präzision:** Entfernung von bekannten Fehlalarmen (False Positives).
- **Struktur-Korrektur:** Sicherstellung, dass jedes Log exakt dem JSON/CSV-Standard entspricht.

## Teil 1: Filtering an der Quelle (PowerShell auf DC-01)

Anstatt alle Events von Windows an den Kali-Hub zu senden, filtern wir bekannte „Spam“-IDs direkt im Export-Skript aus Modul 7.5 aus.

**Optimiertes PowerShell Export-Skript**

```powershell
# Bekannte Rausch-IDs definieren (Beispiele)
# 4662: Zugriff auf Verzeichnisdienst-Objekt (sehr haeufig)
# 5156: Windows Filtering Platform erlaubte Verbindung
$NoiseIDs = @(4662, 5156, 5158)

$Events = Get-WinEvent -LogName "ForwardedEvents" -MaxEvents 1000
$CleanEvents = $Events | Where-Object { $NoiseIDs -notcontains $_.Id }

$StructuredData = $CleanEvents | ForEach-Object {
    [PSCustomObject]@{
        Time = $_.TimeCreated; ID = $_.Id;
        User = $_.UserId; Msg = ($_.Message -split "\r?\n")[0] # Nur erste Zeile der Meldung
    }
} | ConvertTo-Json -Compress
```

## Teil 2: Zentrale Bereinigung auf dem Kali-Hub (Python)

Auf dem Kali-Client nutzen wir ein Python-Skript, das die eingehenden CSV-Netzwerk-Logs (aus Modul 7.2/7.5) analysiert und redundante Zeilen (z. B. ständige DNS-Abfragen) zusammenfasst.

**Python: Log-Deduplizierung & Cleaning**

```python
import pandas as pd

# CSV einlesen (erstellt in Modul 7.5)
log_file = "/var/lib/siem-hub/syslog/network_structured.csv"
df = pd.read_csv(log_file, sep=';', names=['Timestamp', 'Host', 'Service', 'Message'])

# 1. Bekannte harmlose Services entfernen (z.B. NTP-Sync)
filtered_df = df[~df['Message'].str.contains('ntp|time-sync', case=False)]

# 2. Identische aufeinanderfolgende Meldungen zaehlen (Deduplizierung)
# Verhindert, dass 1000 "Connection Denied" Zeilen die KI fluten
df_grouped = filtered_df.groupby(['Host', 'Message']).size().reset_index(name='Occurrences')

# 3. Bereinigte Daten fuer die KI speichern
df_grouped.to_json("/var/lib/siem-hub/analysis/cleaned_batch.json", orient='records')
```

## Teil 3: Automatisierung der Bereinigung

Wir automatisieren den Bereinigungsprozess auf Kali mittels *Crontab*, damit die KI immer frische, saubere Daten vorfindet.

**1.** Öffnen Sie die Crontab: `crontab -e`

**2.** Fügen Sie folgende Zeile hinzu (Ausführung alle 30 Min.):

```bash
*/30 * * * * /usr/bin/python3 /home/kali/scripts/clean_logs.py
```

> [!NOTE]
> **Portfolio-Check: Strategische Datenreduktion**\
> Dokumentieren Sie diesen Schritt als „Pre-Processing Layer“. Erklären Sie, dass moderne SIEM-Infrastrukturen (wie Splunk oder Elastic) nach dem gleichen Prinzip arbeiten: Daten werden gefiltert und normalisiert, bevor sie den teuren Speicher oder die Analyse-Logik erreichen. Dies unterstreicht Ihre Kompetenz in der **Ressourcen-Optimierung** innerhalb einer Security-Pipeline.

> [!IMPORTANT]
> **Sicherheits-Hinweis zum Filtern:**\
> Löschen Sie niemals die Roh-Logs (`.evtx` auf dem DC oder die CSV auf dem Kali-Hub)! Die Bereinigung findet nur für die *Kopie* der Daten statt, die an die KI geht. Für eine spätere forensische Untersuchung (Incindent Response) müssen die ungefilterten Originaldaten weiterhin im Archiv (NAS) verfügbar sein.
