# 7.6 Erweiterte Überwachungsrichtlinien (Audit Policies)

## Konzept: Warum Advanced Audit Policies?

Damit der Kali-SIEM-Hub (Modul 7.4) und die KI (Phase 8) Angriffe erkennen können, müssen die Windows-Systeme die richtigen Beweise liefern. Die klassischen „Überwachungsrichtlinien“ sind zu grob gefasst. Wir nutzen die **Erweiterte Überwachungsrichtlinienkonfiguration**, um:

- **Rauschen zu reduzieren:** Nur relevante Events loggen (spart Speicherplatz auf dem Kali-Hub).
- **Prozess-Tracking:** Zu sehen, welches Programm (z. B. `mimikatz.exe`) gestartet wurde.
- **Präzise Login-Daten:** Unterscheidung zwischen Netzwerk-Logins und physischen Logins.

## Schritt 1: GPO für die Überwachung erstellen

Führen Sie diese Schritte auf dem `SRV-DC-01` aus.

**1.1** Öffnen Sie die **Gruppenrichtlinienverwaltung** (`gpmc.msc`).

**1.2** Erstellen Sie ein neues GPO namens **`SEC-Baseline-Auditing`**.

**1.3** Verknüpfen Sie das GPO mit der obersten Ebene der Domäne (`ad.example.com`), damit alle Server und Clients überwacht werden.

**1.4** Rechtsklick → **Bearbeiten**.

## Schritt 2: Die wichtigsten Audit-Einstellungen

Navigieren Sie zu: *Computerkonfiguration* → *Richtlinien* → *Windows-Einstellungen* → *Sicherheitseinstellungen* → *Erweiterte Überwachungsrichtlinienkonfiguration*.

Aktivieren Sie in den Unterkategorien jeweils **Erfolg** und **Fehler** für folgende Punkte:

| **Kategorie** | **Unterkategorie** | **Zweck für die KI** |
| --- | --- | --- |
| **Anmelden/Abmelden** | Anmelden | Erkennt Brute-Force (Event 4625). |
| **Kontenverwaltung** | Benutzerkontenverwaltung | Erkennt unbefugte Admin-Erstellungen. |
| **Detailtracking** | Prozessoberfläche | **Wichtig:** Erkennt Schadsoftware-Starts (4688). |
| **Objektzugriff** | Dateisystem | Überwacht Zugriffe auf sensible Shares (NAS). |
| **Richtlinienänderung** | Authentifizierungsrichtlinie | Erkennt Manipulationen an der Firewall/GPO. |

## Schritt 3: Erzwingen der erweiterten Richtlinien (Kritisch)

Windows ignoriert die erweiterten Richtlinien oft, wenn die alten „Legacy“-Richtlinien noch aktiv sind. Wir müssen den Vorrang erzwingen.

**3.1** Navigieren Sie im selben GPO zu: *Sicherheitseinstellungen* → *Lokale Richtlinien* → *Sicherheitsoptionen*.

**3.2** Suchen Sie die Richtlinie: **Überwachung: Unterkategorien der Überwachungsrichtlinie erzwingen...**

**3.3** Setzen Sie diese auf **Aktiviert**.

## Schritt 4: Command-Line Logging (Deep Visibility)

Damit wir im Log nicht nur sehen, DASS eine `cmd.exe` gestartet wurde, sondern auch WELCHER Befehl getippt wurde:

**4.1** Navigieren Sie zu: *Computerkonfiguration* → *Administrative Vorlagen* → *System* → *Überwachung der Prozesserstellung*.

**4.2** Aktivieren Sie: **Befehlszeile in Prozesserstellungsereignissen einschließen**.

## Schritt 5: Verifizierung am Client

Führen Sie auf `CL-WIN-01` ein `gpupdate /force` aus. Prüfen Sie danach die effektiven Richtlinien:

**Prüfung der aktiven Audit-Vorgaben**

```bash
auditpol /get /category:*
```

*Ergebnis:* Sie sollten eine lange Liste sehen, in der Ihre in Schritt 2 gewählten Kategorien auf „Erfolg und Fehler“ stehen.

> [!NOTE]
> **Portfolio-Check: Threat Hunting Readiness**\
> Dokumentieren Sie, dass diese Konfiguration die Basis für **Threat Hunting** ist. Erklären Sie: „Durch das Command-Line Logging kann die KI in Phase 8 sogar Powershell-Angriffe (Fileless Malware) erkennen, da der gesamte Befehlscode im Event 4688 übertragen und über den WEF-Staging-Server zum Kali-Hub weitergeleitet wird.“
