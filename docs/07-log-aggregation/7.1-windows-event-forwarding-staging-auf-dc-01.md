# 7.1 Windows Event Forwarding (Staging auf DC-01)

## Konzept: Windows-Log-Aggregation vor dem KI-Hub

In unserer neuen SIEM-Architektur ist der Kali-Client das Endziel. Da Windows-Events jedoch ein proprietäres Binärformat (`.evtx`) nutzen, schalten wir den **`SRV-DC-01`** als Aggregator (Collector) dazwischen.

**Der Ablauf:**

1. Alle Windows-Systeme (HQ und Filiale) senden ihre Security-Events via WEF an den `SRV-DC-01`.
2. Der `SRV-DC-01` bündelt diese im Log *Forwarded Events*.
3. In einem späteren Schritt (Modul 7.3) werden diese Daten in JSON konvertiert und zum Kali-Hub gepusht.

## Schritt 1: Collector-Dienst aktivieren (SRV-DC-01)

Führen Sie diesen Befehl auf dem primären Domain Controller aus, um ihn für den Empfang von Events bereitzumachen.

**Event Collector initialisieren**

```bash
# In einer administrativen PowerShell
wecutil qc
```

Bestätigen Sie mit **Y**. Der Dienst „Windows-Ereignissammlung“ wird auf *Automatisch* gesetzt und gestartet.

## Schritt 2: Gruppenrichtlinie für Forwarder (GPO)

Wir müssen allen Windows-Rechnern im AD mitteilen, dass sie ihre Logs an den DC-01 senden sollen.

**2.1** Erstellen Sie ein GPO **`COMP-Log-Forwarding`** auf Domänenebene.

**2.2 WinRM Dienst aktivieren:**

*Computerkonf.* → *Richtlinien* → *Windows-Einstellungen* → *Sicherheitseinstellungen* → *Systemdienste*.\
Setzen Sie **Windows-Remoteverwaltung** auf **Automatisch**.

**2.3 Subscription Manager konfigurieren:**

*Computerkonf.* → *Admin. Vorlagen* → *Windows-Komponenten* → *Ereignisweiterleitung*.\
Aktivieren Sie **Ziel-Abonnement-Manager konfigurieren** und tragen Sie den DC-01 als Ziel ein:

```bash
    Server=http://SRV-DC-01.ad.example.com:5985/wsman/SubscriptionManager/WEC, Refresh=60
```

**2.4 Berechtigungen für das Security-Log:**

Damit der Netzwerkdienst die Logs lesen und versenden darf, fügen Sie die Gruppe **Netzwerkdienst** (Network Service) via GPO der lokalen Gruppe **Ereignislog-Leser** auf allen Systemen hinzu.

## Schritt 3: Abonnement (Subscription) einrichten

Nun definieren wir auf dem `SRV-DC-01`, welche Events genau gesammelt werden sollen.

**3.1** Öffnen Sie die **Ereignisanzeige** → **Abonnements**.

**3.2** Klicken Sie auf **Abonnement erstellen...**.

**3.3 Name:** `Windows-SIEM-Staging`

**3.4 Abonnement-Typ:** *Vom Quellcomputer initiiert* (Push-Verfahren).

**3.5 Computergruppen:** Fügen Sie *Domänencomputer* und *Domänencontroller* hinzu.

**3.6 Ereignisse auswählen:** Wählen Sie das Protokoll **Sicherheit** und filtern Sie ggf. nach kritischen IDs (z. B. 4624 für Logins, 4625 für Fehler).

## Schritt 4: Verifizierung (Der Weg zum Kali-Hub)

**4.1** Führen Sie auf dem `SRV-DC-02` (Filiale) ein `gpupdate /force` aus.

**4.2** Prüfen Sie auf dem `SRV-DC-01` unter *Windows-Protokolle* → *Forwarded Events*.

**4.3** Erscheinen Einträge vom Filial-DC, funktioniert die Aggregation über den VPN-Tunnel hinweg.

> [!NOTE]
> **Portfolio-Check: Architektur-Vorteil**\
> Dokumentieren Sie, dass dieses „Staging“ auf dem DC-01 die Last auf dem Kali-Client minimiert. Anstatt dass hunderte Windows-Systeme einzeln eine Samba-Verbindung zum Kali-Hub aufbauen, bündelt der DC-01 alle Events. Dies schont die Ressourcen des Kali-SIEMs (CPU/RAM) für die eigentliche KI-Analyse, da nur noch ein einziger, strukturierter Datenstrom verarbeitet werden muss.
