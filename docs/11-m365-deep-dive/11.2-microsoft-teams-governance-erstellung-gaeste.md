# 11.2 Microsoft Teams Governance (Erstellung & Gäste)

## Konzept: Vermeidung von „Teams-Wildwuchs“

Standardmäßig darf jeder Microsoft 365 Benutzer eigene Microsoft 365-Gruppen (und damit Teams und verbundene SharePoint-Sites) erstellen. In produktiven Enterprise-Umgebungen führt dies schnell zu Hunderten von verwaisten Teams, unklaren Datenablagen und einem erhöhten Risiko für Datenabfluss (Data Leakage) durch unkontrollierte Gast-Einladungen.

**Ziele der Governance-Strategie:**

- **Eingeschränkte Erstellung:** Nur autorisierte Benutzer (z. B. IT-Admins oder Abteilungsleiter) dürfen neue Teams erstellen.
- **Namenskonventionen:** Einheitliche Präfixe (z. B. `PRJ_`) für Projekt-Teams erzwingen.
- **Kontrollierter Gastzugriff:** Definieren, was Externe in einem Team dürfen und was nicht.

## Schritt 1: Sicherheitsgruppe im lokalen AD erstellen

Wir steuern die Berechtigung zur Teams-Erstellung zentral über unser lokales Active Directory und lassen den Entra Connect Agenten (Modul 6.2) die Arbeit machen.

**1.1** Melden Sie sich am `SRV-DC-01` an und öffnen Sie **Active Directory-Benutzer und -Computer**.

**1.2** Navigieren Sie zu `OU=CloudSyncUsers` (damit die Gruppe synchronisiert wird).

**1.3** Erstellen Sie eine neue Globale Sicherheitsgruppe namens **`GRP_Teams_Creator`**.

**1.4** Fügen Sie Ihren synchronisierten Admin- oder Power-User (z. B. `schulung@example.com`) als Mitglied hinzu.

**1.5** Erzwingen Sie einen Sync: `Start-ADSyncSyncCycle -PolicyType Delta` auf dem `SRV-SYNC-01`.

## Schritt 2: Teams-Erstellung per PowerShell einschränken

Microsoft bietet aktuell keine grafische Oberfläche, um die Gruppenerstellung global zu deaktivieren. Dies muss per PowerShell mit dem *Microsoft Graph* oder dem *AzureADPreview* Modul durchgeführt werden.

Führen Sie diesen Block auf Ihrem Windows-Client aus (verbunden mit dem Internet):

**PowerShell: M365 Gruppenerstellung einschränken**

```powershell
# Module installieren (falls noch nicht vorhanden)
Install-Module AzureADPreview -Force

# Mit dem Tenant als Global Admin verbinden
Connect-AzureAD

# Die ObjectID der zuvor synchronisierten Gruppe abrufen
$GroupName = "GRP_Teams_Creator"
$TargetGroup = Get-AzureADGroup -SearchString $GroupName

# Die globalen Verzeichniseinstellungen laden und anpassen
$Template = Get-AzureADDirectorySettingTemplate | Where-Object {$_.DisplayName -eq "Group.Unified"}
$Setting = $Template.CreateDirectorySetting()
$Setting["EnableGroupCreation"] = $false
$Setting["GroupCreationAllowedGroupId"] = $TargetGroup.ObjectId

# Einstellungen in den Tenant schreiben
New-AzureADDirectorySetting -DirectorySetting $Setting
```

*Als Datei:* [`scripts/11-m365-deep-dive/11.2-powershell-m365-gruppenerstellung.ps1`](../../scripts/11-m365-deep-dive/11.2-powershell-m365-gruppenerstellung.ps1)

*Ergebnis:* Wenn sich nun ein normaler Benutzer in Teams anmeldet, ist der Button „Team erstellen“ für ihn verschwunden. Nur Mitglieder der Gruppe dürfen den Button noch nutzen.

## Schritt 3: Gastzugriff im Teams Admin Center konfigurieren

Der externe Zugriff muss ausbalanciert sein: Offen genug für Zusammenarbeit, restriktiv genug für Sicherheit.

**3.1** Loggen Sie sich ins Teams Admin Center ein: `https://admin.teams.microsoft.com`.

**3.2** Navigieren Sie zu **Benutzer** → **Gastzugriff**.

**3.3 Gastzugriff in Teams zulassen:** Stellen Sie dies auf **Ein**.

**3.4** Konfigurieren Sie die Einschränkungen unter *Anrufe*, *Besprechungen* und *Nachrichten*:

- *Gäste dürfen gesendete Nachrichten löschen:* **Aus** (Compliance/Beweissicherung).
- *Gäste dürfen gesendete Nachrichten bearbeiten:* **Aus**.
- *Bildschirmfreigabe-Modus (Gäste):* Optional einschränken auf „Einzelne Anwendung“ statt des gesamten Desktops.

**3.5** Klicken Sie auf **Speichern**. *(Hinweis: Es kann bis zu 24 Stunden dauern, bis Gastrichtlinien im gesamten Tenant aktiv werden.)*

## Schritt 4: Namensrichtlinie (Naming Policy) konfigurieren

(Voraussetzung: Entra ID P1 Lizenz) Um Teams sofort zuzuordnen, können Präfixe erzwungen werden.

**4.1** Öffnen Sie das Microsoft Entra Admin Center: `https://entra.microsoft.com`.

**4.2** Navigieren Sie zu **Gruppen** → **Namensrichtlinie**.

**4.3** Fügen Sie unter *Gruppenbenennungsrichtlinie* ein Präfix hinzu:

- Typ: **Zeichenfolge** (String)
- Wert: `LAB_`

**4.4** *Zusatz:* Unter **Blockierte Wörter** können Sie Wörter wie `CEO`, `Gehalt` oder `HR` hochladen, die in Team-Namen verboten sein sollen.

> [!NOTE]
> **Portfolio-Check: Lifecycle Management**\
> Dokumentieren Sie in Ihrem Projektbericht, dass Teams Governance nicht nur aus Erstellungs-Einschränkungen besteht, sondern einen Lifecycle darstellt (Provisioning → Management → De-Provisioning). Erwähnen Sie **Ablaufrichtlinien (Expiration Policies)** als nächsten logischen Schritt: Ein Team, das 180 Tage lang inaktiv war (keine Datei-Uploads, keine Chats), fordert den Besitzer automatisch per E-Mail zur Verlängerung auf. Reagiert dieser nicht, wird das Team (inklusive verknüpfter SharePoint-Site) gelöscht. Das hält die Infrastruktur schlank und sicher.
