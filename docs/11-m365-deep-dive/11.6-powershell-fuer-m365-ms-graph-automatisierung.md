# 11.6 PowerShell für M365 (MS Graph Automatisierung)

## Konzept: Der Wechsel zu MS Graph

In der Vergangenheit wurden Microsoft 365 und Azure AD mit den PowerShell-Modulen `MSOnline` oder `AzureAD` verwaltet. Diese Module gelten als veraltet (deprecated) und wurden durch Microsoft abgelöst.

Der neue Industrie-Standard ist das **Microsoft Graph PowerShell SDK**. Es fungiert als API-Wrapper und kommuniziert direkt mit der modernen Microsoft Graph REST-API. Ein entscheidender Unterschied: Sie verbinden sich nicht mehr einfach als „Globaler Administrator“ mit vollen Rechten auf alles, sondern Sie fordern beim Login **spezifische Berechtigungen (Scopes)** an.

## Schritt 1: Installation & Authentifizierung

Führen Sie diese Schritte an Ihrem Windows-Client (`CL-WIN-01`) aus. Starten Sie eine administrative PowerShell.

**Installation und Login**

```powershell
# 1. Bereiten Sie die PowerShell vor (Execution Policy anpassen)
Set-ExecutionPolicy RemoteSigned -Force

# 2. Installieren Sie das Microsoft Graph Modul
Install-Module Microsoft.Graph -Scope CurrentUser -Force

# 3. Verbinden Sie sich mit dem Tenant (Interaktiver Login)
# WICHTIG: Wir fordern hier nur die Rechte an, Benutzer zu lesen und zu aendern!
Connect-MgGraph -Scopes "User.ReadWrite.All", "Directory.Read.All"
```

*Was passiert jetzt?* Es öffnet sich ein Browser-Fenster. Sie loggen sich mit `mika.varga@example.com` ein und bestätigen die MFA (Modul 11.5). Anschließend erscheint ein Fenster **Zustimmung anfordern** (Consent). Hier stimmen Sie zu, dass die PowerShell-App in Ihrem Namen Benutzerdaten bearbeiten darf.

## Schritt 2: Reporting (Daten abfragen)

Die Stärke der PowerShell liegt im schnellen Auslesen von Daten (Reporting). Wir generieren eine Liste aller Benutzer im Tenant.

**Einfaches Reporting mit Get-MgUser**

```powershell
# Alle Benutzer abrufen und bestimmte Eigenschaften anzeigen
Get-MgUser -All | Select-Object DisplayName, UserPrincipalName, AccountEnabled

# Erweiterte Abfrage: Nur Benutzer anzeigen, die nicht aus dem lokalen AD synchronisiert wurden (Cloud-Only)
Get-MgUser -All -Filter "onPremisesSyncEnabled eq null" | Select-Object DisplayName
```

## Schritt 3: Massen-Anpassungen (Bulk Operations)

Ein klassisches Szenario: Bevor Sie Lizenzen vergeben können (Modul 6.5), **muss** jedem Benutzer ein Verwendungsstandort (Usage Location, z. B. „AT“ für Österreich oder „DE“ für Deutschland) zugewiesen werden. Wenn der Entra Connect Sync 50 neue Benutzer anlegt, dauert das Klicken im Webportal viel zu lange.

Wir automatisieren dies, indem wir allen Benutzern, die noch keinen Standort haben, „AT“ zuweisen.

**Massen-Update von Benutzerattributen**

```powershell
# 1. Alle Benutzer abfragen, bei denen der Verwendungsstandort leer ist
$UsersWithoutLocation = Get-MgUser -All | Where-Object { [string]::IsNullOrEmpty($_.UsageLocation) }

# 2. Schleife starten und jeden Benutzer anpassen
foreach ($User in $UsersWithoutLocation) {
    Write-Host "Setze Standort 'AT' fuer $($User.DisplayName)..."
    Update-MgUser -UserId $User.Id -UsageLocation "AT"
}

Write-Host "Massen-Update abgeschlossen."
```

## Schritt 4: Sicherheit & Sitzung beenden

Da die MS Graph Token sehr weitreichende Berechtigungen haben können, trennen Sie die Verbindung nach der Arbeit immer.

```bash
Disconnect-MgGraph
```

> [!NOTE]
> **Portfolio-Check: Least Privilege Prinzip**\
> Heben Sie in Ihrer Projektdokumentation das **Scope-basierte Rechtemodell** von MS Graph hervor. Erklären Sie: „Selbst wenn ein Skript kompromittiert wird, kann es nur das tun, was beim `Connect-MgGraph -Scopes...` freigegeben wurde.“
>
> Wenn Sie das Skript aus Schritt 3 in einem **Azure Automation Runbook** oder als geplanten Task laufen lassen würden, nutzt man dafür moderne **App-Registrierungen** (Service Principals) anstelle von Benutzernamen und Passwörtern. Das beweist tiefgehendes Enterprise-Verständnis im Cloud-Automatisierungsbereich.

> [!IMPORTANT]
> **Tipp zur Migration (AzureAD zu Graph):**\
> Falls Sie im Internet alte Tutorials finden, die `Get-AzureADUser` verwenden: Sie können diese Befehle im Kopf einfach mit `Get-MgUser` „übersetzen“. Beachten Sie jedoch, dass MS Graph im Hintergrund Hash-Tables und Objekte (Graph-Typen) anders zurückgibt, weshalb Eigenschaften oft mit `Select-Object -ExpandProperty` aufgerufen werden müssen.
