# 11.5 Security Defaults & MFA (Überprüfung der Anmeldesicherheit)

## Konzept: Identität als neue Firewall (Zero Trust)

In einer Cloud-basierten Welt reicht die Perimeter-Firewall (Modul 2.6) nicht mehr aus, um Firmendaten zu schützen, da Benutzer von überall auf E-Mails und Dateien zugreifen. Die **Identität** wird zur neuen Sicherheitsgrenze.

Die **Sicherheitsstandards (Security Defaults)** sind ein kostenloses Feature in Microsoft Entra ID. Sie bieten vorkonfigurierte Sicherheitseinstellungen, die 99,9 % der identitätsbezogenen Angriffe (wie Password Spraying oder Phishing) blockieren.

**Kernfunktionen der Security Defaults:**

- **MFA für alle Benutzer:** Jeder Benutzer muss sich für die Multi-Faktor-Authentifizierung registrieren.
- **MFA für Administratoren zwingend:** Bei jedem Login eines Admins wird MFA sofort gefordert.
- **Blockierung von Legacy-Authentifizierung:** Veraltete Protokolle (wie POP3, IMAP, SMTP ohne moderne Authentifizierung), die kein MFA unterstützen, werden netzwerkweit blockiert.

## Schritt 1: Aktivierung im Entra Admin Center

Standardmäßig sind die Security Defaults in neuen Tenants bereits aktiv. Wir überprüfen dies und stellen sicher, dass die Richtlinie greift.

**1.1** Melden Sie sich als globaler Administrator (`mika.varga@example.com`) an.

**1.2** Öffnen Sie das **Microsoft Entra Admin Center** (`entra.microsoft.com`).

**1.3** Navigieren Sie im linken Menü zu **Identität** → **Übersicht** → **Eigenschaften**.

**1.4** Scrollen Sie ganz nach unten und klicken Sie auf den blauen Link: **Sicherheitsstandards verwalten** (Manage security defaults).

**1.5** Ein Seitenbereich öffnet sich. Stellen Sie das Dropdown-Menü auf **Aktiviert** (Enabled).

**1.6** Klicken Sie auf **Speichern**.

## Schritt 2: Die User Experience (MFA-Registrierung)

Wir testen nun, was passiert, wenn sich Ihr Lab-Benutzer anmeldet.

**2.1** Melden Sie sich auf Ihrem Windows-Client (`CL-WIN-01`) von allen M365-Diensten ab.

**2.2** Versuchen Sie, sich in Outlook Web (`outlook.office.com`) mit `schulung@example.com` anzumelden.

**2.3 Die Unterbrechung:** Nach Eingabe des Passworts erscheint die Meldung: *„Ihre Organisation benötigt weitere Informationen, um die Sicherheit Ihres Kontos zu gewährleisten.“*

**2.4 Grace Period (Schonfrist):** Der Benutzer hat nun 14 Tage Zeit, die MFA-App einzurichten. Er könnte dies vorerst überspringen, danach wird der Login jedoch hart blockiert.

**2.5 Einrichtung:** Der Benutzer wird angeleitet, die **Microsoft Authenticator App** auf seinem Smartphone zu installieren und den QR-Code auf dem Bildschirm zu scannen.

## Schritt 3: Überprüfung blockierter Protokolle

Durch die Security Defaults können Angreifer keine simplen Skripte mehr nutzen, um Passwörter über das E-Mail-Protokoll IMAP durchzuprobieren.

**3.1** Versuchen Sie (theoretisch oder praktisch mit einem Tool wie Thunderbird), eine Verbindung über klassisches IMAP/SMTP (Basic Authentication) zum Postfach `schulung@example.com` aufzubauen.

**3.2 Ergebnis:** Die Verbindung wird von Microsoft hart abgewiesen, selbst wenn das Passwort korrekt ist, da diese Protokolle die MFA-Aufforderung nicht darstellen können. E-Mails können nur noch über moderne Apps (Outlook, Teams, native Apple Mail App mit OAuth2) abgerufen werden.

> [!NOTE]
> **Portfolio-Exkurs: Security Defaults vs. Conditional Access**\
> Erklären Sie in Ihrer Abschluss-Dokumentation den Unterschied zwischen den kostenlosen *Security Defaults* und dem lizenzpflichtigen *Conditional Access* (Bedingter Zugriff, erfordert Entra ID P1 / M365 Business Premium):
>
> - **Security Defaults** sind ein „Alles-oder-Nichts“-Ansatz. Sie können keine Ausnahmen definieren (z. B. für Scanner, die noch altes SMTP nutzen müssen).
> - **Conditional Access** ermöglicht granulare Wenn-Dann-Regeln: *„WENN der Benutzer aus dem HQ-Netzwerk (Trusted IP) kommt UND das Gerät Hybrid-Joined ist (Modul 6.4), DANN fordere kein MFA. Kommt er aus einem ungesicherten WLAN, fordere MFA.“*\
>   Zeigen Sie im Portfolio, dass Sie diesen Unterschied kennen und wissen, wann in Enterprise-Konzernen der Wechsel auf Entra ID P1 zwingend wird.

> [!WARNING]
> **Sicherheits-Hinweis: Der Break-Glass Account**\
> Wenn Sie MFA für alle Administratoren erzwingen, riskieren Sie, sich selbst aus dem Tenant auszusperren (z. B. wenn Ihr Handy mit der Authenticator-App defekt ist und die Handynummer wechselt).
>
> vergeben Sie ein 30+ stelliges komplexes Passwort, legen Sie dieses Passwort in einen physischen Tresor und schließen Sie diesen Account von der MFA-Pflicht aus (Achtung: Dies geht nur über Conditional Access, nicht über Security Defaults!).

**Best Practice:** Erstellen Sie einen Cloud-Only Admin-Account (z. B. `notfall-admin@contoso.onmicrosoft.com`),
