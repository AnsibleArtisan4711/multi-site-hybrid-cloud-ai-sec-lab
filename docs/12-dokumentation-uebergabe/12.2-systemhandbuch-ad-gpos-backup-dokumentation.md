# 12.2 Systemhandbuch: AD, GPOs & Backup-Dokumentation

## Zweck des Systemhandbuchs

Dieses Dokument dient als zentrale technische Referenz (Betriebshandbuch) für die `ad.example.com` Infrastruktur. Es dokumentiert die logische Struktur des Active Directorys, das etablierte Set an Gruppenrichtlinien (GPOs) zur Durchsetzung der Unternehmenssicherheit sowie das 3-2-1 Disaster-Recovery-Konzept.

## \1. Active Directory Architektur

Das Active Directory wurde nach dem **Microsoft Tier-Modell** (Schichtenmodell) zur Vermeidung von Privilege Escalation und Lateral Movement konzipiert.

### 1.1 Domänen- und Standort-Topologie

- **Interner Namespace (AD):** `ad.example.com` (Forest Root Domain)
- **Externes Suffix (UPN):** `@example.com` (für Microsoft 365 / Entra ID)
- **Funktionsebene:** Windows Server 2016 oder höher.

| **Standort (Site)** | **Subnetz** | **Domain Controller** | **Rollen** |
| --- | --- | --- | --- |
| **HQ** | `10.0.10.0/24` | `SRV-DC-01` | Alle FSMO-Rollen, Global Catalog, DNS, DHCP. |
| **Filiale** | `10.0.30.0/24` | `SRV-DC-02` | Global Catalog, lokales DNS. |

*Replikation:* Erfolgt über den WireGuard-IPsec-Tunnel (Site-Link: `DEFAULTIPSITELINK`, Kosten: 100, Intervall: 15 Minuten).

### 1.2 Organisationsstruktur (OU-Design)

Die Organisationseinheiten (OUs) spiegeln das Sicherheitsmodell wider.

- **OU=Tier0:** Enthält Domain Controller und den `SRV-SYNC-01` (Entra Connect).
- **OU=Tier1:** Enthält Infrastruktur-Server (`SRV-FS-01`) und Dienstkonten (`svc-syslog`, `svc-log-push`).
- **OU=Tier2:** Enthält Endbenutzer-Geräte (`CL-WIN-01`, `CL-UBU-01`) und reguläre Benutzer.

  - **OU=CloudSyncUsers:** Dedizierte Unter-OU für Benutzer, die via Entra Connect in den Cloud-Tenant repliziert werden (OU-Filtering).

## \2. Gruppenrichtlinien-Objekte (GPOs)

Gruppenrichtlinien sind das zentrale Instrument zur Härtung der Windows-Clients und Automatisierung der Umgebung.

### 2.1 Domänenweite Richtlinien (Verknüpft auf Root-Ebene)

| **GPO Name** | **Module** | **Wichtige Einstellungen** |
| --- | --- | --- |
| **Default Domain Policy** | 5.3 | **Passwort:** Min. 12 Zeichen, Komplexität ein, Ablauf: Nie. **Kontosperrung:** Nach 5 Fehlversuchen für 15 Minuten. |
| **COMP-Log-Forwarding** | 7.1 | **WEF (Windows Event Forwarding):** WinRM Auto-Start. Subscription-Ziel: `http://SRV-DC-01:5985/wsman...` Netzwerkdienst zur Gruppe *Ereignislog-Leser* hinzugefügt. |
| **SEC-Baseline-Auditing** | 7.6 | **Advanced Auditing:** Überwachung von Logins, Objekten und Prozesserstellung erzwungen. Command-Line Logging (Event 4688) aktiviert. |

## \3. Backup & Disaster Recovery Dokumentation

Das Datensicherungskonzept basiert auf **Veeam Backup & Replication** und erfüllt die industrielle 3-2-1 Backup-Regel (3 Kopien, 2 Medien, 1 Offsite-Standort).

### 3.1 Storage Architektur (UGreen NAS DXP4800)

Der Backup-Server (`SRV-BKP-01`) ist eine Tier-0 Instanz und greift via **iSCSI** auf das NAS zu, um die Speicherblöcke gegen Ransomware-Übergriffe auf Netzwerk-Shares (SMB) zu isolieren.

- **Primary Repo (Laufwerk B:):** 3x8TB JBOD, NVMe-Lese-Cache. Formatiert mit **ReFS (64K Blocks)** für extrem schnelle und speicherplatzsparende synthetische Vollbackups (Fast Clone).
- **Secondary Repo (Laufwerk A:):** 1x14TB JBOD für langfristige Archive (GFS). Formatiert mit ReFS (64K).

### 3.2 Backup-Jobs & Methodik

| **Job-Name** | **Inhalt & Ziel** | **Spezielle Einstellungen** |
| --- | --- | --- |
| **JOB-Core-Infra** | `SRV-DC-01/02`, Firewalls → Primary Repo | **Application-Aware Processing** via Tier-0 Credentials (Zwingend für konsistente Active Directory VSS-Snapshots). |
| **JOB-T1-T2** | Webserver, Linux, Clients→ Primary Repo | Job-Chaining (startet nach Core-Infra). Erstellt samstags synthetische Vollbackups via ReFS Block Cloning. |
| **COPY-Secondary** | Kopie der obigen Jobs→ Secondary Repo | **Backup Copy Job** mit GFS-Aufbewahrung. Backups werden hierbei **AES-256 verschlüsselt** abgelegt. |

### 3.3 Offsite-Archivierung (Cloud Gateway)

Um die Daten gegen den Totalausfall des Labors (Feuer/Diebstahl) abzusichern, wird das **verschlüsselte** Secondary Repo automatisiert in die Cloud gespiegelt.

- **Tooling:** `rclone` (ausgeführt als Post-Job-Script in Veeam).
- **Ziel:** Google Drive (Google One 5TB / Cloud-Tier).
- **Sicherheit:** Da Veeam die Daten im Secondary Repo AES-256 verschlüsselt hat, liegen die Dateien als „Zero Knowledge“-Archiv bei Google. Niemand ohne das Veeam-Kennwort kann diese Daten lesen.

### 3.4 Restore-Prozesse (Recovery Time Objectives)

- **Instant VM Recovery (IVMR):** Ein zerstörter Server (z. B. nach Ransomware-Befall) wird in &lt; 3 Minuten direkt aus dem komprimierten Backup-Image vom NAS gebootet. Die Wiederherstellung (Migration to Production) auf die NVMe des Hyper-V Hosts erfolgt anschließend unterbrechungsfrei im Hintergrund.
- **Item-Level Recovery (AD/SQL):** Ein versehentlich gelöschter AD-Benutzer (oder eine GPO) wird **ohne** kompletten Server-Neustart via *Veeam Explorer for Microsoft Active Directory* live in den Domain Controller zurückinjiziert. Dies verhindert USN-Rollbacks der AD-Datenbank.

> [!TIP]
> **Hinweis zur Anlagen-Übergabe:**\
> Mit diesem Systemhandbuch, den Visio-Netzplänen (Modul 12.1) und der Management-Zusammenfassung liegt die Infrastruktur vollständig dokumentiert vor. Die administrativen Passwörter (sowie das AES-256 Passwort für das Veeam-Cloud-Backup) sind sicher in einem Offline-Tresor / Passwort-Manager verwahrt und physisch an die IT-Leitung übergeben worden.
