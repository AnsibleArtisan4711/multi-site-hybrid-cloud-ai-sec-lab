# 12.4 Notfall-Plan (Disaster Recovery Runbook)

## Zweck dieses Runbooks

Dieses Dokument ist die **Single Source of Truth** für den IT-Notfall. Es beschreibt die exakten administrativen Schritte zur Wiederherstellung des regulären Betriebs bei vier definierten Desaster-Szenarien. Prämisse: Während eines Ausfalls (*Downtime*) wird streng nach diesen Checklisten gearbeitet, um Fehler durch Stress oder Zeitdruck zu vermeiden.

## Szenario A: Ransomware-Befall einer einzelnen VM

**Auswirkung:** Eine virtuelle Maschine (z. B. `SRV-FS-01`) wurde verschlüsselt oder zerstört.\
**Ziel-RTO (Recovery Time Objective):** &lt; 5 Minuten.

**1. Isolation:** Schalten Sie die betroffene VM im Hyper-V Manager **sofort hart aus** (Ausschalten), um eine Ausbreitung der Malware im Netz zu stoppen.

**2. Veeam Console öffnen:** Melden Sie sich am Backup-Server (`SRV-BKP-01`) an.

**3. Instant VM Recovery (IVMR):**

- Gehen Sie zu *Home* → *Backups* → *Disk*.
- Rechtsklick auf die betroffene VM → **Restore** → **Instant Recovery** → **Hyper-V**.
- Wählen Sie den letzten sauberen Wiederherstellungspunkt.
- Haken bei *Connect VM to network* und *Power on VM automatically* setzen.

**4. Produktivschaltung:** Sobald die VM aus dem Backup bootet und die Dienste wieder erreichbar sind, Rechtsklick in Veeam auf die laufende Instant Recovery Session → **Migrate to production**. Der Speicher wird im Hintergrund zurück auf die schnelle SSD des Hosts kopiert.

## Szenario B: Versehentliche AD-Objekt Löschung

**Auswirkung:** Ein Administrator hat kritische Benutzer, OUs oder GPOs im Active Directory gelöscht.\
**Ziel-RTO:** &lt; 10 Minuten. **Achtung: Niemals den kompletten DC wiederherstellen (USN Rollback Gefahr)!**

**1. Veeam Explorer starten:** Öffnen Sie Veeam auf dem `SRV-BKP-01`.

**2.** Gehen Sie zu *Home* → *Backups* → *Disk* und wählen Sie den `JOB-Core-Infrastructure`.

**3.** Rechtsklick auf `SRV-DC-01` → **Restore application items** → **Microsoft Active Directory objects**.

**4. Compare State:** Klicken Sie in der Menüleiste des Veeam Explorers auf **Compare with Production**.

**5.** Suchen Sie die rot markierten (gelöschten) Objekte.

**6.** Rechtsklick auf das Objekt → **Restore to ad.example.com**.

**7.** Wählen Sie *Restore Passwords*, damit der Benutzer sein altes Kennwort behält.

## Szenario C: Physischer Hardware-Ausfall (Host 1)

**Auswirkung:** Der physische Windows Server (Hyper-V Host 1 im HQ) bootet nicht mehr (Hardware-Defekt oder OS-Crash). Die NAS (`STO-NAS-01`) ist jedoch unbeschädigt.

**1. Cold-Boot einleiten:** Nutzen Sie die in Modul 1.5 präparierte **SD-Karte** (Ventoy). Starten Sie den Server von der SD-Karte in ein Live-Rettungssystem (WinPE) oder installieren Sie den Windows Server Hyper-V Host komplett neu auf eine Austausch-SSD.

**2. Speicher anbinden:** Nach der Neuinstallation des Hosts verbinden Sie den **iSCSI-Initiator** wieder mit der IP der NAS (`10.0.10.250`). Das Backup-Laufwerk `B:` wird sofort als ReFS-Laufwerk erkannt.

**3. Veeam Wiederherstellung:**

- Installieren Sie Veeam (Community Edition) neu.
- Klicken Sie auf *Backup Infrastructure* → *Backup Repositories* → *Add Repository*. Binden Sie Laufwerk `B:` wieder ein.
- Rechtsklick auf das Repository → **Rescan**. Alle Backups tauchen nun unter *Home* → *Backups* → *Imported* auf.
- Führen Sie einen **Full VM Restore** aller VMs auf die SSD des neuen Hosts durch.

## Szenario D: Totalverlust des Standorts (Feuer/Diebstahl/Ransomware)

**Auswirkung:** Das gesamte Labor (Hosts und die NAS) wurde vernichtet oder verschlüsselt.\
**Rettungsanker:** Das Cloud-Gateway (Google Drive) aus Modul 10.4.

**1. Ersatz-Hardware beschaffen:** Stellen Sie einen neuen PC/Server bereit.

**2. Rclone Download:**

- Installieren Sie `rclone`.
- Authentifizieren Sie sich bei Ihrem Google Drive (`rclone config`).
- Laden Sie das Archiv herunter:\
  `rclone copy GDrive:Veeam_Offsite_Backup C:\Restore -v`

**3. Veeam Import & Entschlüsselung:**

- Installieren Sie Veeam Backup & Replication.
- Fügen Sie den Ordner `C:\Restore` als neues Backup Repository hinzu und scannen Sie es.
- Die Backups tauchen auf, sind aber verschlüsselt. Rechtsklick → **Specify Password**.
- Geben Sie das AES-256 Kennwort aus Modul 10.5 (aus Ihrem Passwort-Manager) ein.

**4. Wiederherstellung:** Die Kette ist entsperrt. Stellen Sie die VMs (angefangen bei DC und Firewall) wieder her.

> [!NOTE]
> **Portfolio-Check: Der Wert eines Runbooks**\
> Heben Sie in Ihrer Projektpräsentation hervor, dass die IT-Security nicht bei der Abwehr aufhört (Phase 9), sondern auch die Gewissheit der Wiederherstellbarkeit (Resilienz) umfasst. Ein solches tabellarisches Runbook beweist, dass Sie nicht nur Systeme konfigurieren können, sondern auch über das *Business Continuity Management (BCM)* nachgedacht haben, das Unternehmen nach einem Cyber-Angriff vor dem Bankrott bewahrt.
