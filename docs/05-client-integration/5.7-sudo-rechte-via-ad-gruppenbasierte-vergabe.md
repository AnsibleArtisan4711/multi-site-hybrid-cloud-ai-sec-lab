# 5.7 Sudo-Rechte via AD (Gruppenbasierte Vergabe)

## Konzept: Zentrales Access Management (IAM)

In Modul 5.2 haben wir einem spezifischen Benutzer (`adm-t2-mvarga@ad.example.com`) direkte Root-Rechte auf dem Ubuntu-Client gegeben. In Enterprise-Umgebungen ist dies jedoch schwer zu skalieren. Wenn Mitarbeiter das Unternehmen verlassen oder die Abteilung wechseln, müssten hunderte Linux-Clients manuell bereinigt werden.

**Die Lösung:** Wir weisen die Root-Berechtigung (`sudo`) einer Active Directory-Gruppe zu. Das Rechte-Management erfolgt ab sofort zu 100% zentral auf dem Windows Domain Controller.

## Schritt 1: AD-Gruppe vorbereiten (Auf dem DC)

Zuerst erstellen wir die steuernde Gruppe im Active Directory.

**1.1** Melden Sie sich auf dem `SRV-DC-01` an und öffnen Sie **Active Directory-Benutzer und -Computer**.

**1.2** Navigieren Sie zu Ihrer administrativen OU (z. B. *Tier2*).

**1.3** Erstellen Sie eine neue globale Sicherheitsgruppe mit dem Namen **`grp_linux_admins`**.

**1.4** Fügen Sie Ihren Tier-2 Administrator (z. B. `adm-t2-mvarga`) als Mitglied zu dieser Gruppe hinzu.

**1.5** *Wichtig:* Der Standard-Benutzer (`mvarga`) darf **nicht** in dieser Gruppe sein!

## Schritt 2: Die Sudoers-Datei anpassen (Auf dem Linux-Client)

Nun bringen wir dem Linux-System bei, dass Mitglieder dieser AD-Gruppe ab sofort `sudo` nutzen dürfen.

**2.1** Melden Sie sich auf dem Linux-Client (`CL-UBU-01`) mit Ihrem **lokalen Startbenutzer** (z. B. `edubuntu`) oder Ihrem zuvor autorisierten AD-Admin an.

**2.2** Öffnen Sie das Terminal und rufen Sie den Sudo-Editor auf. *(Nutzen Sie zwingend* *`visudo`**, da dieses Tool die Datei beim Speichern auf Syntax-Fehler prüft und Sie vor dem Aussperren bewahrt!)*

```bash
        sudo visudo
```

**2.3** Scrollen Sie in der Datei nach unten, bis Sie den Bereich sehen, in dem die Gruppe `%sudo` definiert ist.

**2.4** Fügen Sie direkt darunter folgende neue Zeile ein:

**Eintrag für die AD-Gruppe**

```bash

```

**Erklärung der Syntax:**

- Das **`%`** Zeichen am Anfang teilt Linux mit, dass es sich um eine *Gruppe* handelt (und nicht um einen einzelnen User).
- **`@ad.example.com`** stellt sicher, dass die Gruppe im Active Directory (SSSD) und nicht lokal gesucht wird.
- **`ALL=(ALL:ALL) ALL`** gewährt uneingeschränkte Root-Rechte auf dem System.

> [!IMPORTANT]
> **Praxis-Falle: AD-Gruppen mit Leerzeichen**\
> Hätten Sie die Windows-Standardgruppe *Domain Admins* nutzen wollen, gibt es ein Problem: Linux `sudoers` mag keine Leerzeichen in Gruppennamen. Sie müssen Leerzeichen mit einem Backslash (`\`) maskieren!\
> Beispiel: `%domain\admins@ad.example.comALL=(ALL:ALL)ALL`
>
> erstellt.

Aus genau diesem Grund haben wir in Schritt 1 die sauber formatierte Gruppe `grp_linux_admins`

## Schritt 3: Verifizierung & Live-Test

Das AD-Gruppen-Mapping ist sofort aktiv, es ist kein Neustart notwendig.

### Test A: Der Administrator

**1.** Melden Sie sich vom Linux-System ab.

**2.** Melden Sie sich grafisch mit `adm-t2-mvarga@ad.example.com` an.

**3.** Öffnen Sie ein Terminal und prüfen Sie Ihre Sudo-Rechte:

```bash
       sudo -l
```

*Ergebnis:* Linux fordert Sie zur Passwort-Eingabe auf und listet anschließend auf, dass Sie alle Befehle (`ALL`) ausführen dürfen, da Sie Mitglied der `grp_linux_admins` sind.

### Test B: Der Standard-Benutzer (Negative-Test)

**1.** Melden Sie sich nun als Standard-User `mvarga@ad.example.com` an.

**2.** Versuchen Sie, einen administrativen Befehl auszuführen:

```bash
       sudo apt update
```

*Ergebnis:* Der Befehl muss verweigert werden. Die Trennung (Tier-Modell) funktioniert fehlerfrei!
