# 5.5 LAPS Implementierung (Local Administrator Password Solution)

## Das Problem: Pass-the-Hash & Lateral Movement

In vielen Netzwerken haben alle lokalen Administrator-Konten auf den Windows-Clients (z. B. der eingebaute `Administrator`) dasselbe Passwort. Wenn ein Hacker oder eine Malware einen einzigen Client (z. B. `CL-WIN-01`) kompromittiert, kann er den Passwort-Hash dieses lokalen Admins aus dem Arbeitsspeicher (LSASS) auslesen. Mit diesem Hash kann sich der Angreifer fortan auf **jedem anderen System** im Netzwerk anmelden (*Pass-the-Hash*), ohne das Passwort im Klartext zu kennen.

**Die Lösung (LAPS):** Windows LAPS generiert für jeden Client ein individuelles, kryptografisch starkes lokales Admin-Passwort, rotiert dieses regelmäßig und speichert es sicher verschlüsselt im Active Directory.

## Schritt 1: AD-Schema für LAPS vorbereiten

Seit Windows 11 (22H2) und Windows Server 2022 ist **Windows LAPS** nativ in das Betriebssystem integriert. Wir müssen lediglich das Active Directory Schema erweitern, damit es die Passwörter aufnehmen kann.

Führen Sie dies als Domain-Admin (`adm-t0-mvarga`) auf dem `SRV-DC-01` aus:

**PowerShell: LAPS Schema-Erweiterung**

```powershell
# LAPS PowerShell-Modul laden und Schema aktualisieren
Update-LapsADSchema -Verbose
```

## Schritt 2: Berechtigungen (Permissions) vergeben

Die Computer müssen das Recht erhalten, ihr eigenes Passwort in das AD zu schreiben. Zudem müssen wir definieren, wer die Passwörter lesen darf (z. B. nur Tier-0 oder Tier-2 Admins).

**PowerShell: LAPS Berechtigungen setzen**

```powershell
# 1. Erlauben Sie den Computern in der Tier-2 OU, ihr eigenes Passwort zu aktualisieren:
Set-LapsADComputerSelfPermission -Identity "OU=Workstations,OU=Tier2,DC=ad,DC=example,DC=com"

# 2. Erlauben Sie den Domänen-Admins, die Passwörter auszulesen:
Set-LapsADReadPasswordPermission -Identity "OU=Workstations,OU=Tier2,DC=ad,DC=example,DC=com" -AllowedPrincipals "Domänen-Admins"
```

## Schritt 3: LAPS Gruppenrichtlinie (GPO) erstellen

Damit der Client `CL-WIN-01` weiß, dass er LAPS nutzen soll, erstellen wir ein neues GPO.

**3.1** Öffnen Sie die **Gruppenrichtlinienverwaltung** auf dem DC.

**3.2** Rechtsklick auf die Tier-2 Workstations OU → *Gruppenrichtlinienobjekt hier erstellen...*

**3.3** Name: **`SEC-Workstations-LAPS`**.

**3.4** Rechtsklick auf das neue GPO → **Bearbeiten**.

**3.5 Kritischer Zwischenschritt (Admin-Konto aktivieren):**

Standardmäßig ist das Administratorkonto in Windows 11 deaktiviert. Navigieren Sie zu: *Computerkonfiguration* → *Richtlinien* → *Windows-Einstellungen* → *Sicherheitseinstellungen* → *Lokale Richtlinien* → *Sicherheitsoptionen*. Setzen Sie dort **Konten: Status des Administratorkontos** auf **Aktiviert**.

**3.6** Navigieren Sie nun zu den LAPS-Einstellungen: *Computerkonfiguration* → *Richtlinien* → *Administrative Vorlagen* → *System* → *LAPS*.

**3.7** Konfigurieren Sie folgende Richtlinien:

- **LAPS konfigurieren:** Aktiviert (Sicherungs-Verzeichnis: *Active Directory*).
- **Kennworteinstellungen:** Aktiviert (Komplexität: Große & kleine Buchstaben, Zahlen, Sonderzeichen / Länge: *16 Zeichen* / Alter: *30 Tage*).
- **Name des zu verwaltenden Administratorkontos:** Aktiviert. Geben Sie hier `Administrator` ein.

  - **Hintergrundwissen (Built-in Admin):** Jedes Windows-System besitzt ein vorinstalliertes, lokales Administratorkonto mit den höchsten Rechten (die sogenannte SID- 500). Auf deutschen Systemen heißt dieses Konto standardmäßig `Administrator`. LAPS muss exakt wissen, wessen Passwort es ändern und verwalten soll. Wenn Sie dieses Standardkonto in Ihrer Domäne belassen haben, tragen Sie hier `Administrator` ein. Falls Sie das Konto jedoch per GPO aus Sicherheitsgründen umbenannt haben (z. B. in `sys-admin`), müssten Sie LAPS hier den neuen Namen mitteilen.

## Schritt 4: Verifizierung am Client & im AD

**4.1** Starten Sie `CL-WIN-01` und führen Sie in der CMD `gpupdate /force` aus.

**4.2** Öffnen Sie auf dem Domain Controller **Active Directory-Benutzer und -Computer**.

**4.3** Suchen Sie das Computer-Objekt `CL-WIN-01`.

**4.4** Rechtsklick → **Eigenschaften** → Reiter **LAPS**.

**4.5 Erfolg:** Sie sehen nun das aktuell gültige, automatisch generierte 16-stellige Klartext-Passwort des lokalen Administrators und das Ablaufdatum.

## Schritt 5: LAPS in der Praxis (Anwendung)

Das LAPS-Passwort bietet keinen „Single Sign-On“ Komfort, sondern ist bewusst als manueller Schlüssel für administrative Tätigkeiten auf dem lokalen Endgerät konzipiert. In diesen drei Szenarien wenden Sie es an:

**a.) Die Benutzerkontensteuerung (UAC):** Ein Mitarbeiter (Standard-Benutzer) meldet sich am `CL-WIN-01` an und möchte eine Software installieren. Die Windows-UAC fragt nach Administrator-Zugangsdaten. Sie lesen das Passwort im AD aus und geben im UAC-Fenster als Benutzer **`.\Administrator`** (das`.\` erzwingt die lokale Anmeldung statt der Domäne) und das kopierte LAPS-Passwort ein.

**b.) Der Domänen-Verlust (Notfall-Login):** Fällt der VPN-Tunnel oder der DNS aus, kann der Client den Domain Controller nicht erreichen. Eine Anmeldung mit AD-Konten schlägt fehl. Über den lokalen Administrator und das LAPS-Passwort können Sie sich dennoch am PC anmelden und das Netzwerk reparieren.

**c.) Copy & Paste statt Abtippen:** Da das Abtippen von 16 kryptischen Zeichen fehleranfällig ist, nutzt der Administrator idealerweise Remote Desktop (RDP) oder die „Erweiterte Sitzung“ (Enhanced Session) in Hyper-V. Dadurch lässt sich das Passwort direkt aus der Active Directory-Konsole am Server kopieren und in den Client einfügen.

> [!NOTE]
> **Portfolio-Highlight: Was passiert mit Linux (Edubuntu)?**\
> Windows LAPS ist ein rein Microsoft-spezifisches Protokoll und wird vom `CL-UBU-01` (Edubuntu) ignoriert. Um ein ähnliches Sicherheitsniveau auf Linux-Clients zu erreichen, dokumentieren Sie, dass Sie auf Linux stattdessen den lokalen `root`-Login per Passwort komplett deaktiviert haben (`PermitRootLogin no` in SSH) und administrative Rechte ausschließlich über die AD-Authentifizierung (`sudo` Rechte für die *Domänen-Admins* via SSSD) gesteuert werden.
