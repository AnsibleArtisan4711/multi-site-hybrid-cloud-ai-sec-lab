# 5.4 GPO: File Shares (Automatische Netzlaufwerke)

## Konzept der Laufwerkszuordnung (Drive Mapping)

In Unternehmensnetzwerken speichern Benutzer ihre Daten nicht lokal, sondern auf zentralen Servern (NAS). Um den Zugriff so einfach wie möglich zu gestalten, werden UNC-Pfade (wie `\\STO-NAS-01\Projekte`) automatisch als feste Laufwerksbuchstaben (z. B. `P:`) in Windows eingebunden. Hierfür nutzen wir die **Group Policy Preferences (GPP)**.

## Voraussetzung: Die NAS-Freigabe

Bevor wir das GPO erstellen, muss die Freigabe auf dem NAS existieren.

**1.** Öffnen Sie die Weboberfläche der UGreen NAS (UGOS Pro).

**2.** Erstellen Sie unter *Dateidienste* einen neuen freigegebenen Ordner namens **Projekte**.

**3. AD-Integration (Best Practice):** Sofern Ihre NAS an das Active Directory angebunden ist (LDAP/AD Join), vergeben Sie die Lese-/Schreibrechte direkt an die AD-Gruppe `Domänen-Benutzer`.

**4. UNC-Pfad notieren:** Der Pfad lautet nun: `\\10.0.10.250\Projekte` (oder `\\STO-NAS-01\Projekte`).

## Schritt 1: Das GPO erstellen

Da Netzlaufwerke immer einem **Benutzer** (nicht dem Computer) zugewiesen werden, verknüpfen wir dieses GPO mit der OU, in der sich Ihre Benutzerkonten befinden.

**1.1** Öffnen Sie auf dem Domain Controller (`SRV-DC-01`) die **Gruppenrichtlinienverwaltung**.

**1.2** Navigieren Sie zur OU Ihrer Mitarbeiter (z. B. `ad.example.com` → `Tier2` → `Users`).

**1.3** Rechtsklick → **Gruppenrichtlinienobjekt hier erstellen und verknüpfen...**

**1.4** Name: **`USR-DriveMaps-Projekte`**

**1.5** Rechtsklick auf das neue GPO → **Bearbeiten**.

## Schritt 2: Die Laufwerkszuordnung konfigurieren

Navigieren Sie zu: *Benutzerkonfiguration* → *Einstellungen* → *Windows-Einstellungen* → *Laufwerkszuordnungen*.

**2.1** Rechtsklick in den freien Bereich → **Neu** → **Zugeordnetes Laufwerk**.

**2.2** Füllen Sie die Registerkarte **Allgemein** wie folgt aus:

- **Aktion:** `Aktualisieren` (Update). Dies ist der sicherste Modus, da er bestehende Laufwerke aktualisiert, ohne sie bei jedem Login hart zu trennen (wie es „Ersetzen“ tun würde).
- **Standort:** `\\10.0.10.250\Projekte`
- **Erneut verbinden:** `Aktiviert`
- **Beschriftung als:** `Projektdaten (NAS)`
- **Laufwerksbuchstabe:** Verwenden Sie `P:`
- **Ausblenden/Anzeigen:** `Dieses Laufwerk einblenden`

## Schritt 3: Zielgruppenadressierung (Portfolio-Highlight)

Dies ist ein Enterprise-Feature. Wir sorgen dafür, dass das Laufwerk **nur** Benutzern angezeigt wird, die in einer bestimmten AD-Gruppe sind.

**3.1** Wechseln Sie in den Eigenschaften des Laufwerks in den Reiter **Gemeinsame Optionen**.

**3.2** Setzen Sie den Haken bei **Zielgruppenadressierung auf Elementebene** und klicken Sie auf **Zielgruppenadressierung...**

**3.3** Klicken Sie auf **Neues Element** → **Sicherheitsgruppe**.

**3.4** Klicken Sie auf den Button`...` und suchen Sie die AD-Gruppe (z. B. `Domänen-Benutzer` oder eine neu erstellte Gruppe `GRP_RW_Projekte`).

**3.5** Klicken Sie überall auf OK, um das GPO zu speichern.

## Schritt 4: Verifizierung am Windows-Client

**4.1** Melden Sie sich an Ihrem Windows-Client (`CL-WIN-01`) mit Ihrem Test-Benutzer an.

**4.2** Öffnen Sie die Kommandozeile und erzwingen Sie ein Policy-Update:

```bash
        gpupdate /force
```

**4.3** (Optional) Melden Sie sich einmal ab und wieder an.

**4.4** Öffnen Sie den **Windows Explorer**. Unter *Dieser PC* erscheint nun vollautomatisch das Laufwerk **Projektdaten (NAS) (P:)**.

> [!NOTE]
> **Linux-Integration: Wie bekommt Edubuntu die Laufwerke?**\
> Gruppenrichtlinien-Einstellungen (GPPs) für Laufwerke sind ein Windows-spezifisches Feature. Um denselben Komfort auf dem in Modul 5.2 gejointen Edubuntu-Client (`CL-UBU-01`) zu erreichen, nutzt der Linux-Administrator das Modul **`pam_mount`**.\
> Wird dies konfiguriert, liest das Modul beim grafischen Login des AD-Benutzers in Edubuntu dessen Kerberos-Ticket aus und hängt das NAS-Share (SMB) automatisch (z. B. nach `/media/Projekte`) ein, ohne dass der Benutzer sein Passwort erneut eingeben muss (Single Sign-On für Storage).
