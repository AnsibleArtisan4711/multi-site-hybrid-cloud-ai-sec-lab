# 5.3 GPO: Basis-Security (Kennwort & Bildschirmsperre)

## Konzept der Gruppenrichtlinien (GPOs)

Gruppenrichtlinien (Group Policy Objects) sind das mächtigste Werkzeug in einer Windows-Domäne, um Einstellungen und Sicherheitsvorgaben zentral auf hunderte Clients und Benutzer auszurollen.

- **Domänen-Ebene:** Richtlinien, die für alle gelten (wie Passwörter), werden auf der obersten Ebene verknüpft (Default Domain Policy).
- **OU-Ebene:** Spezifische Richtlinien (wie die Bildschirmsperre für Büro-PCs) werden nur mit der jeweiligen Organisationseinheit (z. B. Tier 2 Workstations) verknüpft.

Um Ihr Active Directory gegen Brute-Force- und Dictionary-Angriffe zu härten, passen wir die standardmäßige *Default Domain Policy* an.

### Richtlinie bearbeiten

Loggen Sie sich als `adm-t0-mvarga` auf dem `SRV-DC-01` ein.

**1.** Öffnen Sie die **Gruppenrichtlinienverwaltung** (`gpmc.msc`).

**2.** Navigieren Sie zu Gesamtstruktur → Domänen → `ad.example.com`.

**3.** Klicken Sie mit der rechten Maustaste auf die **Default Domain Policy** und wählen Sie **Bearbeiten**.

### Kennwortrichtlinien konfigurieren

Navigieren Sie zu: *Computerkonfiguration* → *Richtlinien* → *Windows-Einstellungen* → *Sicherheitseinstellungen* → *Kontorichtlinien* → *Kennwortrichtlinien*.

| **Einstellung** | **Empfohlener Wert für das Lab** |
| --- | --- |
| **Kennwort muss Komplexitätsvoraussetzungen entsprechen** | Aktiviert |
| **Minimale Kennwortlänge** | 12 Zeichen (BSI-Empfehlung) |
| **Maximales Kennwortalter** | 0 (Deaktiviert) - *Moderne Vorgabe: Passwörter sollen nicht mehr routinemäßig ablaufen, da dies Nutzer zu schwachen Mustern zwingt.* |

### Kontosperrungsrichtlinien konfigurieren (Anti Brute-Force)

Wechseln Sie in den Ordner **Kontosperrungsrichtlinien** (direkt unter Kennwortrichtlinien).

| **Einstellung** | **Empfohlener Wert** |
| --- | --- |
| **Kontosperrungsschwelle** | 5 ungültige Anmeldeversuche |
| **Kontosperrungsdauer** | 15 Minuten |
| **Zähler für Kontosperrung zurücksetzen nach** | 15 Minuten |

**Bildschirmsperre (Inaktivitätslimit)**

Um zu verhindern, dass unbefugte Personen auf verwaiste Rechner zugreifen (z. B. wenn ein Mitarbeiter den Platz verlässt), erzwingen wir eine automatische Bildschirmsperre.

### Neues GPO für Workstations erstellen

**1.** Gehen Sie in der Gruppenrichtlinienverwaltung zu Ihrer Tier 2 Workstations-OU (z. B. `ad.example.com` → `Tier2` → `Workstations`).

**2.** Rechtsklick auf die OU → **Gruppenrichtlinienobjekt hier erstellen und verknüpfen...**

**3.** Nennen Sie das GPO **`SEC-Workstations-Base`** und klicken Sie auf OK.

**4.** Rechtsklick auf das neue GPO → **Bearbeiten**.

### Inaktivitätslimit konfigurieren

Navigieren Sie zu: *Computerkonfiguration* → *Richtlinien* → *Windows-Einstellungen* → *Sicherheitseinstellungen* → *Lokale Richtlinien* → *Sicherheitsoptionen*.

- Suchen Sie die Richtlinie: **Interaktive Anmeldung: Limit für Computerinaktivität**.
- Aktivieren Sie die Richtlinie und setzen Sie den Wert auf **900 Sekunden** (15 Minuten).

**Verifizierung (gpupdate)**

Damit die Änderungen auf Ihrem Windows-Client sofort aktiv werden, müssen die Richtlinien aktualisiert werden.

**1.** Melden Sie sich auf Ihrem Client `CL-WIN-01` mit Ihrem Standard-Benutzer an.

**2.** Öffnen Sie die Kommandozeile (CMD) und führen Sie den Update-Befehl aus:

**Gruppenrichtlinien erzwingen**

```bash
gpupdate /force
```

**1. Prüfung:** Um zu sehen, ob das GPO angekommen ist, geben Sie `gpresult /r` ein. Unter *Angewendete Gruppenrichtlinienobjekte* sollte nun `SEC-Workstations-Base` stehen.

> [!NOTE]
> **Portfolio-Tipp: Wie verhält sich Edubuntu (Linux)?**\
> Zeigen Sie in Ihrem Projektbericht technisches Tiefenwissen: Die **Passwort- und Kontosperrrichtlinien** (Default Domain Policy) gelten für das gesamte Active Directory. Das bedeutet: Auch wenn sich jemand am Linux-Client (`CL-UBU-01`) fünfmal mit einem falschen AD-Passwort anmeldet, sperrt der Domain Controller das Konto!\
> Die **Bildschirmsperre** (SEC-Workstations-Base) ist jedoch eine Windows-spezifische Registry-Einstellung. Sie wird vom Linux-Client ignoriert. Um eine Bildschirmsperre für Ubuntu zentral auszurollen, müsste man erweiterte Tools (wie Ansible, Chef oder spezielle SSSD-Policies) verwenden.
