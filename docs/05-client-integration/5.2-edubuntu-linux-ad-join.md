# 5.2 Edubuntu (Linux) AD-Join

## Zweck der Integration

Die Anbindung eines Edubuntu-Clients (`CL-UBU-01`) an das Active Directory (`ad.example.com`) ermöglicht es Benutzern, sich mit denselben Windows-Anmeldedaten (Single Sign-On Ansatz) am Linux-System anzumelden. Hierfür nutzen wir die modernen Linux-Dienste **realmd** (Realm Discovery) und **SSSD** (System Security Services Daemon).

## Vorbereitung: Dokumentierte Benutzerkonten

Für die Installation und den späteren Betrieb des Edubuntu-Clients kommen unterschiedliche Konten zum Einsatz. Es ist wichtig, den initialen lokalen Startbenutzer zu dokumentieren, da dieser für das Setup (sudo-Rechte) benötigt wird und als Notfall-Login dient, falls das Active Directory einmal nicht erreichbar sein sollte.

| **Kontotyp** | **Benutzername** | **Passwort (Lab-Standard)** | **Zweck** |
| --- | --- | --- | --- |
| **Lokaler Admin** | `edubuntu` | `<PASSWORT>` | Initiale Systemeinrichtung (sudo) und Notfall-Zugriff. |
| **AD-Benutzer** | `mvarga@ad.example.com` | *[Ihr AD-Passwort]* | Täglicher Login nach erfolgreichem Domänenbeitritt. |

## Schritt 1: Netzwerk & DNS vorbereiten

Genau wie beim Windows-Client ist ein funktionierendes DNS zur Domänenauflösung zwingend erforderlich.

**1.1** Öffnen Sie in Edubuntu die grafischen Netzwerkeinstellungen oder bearbeiten Sie die Netplan-Konfiguration (je nach Setup-Art).

**1.2** Stellen Sie sicher, dass als primärer DNS-Server die IP des Domain Controllers **`10.0.10.10`** eingetragen ist.

**1.3** Öffnen Sie ein Terminal und testen Sie die Auflösung:

```bash
    ping -c 3 ad.example.com
```

*Erfolg:* Die IP `10.0.10.10` muss antworten.

## Schritt 2: Installation der benötigten Pakete

Edubuntu benötigt Werkzeuge, um mit Kerberos und LDAP (den Kernprotokollen des Active Directorys) zu sprechen.

**Paketinstallation im Terminal**

```bash
sudo apt update
sudo apt install realmd sssd sssd-tools libnss-sss libpam-sss adcli samba-common-bin -y
```

## Schritt 3: Domänenentdeckung und Beitritt

Das Tool `realmd` sucht automatisch nach der SRV-Konfiguration der Domäne und konfiguriert die komplexen SSSD-Dateien im Hintergrund.

**Domänenbeitritt durchführen**

```bash
# 1. Domäne entdecken (Prüft, ob AD erreichbar ist)
realm discover ad.example.com

# 2. Der eigentliche Join (Benötigt einen Domain-Admin)
sudo realm join -U adm-t0-mvarga ad.example.com
```

Geben Sie das Passwort Ihres Tier-0 Admins ein. Wenn keine Fehlermeldung erscheint, war der Join erfolgreich.

## Schritt 4: Home-Verzeichnisse & Rechte konfigurieren

Standardmäßig legt Linux beim ersten Login eines AD-Benutzers kein lokales Home-Verzeichnis (`/home/...`) an. Dies müssen wir PAM (Pluggable Authentication Modules) mitteilen.

**Automatisches Erstellen von Home-Verzeichnissen**

```bash
sudo pam-auth-update --enable mkhomedir
```

## Schritt 5: Verifizierung & Login

Prüfen Sie nun, ob der Linux-Client das Active Directory erfolgreich lesen kann.

**AD-Benutzer abfragen**

```bash
# Fragen Sie einen AD-Benutzer ab
id mvarga@ad.example.com

# Soll-Ausgabe (Beispiel):
# uid=183401103(mvarga@ad.example.com) gid=183400513(domain users@ad. example.com)...
```

**Grafischer Login (Edubuntu GUI):**

1. Melden Sie sich vom aktuellen lokalen Edubuntu-Benutzer ab.

1. Wählen Sie auf dem Anmeldebildschirm **Anderer Benutzer** (oder „Not listed?“).
2. Geben Sie als Benutzernamen `mvarga@ad.example.com` und Ihr Windows-Passwort ein.

> [!IMPORTANT]
> **Integration ins Tier-Modell (Sudo-Rechte)**\
> Wie bei Windows-Clients (Modul 5.1) taucht Edubuntu nun im AD-Container `CN=Computers` auf. Verschieben Sie auch dieses Objekt in die Tier-2 Workstations OU.
>
> Wenn Sie möchten, dass bestimmte AD-Benutzer (z. B. `adm-t2-mvarga`) auf Edubuntu **root-Rechte (sudo)** erhalten, fügen Sie diese der sudoers-Datei hinzu:
>
> `sudo visudo`\
> *`# Fügen Sie am Ende der Datei folgende Zeile ein:`*\
> `adm-t2-mvarga@ad.example.com ALL=(ALL) ALL`
