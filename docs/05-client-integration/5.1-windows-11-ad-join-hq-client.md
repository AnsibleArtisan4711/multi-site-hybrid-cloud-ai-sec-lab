# 5.1 Windows 11 AD-Join (HQ Client)

## Voraussetzungen

Stellen Sie sicher, dass die virtuelle Maschine **`CL-WIN-01`** in Hyper-V (Host 1) läuft, Windows 11 (bzw. Windows 10/11 Enterprise/Pro) installiert ist und die VM mit dem **`vSwitch-LAN`** verbunden ist. *Hinweis: Windows Home Editionen können nicht in ein Active Directory aufgenommen werden.*

## Schritt 1: Netzwerk- und DNS-Prüfung (Kritisch)

Der häufigste Fehler beim AD-Join ist eine falsche DNS-Konfiguration. Der Client **muss** den Domain Controller als primären DNS-Server eingetragen haben, sonst kann er den Namen `ad.example.com` nicht auflösen.

**1.1** Öffnen Sie die **Kommandozeile (CMD)** oder **PowerShell** auf `CL-WIN-01`.

**1.2** Prüfen Sie die IP-Konfiguration: `ipconfig /all`

**1.3** Stellen Sie sicher, dass als **DNS-Server** die IP **`10.0.10.10`** (Ihr `SRV-DC-01`) eingetragen ist.

**1.4** Führen Sie einen Ping-Test aus: `ping ad.example.com`

- **Erfolg:** Die IP `10.0.10.10` antwortet. Der Join kann gestartet werden.
- **Fehlschlag:** Prüfen Sie die IPv4-Einstellungen der Netzwerkkarte. Tragen Sie `10.0.10.10` ggf. manuell als DNS-Server ein, falls Ihr DHCP dies nicht korrekt verteilt hat.

## Schritt 2: Domänenbeitritt (AD-Join)

Der Beitritt kann klassisch über die grafische Oberfläche (GUI) oder effizient per PowerShell erfolgen.

### Methode A: Per PowerShell (Empfohlen für das Portfolio)

Öffnen Sie die PowerShell als **Administrator** und führen Sie diesen Befehl aus:

**PowerShell AD-Join**

```powershell
Add-Computer -DomainName "ad.example.com" -Restart
```

Sie werden nach Anmeldedaten gefragt. Geben Sie hier die Zugangsdaten Ihres **Domain-Admins** (z. B. `adm-t0-mvarga@ad.example.com`) ein. Nach erfolgreicher Authentifizierung startet der Client automatisch neu.

### Methode B: Per GUI

1. Öffnen Sie die **Einstellungen** (Win + I) → **System** → **Info**.
2. Klicken Sie auf **Erweiterte Systemeinstellungen** (oder „Domäne oder Arbeitsgruppe beitreten“).
3. Klicken Sie im Reiter *Computername* auf **Ändern...**
4. Wählen Sie unter „Mitglied von“ den Punkt **Domäne** und tragen Sie `ad.example.com` ein.
5. Geben Sie die Domain-Admin Credentials ein und starten Sie das System neu.

## Schritt 3: Erster Login und Verifizierung

**3.1** Nach dem Neustart sehen Sie den Windows-Sperrbildschirm.

**3.2** Wählen Sie **Anderer Benutzer**.

**3.3** Melden Sie sich mit Ihrem in Modul 3.8 erstellten **Standard-Benutzerkonto** (Tier 2) an:

- **Benutzername:** `mvarga@ad.example.com`
- **Passwort:** [Ihr Standard-Passwort]

**3.4** Öffnen Sie die CMD und tippen Sie `whoami`. Die Ausgabe muss `ad\mvarga` lauten.

> [!IMPORTANT]
> **Sicherheits-Schritt: Computer-Objekt in die richtige OU verschieben**\
> Wenn ein Client der Domäne beitritt, landet das Computer-Objekt standardmäßig im Container **`CN=Computers`**. Dieser Container ist keine OU (Organizational Unit) und es können dort keine GPOs verknüpft werden!
>
> **Aktion auf dem DC (****`SRV-DC-01`****):**
>
> **a.)** Öffnen Sie *Active Directory-Benutzer und -Computer*.
>
> **b.)** Klicken Sie auf den Ordner **Computers**.
>
> **c.)** Klicken Sie mit der rechten Maustaste auf `CL-WIN-01` → **Verschieben**.
>
> **e.)** Erst jetzt greifen Sicherheitsrichtlinien und das spätere LAPS (Modul 5.5) für diesen Client.

**d.)** Wählen Sie Ihre Tier-2 Workstations-OU aus (z. B. `OU=Workstations,OU=Tier2,DC=ad,DC=example,DC=com`).
