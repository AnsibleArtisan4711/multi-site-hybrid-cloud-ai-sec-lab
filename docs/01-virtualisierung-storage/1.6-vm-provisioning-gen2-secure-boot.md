# 1.6 VM-Provisioning (Gen2 & Secure Boot)

## Architektur-Vorgabe: Generation 2

Alle neuen virtuellen Maschinen in diesem Projekt werden zwingend als **Generation 2** (Gen2) in Hyper-V angelegt. Ältere Gen1-VMs (BIOS, IDE-Controller) werden aus Sicherheits- und Performancegründen nicht mehr verwendet. Gen2 bietet UEFI-Firmware, Secure Boot, nativen PXE-Boot per Standard-Netzwerkkarte und eine deutlich höhere I/O-Performance durch virtuelle SCSI-Controller.

## Schritt-für-Schritt Anleitung: Anlegen einer leeren VM

Wiederholen Sie diese Schritte auf Host 1 und Host 2 für alle geplanten Systeme (DCs, Firewalls, Webserver, Clients). Das Betriebssystem wird in diesem Modul noch nicht installiert, es wird lediglich der „virtuelle Container“ gebaut.

1. **Hyper-V Manager öffnen:**\
   Öffnen Sie auf dem physischen Host den **Hyper-V-Manager**. Klicken Sie im rechten Aktionsbereich auf *Neu* → *Virtuelle Maschine...*
2. **Name und Speicherort:**\
   Vergeben Sie den Namen strikt nach der Namenskonvention aus Modul 0.2 (z. B. `SRV-DC-01` oder `FW-HQ-01`). Belassen Sie den Speicherort für die VM-Konfigurationsdateien zwingend auf der extrem schnellen **internen SSD** Ihres Hosts.
3. **Generation angeben:**\
   Wählen Sie **Generation 2**. *Achtung: Diese Einstellung kann nach der Erstellung nicht mehr geändert werden!*
4. **Speicher zuweisen (RAM):**\
   Orientieren Sie sich strikt an Modul 0.3 (Ressourcenplanung).

   - Für Infrastruktur (DC, Firewall, Kali): Tragen Sie den fixen Wert (z. B. 4096 MB) ein und **entfernen** Sie den Haken bei „Dynamischen Arbeitsspeicher verwenden“.
   - Für normale Clients (Windows 11, Ubuntu): Tragen Sie den Startwert ein und **setzen** Sie den Haken für dynamischen RAM.
5. **Netzwerk konfigurieren:**\
   Verbinden Sie die VM mit dem korrekten vSwitch (siehe Modul 1.1). Ein Domain Controller kommt in den **vSwitch-LAN**. Der Webserver kommt in den **vSwitch-DMZ**.\
   *Hinweis für OPNsense:* Die Firewall erhält im Assistenten zunächst nur einen Switch (z. B. vSwitch-WAN). Die anderen Schnittstellen (LAN/DMZ) müssen nach der Erstellung in den VM-Einstellungen („Hardware hinzufügen“) manuell ergänzt werden.
6. **Virtuelle Festplatte verbinden:**\
   Erstellen Sie eine neue VHDX-Datei auf der Host-SSD. Dimensionieren Sie die Festplatte passend (z. B. 60 GB für Windows Server, 20 GB für OPNsense).

7. **Installationsoptionen (ISO einbinden):**\
   Wählen Sie *„Betriebssystem von einer startbaren Imagedatei installieren“*. Navigieren Sie über das Netzwerk zum SMB-Share der UGreen NAS (Modul 1.5) und wählen Sie das ISO aus (z. B. `\\STO-NAS-01\ISOs\WindowsServer.iso`).
8. **Fertigstellen:**\
   Klicken Sie auf Fertigstellen. **Starten Sie die VM noch nicht!**

> [!WARNING]
> **Kritischer Zwischenschritt: Die Secure Boot Falle bei Linux & FreeBSD**\
> Bevor Sie eine VM mit Linux (Ubuntu, Kali) oder FreeBSD (OPNsense) starten, **müssen** Sie deren Sicherheitseinstellungen anpassen, da diese sonst sofort mit der Fehlermeldung *„Image failed to verify“* abbrechen!
>
> - Klicken Sie mit der rechten Maustaste auf die neu erstellte VM → **Einstellungen**.
> - Wechseln Sie links zum Menüpunkt **Sicherheit**.
> - **Für Ubuntu & Kali Linux:** Ändern Sie die Vorlage für den sicheren Start von *Microsoft Windows* auf ***Microsoft UEFI Certificate Authority***.
> - **Für OPNsense (FreeBSD):** Da FreeBSD keine standardmäßig signierten Bootloader für Hyper-V mitbringt, **deaktivieren** Sie den Haken bei *„Sicheren Start aktivieren“* (Secure Boot) für diese spezifische Firewall-VM komplett.

## Automatisierung für Fortgeschrittene (Optional)

Um Zeit zu sparen und Tippfehler zu vermeiden, können Sie VMs elegant per PowerShell provisionieren. Hier ein Beispiel für den Aufbau des zweiten Domain Controllers in der Filiale:

**PowerShell-Provisioning einer Gen2 VM**

```powershell
New-VM -Name "SRV-DC-02" -Generation 2 -MemoryStartupBytes 4GB -SwitchName "vSwitch-LAN" -NewVHDPath "C:\Hyper-V\Virtual Hard Disks\SRV-DC-02.vhdx" -NewVHDSizeBytes 60GB
Set-VMMemory -VMName "SRV-DC-02" -DynamicMemoryEnabled $false
Set-VMDvdDrive -VMName "SRV-DC-02" -Path "\\STO-NAS-01\ISOs\WindowsServer.iso"
```
