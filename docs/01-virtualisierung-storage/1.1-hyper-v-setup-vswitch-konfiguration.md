# 1.1 Hyper-V Setup & vSwitch Konfiguration

## Schritt 1: Installation der Hyper-V Rolle

Das Fundament des Labs bildet der Microsoft Hypervisor. Die Installation muss auf **Host 1 (HQ)** und **Host 2 (Filiale)** durchgeführt werden. Dies kann über den Server-Manager erfolgen, wird hier aber als Best Practice über die PowerShell abgebildet.

**PowerShell-Befehl zur Installation von Hyper-V auf Windows Server**

```powershell
Install-WindowsFeature -Name Hyper-V -IncludeManagementTools -Restart
```

## Schritt 2: Design der virtuellen Switches (vSwitches)

Die korrekte Trennung des Netzwerkverkehrs ist für die OPNsense-Firewalls und die Isolation der DMZ zwingend erforderlich. Wir richten auf beiden Hosts dedizierte vSwitches ein.

### Host 1 (Hauptquartier)

Host 1 benötigt ein komplexeres Netzwerkdesign, da hier WAN, LAN und DMZ aufeinandertreffen.

- **vSwitch-WAN (Typ: Extern):** Wird mit der physischen Netzwerkkarte (NIC) des Hosts verbunden, die Zugang zum Heimnetz/Internet hat.
- **vSwitch-LAN (Typ: Privat / Intern):** Ein isoliertes Netz (`10.0.10.0/24`) für `SRV-DC-01`, `CL-WIN-01` und `CL-UBU-01`.
- **vSwitch-DMZ (Typ: Privat):** Ein strikt isoliertes Netz (`10.0.20.0/24`) ausschließlich für den Apache-Webserver.

### Host 2 (Filiale)

Host 2 hat ein einfacheres Setup, da keine Web-DMZ existiert.

- **vSwitch-WAN (Typ: Extern):** Verbindung zum Heimnetz/Internet.
- **vSwitch-LAN (Typ: Privat / Intern):** Ein isoliertes Netz (`10.0.30.0/24`) für `SRV-DC-02` und `CL-KALI-01`.

## Schritt 3: vSwitch-Zuweisung an die OPNsense (Vorschau)

Die OPNsense-VMs auf beiden Hosts fungieren als Router. Sie sind die *einzigen* VMs, die mit mehreren vSwitches gleichzeitig verbunden werden.

| **VM (Firewall)** | **Virtuelle NICs (vNIC)** | **Verbundener vSwitch** |
| --- | --- | --- |
| **FW-HQ-01** | vNIC 1 (WAN) | vSwitch-WAN (Internet) |
|  | vNIC 2 (LAN) | vSwitch-LAN (10.0.10.1) |
|  | vNIC 3 (DMZ) | vSwitch-DMZ (10.0.20.1) |
| **FW-FIL-01** | vNIC 1 (WAN) | vSwitch-WAN (Internet) |
|  | vNIC 2 (LAN) | vSwitch-LAN (10.0.30.1) |

> [!WARNING]
> **Achtung (Sicherheitsrisiko bei LAN & DMZ):**\
> Nutzen Sie für das LAN und die DMZ zwingend den vSwitch-Typ **Privat**. Nur dieser garantiert, dass der Hyper-V-Host auf Netzwerkebene vollständig von den VMs isoliert ist. Würden Sie den Typ *Intern* wählen, erstellt Hyper-V automatisch einen virtuellen Netzwerkadapter auf dem Host, wodurch dieser die OPNsense-Firewall theoretisch umgehen könnte. Die geforderte Netz-Trennung wäre damit durchbrochen.

> [!IMPORTANT]
> **Wichtiger Hinweis zum Externen vSwitch (Heimnetz-Konflikte vermeiden):**\
> Beim Einrichten des `vSwitch-WAN` (Typ: Extern) wird die virtuelle Firewall direkt in Ihr physisches Heimnetzwerk gebrückt. Um Ihr bestehendes LAN nicht zu stören, beachten Sie zwingend:
>
> - **Verbindung des Hosts erhalten:** Wenn Ihr physischer Server nur *eine* Netzwerkkarte besitzt, **muss** beim Erstellen des externen vSwitch die Option *„Gemeinsames Verwenden dieses Netzwerkadapters für das Verwaltungsbetriebssystem zulassen“* **aktiviert** bleiben. Sonst sperren Sie sich selbst aus dem Host aus!
> - **Rogue DHCP verhindern:** Aktivieren Sie **niemals** einen DHCP-Server auf dem WAN-Interface der OPNsense. Bezieht die WAN-Schnittstelle eine statische IP, muss diese zwingend *außerhalb* des DHCP-Bereichs (Pools) Ihres Heimrouters (z. B. FritzBox) liegen, um IP-Adresskonflikte zu vermeiden.
