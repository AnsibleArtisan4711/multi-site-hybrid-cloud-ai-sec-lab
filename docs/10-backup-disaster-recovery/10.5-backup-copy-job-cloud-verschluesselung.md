# 10.5 Backup Copy Job & Cloud-Verschlüsselung

## Konzept: Unabhängige Ketten & Zero Knowledge

Ein **Backup Copy Job** in Veeam ist kein simples „Copy & Paste“ auf Dateiebene. Er liest die Daten aus dem primären Backup-Repository (Laufwerk B:) und generiert eine völlig unabhängige Backup-Kette auf dem sekundären Repository (Laufwerk A:).

**Die strategischen Vorteile für Ihr Lab:**

1. **AES-256 Verschlüsselung:** Der primäre Job (Laufwerk B:) bleibt unverschlüsselt für maximale Wiederherstellungsgeschwindigkeit (Instant VM Recovery). Der Copy Job auf Laufwerk A: wird stark verschlüsselt. Wenn `rclone` diese Dateien zu Google Drive synchronisiert, landen sie als unverlesbarer Datenblock in der Cloud (*Zero Knowledge*).
2. **GFS-Aufbewahrung (Grandfather-Father-Son):** Auf der riesigen 14TB Festplatte können wir wöchentliche und monatliche Vollbackups für eine langfristige Archivierung vorhalten, während das schnelle RAID 5 (Laufwerk B:) nur die letzten 14 Tage speichert.

## Schritt 1: Veeam Verschlüsselungs-Passwort anlegen

Bevor wir den Job erstellen, hinterlegen wir das Passwort im Password Manager von Veeam.

**1.1** Öffnen Sie die **Veeam Backup & Replication Console**.

**1.2** Klicken Sie ganz oben links auf das Hauptmenü (die drei Striche) → **Passwords**.

**1.3** Klicken Sie auf **Add...**

**1.4** Geben Sie ein extrem starkes Kennwort ein (z. B. generiert aus Ihrem Passwort-Manager).

**1.5 Hint (Hinweis):** Geben Sie einen Hinweis ein, den nur Sie verstehen. Achtung: Wenn Sie dieses Passwort verlieren, sind alle Backups in der Cloud und auf Laufwerk A: unwiderruflich zerstört!

## Schritt 2: Backup Copy Job erstellen

Wir erstellen nun den Job, der die Daten vom Primary Repo auf das Secondary Repo (die 14TB Platte) kopiert.

**2.1** Navigieren Sie zu **Home** → **Backup Copy** → **Virtual machine**.

**2.2 Name:** Vergeben Sie den Namen `COPY-To-Secondary-Encrypted`.

**2.3 Objects:** Klicken Sie auf *Add* → *From jobs* und wählen Sie Ihre primären Backup-Jobs (`JOB-Core-Infrastructure` und `JOB-T1-T2-Workloads`) aus.

**2.4 Target (Ziel):**

- Wählen Sie das in Modul 10.4 erstellte **`REPO-NAS-Secondary`** (Laufwerk A:).
- *Retention policy:* Stellen Sie z. B. 7 Tage ein.
- Setzen Sie den Haken bei **Keep some backups longer for archival purposes** (GFS). Stellen Sie z. B. ein, dass 4 wöchentliche und 12 monatliche Backups behalten werden. Die 14TB Festplatte bietet dafür genug Platz.

**2.5 Target** → **Advanced** → **Storage:**

- Setzen Sie zwingend den Haken bei **Enable backup file encryption**.
- Wählen Sie das in Schritt 1 angelegte Passwort aus.

**2.6 Schedule:** Belassen Sie es auf *Any time (Continuous)*. Veeam wartet automatisch, bis der primäre Backup-Job fertig ist, und startet dann sofort den Copy Job.

## Schritt 3: Cloud-Sync Skript anpassen

Da wir das `rclone`-Skript in Modul 10.4 vorbereitet haben, müssen wir es nun so anpassen, dass es die **verschlüsselten** Dateien aus dem neuen Copy-Job hochlädt und nicht die unverschlüsselten Originaldaten.

**3.1** Öffnen Sie Ihre Datei `C:\Scripts\CloudSync.ps1`.

**3.2** Ändern Sie den `$SourcePath` so, dass er auf Laufwerk A: (Ihr Secondary Repository) zeigt.

**Angepasstes Offsite-Sync Skript**

```powershell
$RcloneExe = "C:\rclone\rclone.exe"
# Pfad auf die 14TB Platte (Secondary Repo mit den verschluesselten Copy-Jobs)
$SourcePath = "A:\VeeamBackups\COPY-To-Secondary-Encrypted\"
$RemotePath = "GDrive:Veeam_Offsite_Backup"

# Sync starten
& $RcloneExe sync $SourcePath $RemotePath --transfers 4 --checkers 8 --verbose --log-file "C:\Logs\rclone_sync.log"
```

*Als Datei:* [`scripts/10-backup-disaster-recovery/10.5-angepasstes-offsite-sync-skript.ps1`](../../scripts/10-backup-disaster-recovery/10.5-angepasstes-offsite-sync-skript.ps1)

**3.1 Integration in Veeam:**

- Bearbeiten Sie Ihren `COPY-To-Secondary-Encrypted` Job.
- Gehen Sie zu **Target** → **Advanced** → **Scripts**.
- Aktivieren Sie das Post-Job-Script und binden Sie das geänderte `CloudSync.ps1` hier ein. (Vergessen Sie nicht, es aus dem primären Job aus Modul 10.4 zu entfernen, damit es nicht doppelt läuft).

> [!NOTE]
> **Portfolio-Check: Die perfekte Architektur**\
> Mit diesem Setup haben Sie eine Architektur geschaffen, die selbst in Enterprise-Konzernen als „Gold Standard“ gilt:
>
> - **Performance (Tier 1):** Die schnellen 8TB Platten (RAID 5 + NVMe) halten unverschlüsselte, sofort bootbare Backups der letzten 14 Tage.
> - **Archiv (Tier 2):** Die große 14TB Platte hält verschlüsselte Langzeit-Archive (Monate/-Jahre).
> - **Cloud (Tier 3):** Google Drive enthält einen perfekten Spiegel von Tier 2. Die Daten liegen absolut sicher (AES-256), vor Hacker-Zugriffen in der Cloud und vor lokalen Elementarschäden geschützt.
