# 10.7 Active Directory Item-Level Recovery (Veeam Explorer)

## Konzept: Warum granulare Wiederherstellung?

Das Wiederherstellen eines kompletten Domain Controllers aus einem Backup ist gefährlich, solange noch andere DCs (wie der `SRV-DC-02`) im Netzwerk aktiv sind. Ein zurückgesetzter DC hat veraltete Update-Nummern (USNs), was die Replikation im Active Directory unwiderruflich zerstören kann (*USN Rollback*).

Um einen versehentlich gelöschten Benutzer zu retten, nutzt man daher **Item-Level Recovery**. Da wir in Modul 10.2 *Application-Aware Processing* im Veeam-Job aktiviert haben, versteht Veeam die interne Struktur der Active Directory-Datenbank (`NTDS.dit`) im Backup und kann gezielt Einzelobjekte zurück in den laufenden Domänenbetrieb injizieren.

## Schritt 1: Die Fehler-Simulation (Das „Desaster“)

Wir simulieren den klassischen Administrationsfehler im Hauptquartier.

**1.1** Melden Sie sich auf dem **`SRV-DC-01`** an.

**1.2** Öffnen Sie **Active Directory-Benutzer und -Computer**.

**1.3** Löschen Sie den Testbenutzer **`schulung@example.com`** (oder einen dedizierten Test-User).

**1.4** *Beweis:* Das Konto ist nun aus der Domäne verschwunden. Ein Login an den Clients ist für diesen Benutzer nicht mehr möglich.

## Schritt 2: Start des Veeam Explorers

Wechseln Sie auf den Backup-Server (`SRV-BKP-01`), um die Rettung einzuleiten.

**2.1** Öffnen Sie die **Veeam Backup & Replication Console**.

**2.2** Navigieren Sie im linken Menü zu **Home** → **Backups** → **Disk**.

**2.3** Klappen Sie den `JOB-Core-Infrastructure` auf.

**2.4** Rechtsklick auf den **`SRV-DC-01`** → **Restore application items** → **Microsoft Active Directory objects...**

**2.5** Wählen Sie den letzten funktionierenden Wiederherstellungspunkt (z. B. das nächtliche Backup von 02:00 Uhr) und klicken Sie auf **Finish**.

**2.6** Veeam mountet nun das Backup der C-Platte im Hintergrund und startet automatisch den **Veeam Explorer for Microsoft Active Directory**.

## Schritt 3: Der Restore-Vorgang

Der Veeam Explorer präsentiert Ihnen die AD-Struktur genau so, wie sie zum Zeitpunkt des Backups aussah.

**3.1** Navigieren Sie im linken Baum zu Ihrer Domäne `ad.example.com` und klicken Sie auf den Button **Compare with Production** (oben im Menüband).

**3.2** Veeam vergleicht nun das Backup mit dem live laufenden Active Directory. Geänderte Objekte werden gelb, gelöschte Objekte **rot** markiert.

**3.3** Navigieren Sie zu Ihrer OU (z. B. *Tier2* → *CloudSyncUsers*). Der Benutzer `Schulung` sollte dort durchgestrichen oder markiert sein.

**3.4** Rechtsklick auf den Benutzer → **Restore to** **`ad.example.com`**.

**3.5 Passwort-Wiederherstellung:** Veeam fragt, ob das Kennwort ebenfalls wiederhergestellt werden soll. Wählen Sie **Restore passwords** aus (dies stellt den Kennwort-Hash wieder her, sodass der Benutzer sein altes Kennwort behält).

**3.6** Warten Sie wenige Sekunden, bis die Erfolgsmeldung erscheint.

## Schritt 4: Verifizierung im Active Directory

Wechseln Sie zurück auf den **`SRV-DC-01`**.

**4.1** Aktualisieren Sie die Ansicht in *Active Directory-Benutzer und -Computer* (Taste F5).

**4.2** Der Benutzer **`schulung`** ist wieder exakt in der richtigen OU vorhanden.

**4.3 Tiefenprüfung:** Öffnen Sie die Eigenschaften des Benutzers. Sie werden sehen, dass nicht nur der Name, sondern **alle** Metadaten (Mitgliedschaft in Gruppen, Profilpfade, E-Mail-Adressen) exakt so wiederhergestellt wurden, wie sie vor dem Löschen waren.

> [!NOTE]
> **Portfolio-Highlight: Veeam Explorer vs. AD Papierkorb**\
> Erklären Sie im Projektbericht den Unterschied zwischen dieser Methode und dem nativen „Active Directory Papierkorb“ (AD Recycle Bin):
>
> - Der AD-Papierkorb ist schnell und hält gelöschte Objekte meist 180 Tage lang im laufenden AD vorrätig.
> - **Das Alleinstellungsmerkmal von Veeam:** Wenn eine Schadsoftware (oder ein fehlerhaftes Skript) nicht nur Objekte *löscht*, sondern hunderte Attribute *abändert* (z. B. alle Telefonnummern überschreibt oder Gruppenzugehörigkeiten löscht), hilft der AD-Papierkorb nicht, da das Objekt nicht gelöscht, sondern nur verändert wurde. Veeam hingegen kann einzelne veränderte Attribute erkennen (Compare State) und gezielt das Attribut auf den Stand von gestern Nacht zurückrollen. Zudem sind die Veeam-Backups durch die Cloud-Anbindung (Modul 10.4) **Offsite-sicher**.

> [!IMPORTANT]
> **Auswirkung auf Microsoft 365 (Entra ID):**\
> Wenn der Sync-Agent (Modul 6.2) das Fehlen des Benutzers bemerkt hat, wurde das Cloud-Postfach möglicherweise kurzzeitig in den Papierkorb verschoben (Soft-Delete). Durch die schnelle lokale Wiederherstellung mit Veeam erkennt Entra Connect beim nächsten Durchlauf (max. 30 Minuten) den Benutzer wieder und stellt den Cloud-Account ohne Datenverlust wieder her.
