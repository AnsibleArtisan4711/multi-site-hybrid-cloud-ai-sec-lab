# 10.1 Veeam Backup & Replication (Installation & Setup)

## Konzept: Der Backup-Server als Hochsicherheitszone

Backups sind die letzte Verteidigungslinie gegen Ransomware und Hardware-Ausfälle. Der Backup-Server benötigt weitreichende Privilegien, um virtuelle Maschinen und Domain Controller zu sichern.

**Sicherheits-Einstufung (Tier 0):** Da der Backup-Server Kopien der Active Directory Datenbank (NTDS.dit) anlegt und verwaltet, wird er **zwingend als Tier-0-Ressource** behandelt. Wer den Backup-Server kontrolliert, kontrolliert die Domäne. Er muss daher strikt vom regulären Datenverkehr (Tier 1/2) isoliert werden.

## Schritt 1: Bereitstellung der VM (SRV-BKP-01)

Wir erstellen eine dedizierte virtuelle Maschine für Veeam auf Host 1 (HQ).

**1.1 VM-Spezifikationen:**

- Name: **`SRV-BKP-01`**
- RAM: **8 GB** (Statisch). Veeam und die dazugehörige PostgreSQL-Datenbank benötigen konsistenten Arbeitsspeicher.
- Netzwerk: **vSwitch-LAN** (`10.0.10.20`).

**1.2 Installation & AD-Join:** Installieren Sie Windows Server, benennen Sie den Hostnamen um und fügen Sie den Server der Domäne `ad.example.com` hinzu.

**1.3 AD-Verschiebung:** Verschieben Sie das Computer-Objekt im Active Directory in die **Tier 0 Server OU**.

## Schritt 2: Vorbereitung des iSCSI-Speichers

Bevor Veeam installiert wird, müssen wir den in **Modul 1.4** erstellten iSCSI-Speicherplatz vom UGreen NAS anbinden. Dies wird das primäre *Backup Repository*.

**2.1** Öffnen Sie den **iSCSI-Initiator** auf `SRV-BKP-01`.

**2.2** Verbinden Sie sich mit der statischen IP Ihres NAS (`10.0.10.250`).

**2.3** Öffnen Sie die **Datenträgerverwaltung** (`diskmgmt.msc`).

**2.4** Initialisieren Sie das neue iSCSI-Laufwerk als **GPT**.

**2.5** **Kritisch:** Formatieren Sie das Laufwerk zwingend mit **ReFS (Resilient File System)** und einer Blockgröße von **64K**. (Dies ermöglicht die platzsparenden *Fast Clone* Operationen von Veeam). Vergeben Sie den Laufwerksbuchstaben **B:** (für Backups).

## Schritt 3: Installation von Veeam Backup & Replication

Laden Sie die kostenlose Veeam Community Edition (VBR v12 oder neuer) als ISO-Datei herunter.

**3.1** Binden Sie das Veeam ISO-Image in Hyper-V an den `SRV-BKP-01` ein und führen Sie die `Setup.exe` aus.

**3.2** Klicken Sie auf **Install Veeam Backup & Replication**.

**3.3 Lizenz:** Überspringen Sie die Abfrage (das Setup wechselt dann in die Community Edition für bis zu 10 Workloads).

**3.4 Komponenten:** Das Setup prüft auf fehlende Systemkomponenten (wie.NET Framework) und installiert diese auf Knopfdruck nach.

**3.5 Datenbank:** Veeam v12 nutzt standardmäßig **PostgreSQL** als interne Konfigurationsdatenbank. Belassen Sie die Standardeinstellungen (die Datenbank wird automatisch lokal mitinstalliert).

**3.6** Klicken Sie auf **Install**. Der Vorgang kann je nach Festplattengeschwindigkeit 10 bis 20 Minuten dauern.

## Schritt 4: Erster Start & Infrastruktur einbinden

Nach dem obligatorischen Neustart öffnen Sie die **Veeam Backup & Replication Console**.

**4.1** Navigieren Sie unten links zum Reiter **Backup Infrastructure**.

**4.2** Klicken Sie auf **Managed Servers** → **Add Server**.

**4.3** Wählen Sie **Microsoft Hyper-V** aus.

**4.4 Host 1 (HQ):** Geben Sie die IP oder den DNS-Namen Ihres physischen Hyper-V Hosts ein. Sie benötigen dafür die lokalen administrativen Zugangsdaten des physischen Windows Servers.

**4.5 Host 2 (Filiale):** Fügen Sie analog auch den zweiten Host aus der Filiale hinzu.

**4.6** Veeam installiert nun im Hintergrund kleine Agenten auf Ihren physischen Hosts, um mit dem Hypervisor zu kommunizieren und Snapshots der VMs ansteuern zu können.

> [!NOTE]
> **Portfolio-Check: Architektur der Backup-Sicherheit**\
> Dokumentieren Sie die strategische Entscheidung für iSCSI statt SMB. Würde das Backup-Repository als normales Netzwerklaufwerk (SMB Share) angebunden, wäre es anfällig für jede Ransomware, die den `SRV-BKP-01` befällt. Da iSCSI als blockbasierter Speicher auf ReFS läuft, hält das NAS die Datenhoheit getrennt. Für einen vollumfänglichen Schutz implementieren wir im nächsten Schritt die **3-2-1 Backup-Regel**.
