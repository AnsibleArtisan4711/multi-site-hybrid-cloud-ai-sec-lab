# 2.5 DMZ-Konfiguration & Isolation

## Konzept der Demilitarisierten Zone (DMZ)

Die DMZ auf **Host 1 (HQ)** dient der Absicherung des öffentlichen Webservers (`SRV-WEB-01`). Das Ziel ist eine strikte Isolation: Der Webserver soll aus dem Internet (WAN) erreichbar sein, darf aber unter keinen Umständen selbstständig eine Verbindung in das interne LAN (`10.0.10.0/24`) oder zur Filiale (`10.0.30.0/24`) initiieren können.

## Schritt 1: Hyper-V Netzwerkkonfiguration

Bevor die OPNsense den Traffic regeln kann, muss die virtuelle Hardware auf dem physischen Host 1 korrekt vorbereitet sein.

**1.1 vSwitch prüfen:**

Stellen Sie im Hyper-V Manager sicher, dass ein virtueller Switch vom Typ **Privat** mit dem Namen **`vSwitch-DMZ`** existiert (siehe Modul 1.1).

**1.2 Interface an FW-HQ-01 anhängen:**

Öffnen Sie die Einstellungen der VM `FW-HQ-01`. Fügen Sie eine neue *Netzwerkkarte* hinzu und verbinden Sie diese mit dem **`vSwitch-DMZ`**.

**1.3 Webserver verbinden:**

Öffnen Sie die Einstellungen der VM `SRV-WEB-01`. Verbinden Sie deren Netzwerkkarte ebenfalls mit dem **`vSwitch-DMZ`**. Trennen Sie alle anderen Netzwerkverbindungen dieser VM.

## Schritt 2: OPNsense Interface Aktivierung

Loggen Sie sich über den HQ-Client (`CL-WIN-01`) in das Web-Interface der OPNsense ein (`https://10.0.10.1`).

**2.1** Gehen Sie zu **Interfaces** → **[OPT1]**.

**2.2** Setzen Sie den Haken bei **Enable Interface**.

**2.3 Description:** Ändern Sie den Namen von *OPT1* auf **DMZ**.

**2.4 IPv4 Configuration Type:** Wählen Sie *Static IPv4*.

**2.5 IPv4 Address:** Tragen Sie `10.0.20.1` ein und wählen Sie `24` als Subnetzmaske.

**2.6** Klicken Sie auf **Save** und anschließend oben auf **Apply Changes**.

## Schritt 3: Firewall-Regeln (Die Isolations-Logik)

Dies ist der wichtigste Teil, um die Sicherheit des Hauptquartiers zu garantieren. Gehen Sie zu **Firewall** → **Rules** → **DMZ**.

| **Aktion** | **Protokoll** | **Quelle** | **Ziel** | **Beschreibung** |
| --- | --- | --- | --- | --- |
| **Block** | Any | DMZ net | LAN net | **Isolation:** Verhindert, dass der Webserver das interne HQ-Netz scannt. |
| **Block** | Any | DMZ net | FIL\_LAN (10.0.30.0/24) | **Isolation:** Verhindert Zugriff auf die Filiale. |
| **Pass** | DNS (UDP) | DMZ net | DMZ address | Erlaubt dem Webserver DNS-Anfragen an die Firewall. |
| **Pass** | Any | DMZ net | any | Erlaubt dem Webserver den Zugriff ins Internet (z. B. für Updates). |

> [!WARNING]
> **Wichtige Regel-Reihenfolge:**\
> In OPNsense werden Regeln von oben nach unten abgearbeitet (*First Match Wins*). Die **Block**-Regeln zum LAN müssen zwingend **über** der allgemeinen *Pass*-Regel ins Internet stehen. Andernfalls würde die Internet-Regel („Allow Any“) den Zugriff auf das interne Netz fälschlicherweise erlauben.

## Schritt 4: Verifizierung (Test)

- Ein Ping vom Webserver (`10.0.20.x`) zu `8.8.8.8` (Internet) muss **erfolgreich** sein.
- Ein Ping vom Webserver zum Domain Controller (`10.0.10.10`) muss **fehlschlagen**.
- Ein Ping vom LAN-Client (`10.0.10.x`) zum Webserver (`10.0.20.x`) sollte **erfolgreich** sein (da das LAN standardmäßig meist „Allow All“ hat), was für die Administration des Servers gewollt ist.
