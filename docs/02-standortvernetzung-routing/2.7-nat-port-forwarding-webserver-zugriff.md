# 2.7 NAT/Port-Forwarding & Webserver-Zugriff

## Konzept: Destination NAT (DNAT)

Da der Webserver (`SRV-WEB-01`) eine private IP-Adresse (`10.0.20.x`) besitzt, ist er aus dem Internet oder Ihrem Heimnetz nicht direkt adressierbar. Die OPNsense-Firewall nimmt Anfragen auf ihrer WAN-IP entgegen und leitet diese basierend auf Port-Regeln an das Ziel in der DMZ weiter. Dieser Vorgang wird als *Port-Forwarding* bezeichnet.

## Schritt 1: Vorbereitung der Webserver-IP

Bevor Sie das Forwarding einrichten, muss der Webserver eine feste IP haben.

- **Ziel-IP:** Wir legen für den Apache-Webserver die statische IP **`10.0.20.80`** fest.
- **Gateway:** Stellen Sie sicher, dass das Standard-Gateway des Webservers auf die DMZ-IP der OPNsense (`10.0.20.1`) zeigt, da Pakete sonst den Weg zurück zum Client nicht finden.

## Schritt 2: Konfiguration des Port-Forwardings (OPNsense HQ)

Loggen Sie sich in die WebGUI der `FW-HQ-01` ein und navigieren Sie zu **Firewall** → **NAT** → **Port Forward**.

**2.1 Regel für HTTP (Port 80) erstellen:**

Klicken Sie auf das Plus-Symbol (+):

- **Interface:** `WAN`
- **TCP/IP Version:** `IPv4`
- **Protocol:** `TCP`
- **Destination:** `WAN address`
- **Destination port range:** `HTTP` (von 80 bis 80)
- **Redirect target IP:** `10.0.20.80`
- **Redirect target port:** `HTTP`
- **Filter rule association:** `Add associated filter rule` (Wichtig: Erstellt automatisch die nötige Firewall-Regel!)

**2.2** Speichern Sie und wiederholen Sie den Vorgang analog für **HTTPS (Port 443)**.

**2.3** Klicken Sie oben auf **Apply Changes**.

## Schritt 3: Verifizierung der Firewall-Regeln

Durch die Option *„Add associated filter rule“* hat OPNsense automatisch Regeln auf dem WAN-Interface erstellt.

- Prüfen Sie unter **Firewall** → **Rules** → **WAN**, ob zwei neue Einträge vorhanden sind, die Traffic zu `10.0.20.80` auf den Ports 80 und 443 erlauben.

## Schritt 4: Der externe Test

Um zu prüfen, ob der Webserver erreichbar ist, nutzen Sie einen Browser auf Ihrem **physischen PC** (nicht in einer VM):

**4.1** Ermitteln Sie die WAN-IP der OPNsense (ersichtlich auf dem Dashboard der Firewall unter *Interfaces*). Beispiel: `192.168.1.50`.

**4.2** Geben Sie diese IP in den Browser Ihres physischen Rechners ein: `http://192.168.1.50`.

**4.3 Erfolg:** Wenn die Apache-Standardseite („It works¡‘) erscheint, war das NAT-Forwarding erfolgreich.

> [!WARNING]
> **Sicherheitshinweis für das Portfolio:**\
> Obwohl wir den Port 80/443 geöffnet haben, bleibt das interne Netzwerk (`10.0.10.0/24`) geschützt. Dank der in Modul 2.5 konfigurierten **DMZ-Isolation** könnte ein Angreifer, der den Webserver über diese Ports übernimmt, dennoch nicht auf den Domain Controller oder andere interne Ressourcen zugreifen. Dies ist der Kern des „Defense-in-Depth“ Konzepts.
