# 2.2 Interface-Konfiguration (WAN, LAN, DMZ)

## Zweck der Schnittstellen-Zuweisung

Nach der Basisinstallation von OPNsense müssen die virtuellen Netzwerkkarten (welche in Hyper-V mit den verschiedenen vSwitches verbunden wurden) den logischen Sicherheitszonen der Firewall zugewiesen werden. FreeBSD benennt Hyper-V Netzwerkkarten nach dem Treiber `hn` (Hyper-V Network), beginnend bei `hn0`.

## Schritt-für-Schritt: Zuweisung per Konsolen-Menü

Öffnen Sie die Hyper-V Konsole der jeweiligen Firewall und loggen Sie sich als `root` ein. Sie sehen nun das OPNsense Hauptmenü (Optionen 0 bis 13). Wählen Sie die Option **1) Assign interfaces**.

### A. Zuweisung auf FW-HQ-01 (Host 1)

Host 1 verfügt über drei Zonen. Geben Sie die Werte exakt so ein, wenn Sie danach gefragt werden:

1. **Do you want to set up VLANs now?** Tippen Sie `N` (Nein) und drücken Sie Enter.
2. **Enter the WAN interface name:** Tippen Sie `hn0` (verbunden mit vSwitch-WAN / Heimnetz).
3. **Enter the LAN interface name:** Tippen Sie `hn1` (verbunden mit vSwitch-LAN).
4. **Enter the Optional interface 1 name:** Tippen Sie `hn2` (verbunden mit vSwitch-DMZ).
5. **Enter the Optional interface 2 name:** Drücken Sie einfach leer **Enter**, um abzuschließen.
6. **Do you want to proceed?** Tippen Sie `Y` (Ja). Die Firewall speichert die Zuweisung und lädt das Menü neu.

### B. Zuweisung auf FW-FIL-01 (Host 2)

Host 2 verfügt nur über zwei Zonen (keine DMZ).

1. **VLANs?** Tippen Sie `N`.
2. **WAN interface:** Tippen Sie `hn0` (vSwitch-WAN).
3. **LAN interface:** Tippen Sie `hn1` (vSwitch-LAN).
4. **Optional interface 1:** Leer lassen (**Enter** drücken).
5. **Proceed?** Tippen Sie `Y`.

## Schritt-für-Schritt: IP-Adressen vergeben

Nachdem das Menü neu geladen wurde, wählen Sie Option **2) Set interface IP address**.

Das **WAN-Interface** können Sie bei beiden Firewalls auf DHCP belassen (Sie drücken für IPv4 DHCP einfach `Y`). Die Firewall bezieht dann eine Adresse aus Ihrem 192er-Heimnetzwerk. Konfigurieren Sie nun die statischen internen Netze:

| **Firewall** | **Interface** | **IP-Adresse** | **Subnetzmaske** |
| --- | --- | --- | --- |
| **FW-HQ-01** | LAN | `10.0.10.1` | `24` |
|  | OPT1 (DMZ) | `10.0.20.1` | `24` |
| **FW-FIL-01** | LAN | `10.0.30.1` | `24` |

*Während des Assistenten für das LAN-Interface werden Sie gefragt:*

- *Upstream IPv4 Gateway:* Drücken Sie **Enter** (None), da das LAN sein eigenes Gateway ist!
- *Enable DHCP server on LAN?* Tippen Sie **Y** (Ja). Geben Sie als Startbereich z. B. `10.0.10.100` und als Endbereich `10.0.10.200` ein. Dies ist essenziell, damit Ihr späterer Windows-Client sofort eine IP erhält, um das Web-Dashboard der OPNsense aufrufen zu können.

> [!NOTE]
> **Architektur-Hinweis: Der spätere DHCP-Konflikt mit Active Directory**\
> Die Aktivierung des DHCP-Servers auf der OPNsense ist ein **rein temporärer Zustand** für die Phase 2! In einer Microsoft-Enterprise-Umgebung muss der DHCP-Dienst vom Domain Controller verwaltet werden, damit die dynamische DNS-Registrierung der Clients im Active Directory fehlerfrei funktioniert.\
> **Der Migrationsplan:** Sobald in Phase 3 der Domain Controller (`SRV-DC-01`) installiert und mit der DHCP-Rolle ausgestattet wird, loggen wir uns in das OPNsense-Dashboard ein und **deaktivieren** den Firewall-DHCP-Server dauerhaft. Bis dahin dient er als zwingend notwendige „Starthilfe“.

> [!IMPORTANT]
> **Wichtig: Erstmaliger Zugriff auf die WebGUI (Das Dashboard)**\
> Aus Sicherheitsgründen blockiert OPNsense by default **alle** Zugriffe auf das Dashboard über das WAN-Interface (also von Ihrem physischen Host oder Laptop aus dem 192er-Netz).
>
> **Lösung für das Setup:**
>
> 1. Starten Sie die `CL-WIN-01` Client-VM in Hyper-V (verbunden mit vSwitch-LAN).
> 2. Der Client erhält per DHCP (das Sie gerade aktiviert haben) eine 10.0.10.x IP.
> 3. Öffnen Sie im Client den Browser und rufen Sie **`https://10.0.10.1`** auf, um das OPNsense-Dashboard zu öffnen.
