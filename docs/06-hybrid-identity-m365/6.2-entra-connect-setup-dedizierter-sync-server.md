# 6.2 Entra Connect Setup (Dedizierter Sync-Server)

## Konzept: Die Identitäts-Brücke zur Cloud

Microsoft Entra Connect (ehemals Azure AD Connect) ist das zentrale Bindeglied Ihrer HybridCloud-Infrastruktur. Es sorgt dafür, dass Benutzerkonten aus Ihrem lokalen Active Directory (`ad.example.com`) sicher in die Cloud (`example.com`) synchronisiert werden. In diesem Modul setzen wir die Installation auf einem dedizierten Member-Server um, um höchste Sicherheits- und Architektur-Standards zu erfüllen.

## Architektur-Entscheidung: Der dedizierte Sync-Server

In professionellen Umgebungen werden keine Drittanbieter-Agenten direkt auf Domain Controllern installiert. Wir nutzen den **`SRV-SYNC-01`** als exklusiven Identity-Gateway.

> [!WARNING]
> **Sicherheits-Fokus: Tier 0 Einstufung**\
> Obwohl der `SRV-SYNC-01` technisch ein Member-Server ist, wird er organisatorisch als **Tier 0 System** behandelt. Der Grund: Der Sync-Agent liest Passwort-Hashes aus dem AD aus. Wer Zugriff auf diesen Server erlangt, hat die Kontrolle über alle Identitäten.
>
> - Anmeldung nur für Domain-Admins (`adm-t0-...`).
> - Platzierung in einer geschützten OU (`OU=Tier0_Servers`).
> - Keine weiteren Rollen (wie File- oder Print-Dienste) auf diesem System.

## Vorbereitung des SRV-SYNC-01

Bevor der Agent installiert werden kann, muss das Basissystem bereitstehen:

**1. VM-Deployment:** Erstellen einer Gen2 VM mit Windows Server, statische IP `10.0.10.12`, DNS zeigt auf `10.0.10.10`.

**2. Domänenbeitritt:** Aufnahme in `ad.example.com`.

**3. Objekt-Management:** Verschieben des Servers in die Tier-0 OU im AD.

**4. Download:** Herunterladen des *Microsoft Entra Connect* Installers (`AzureADConnect.msi`) von der Microsoft-Website.

## Schritt-für-Schritt Installation (Custom Setup)

Führen Sie den Installer auf dem `SRV-SYNC-01` als Administrator aus.

### Initialisierung

Wählen Sie auf dem Begrüßungsbildschirm **NICHT** die Express-Einstellungen. Klicken Sie stattdessen unten auf **Anpassen (Customize)**. Dies ist der einzige Weg, um das OU-Filtering zu aktivieren und Ihren produktiven Tenant vor Kollisionen zu schützen.

### Benutzeranmeldung (User Sign-In)

Wählen Sie **Kennworthashsynchronisierung** (Password Hash Synchronization). Dies ermöglicht Ihren Benutzern (wie `schulung@example.com`), sich in M365 mit ihrem gewohnten lokalen Passwort anzumelden. Aktivieren Sie zusätzlich den Haken bei **Einmaliges Anmelden (Seamless SSO)**.

### Verbindung mit Microsoft Entra ID

Geben Sie die Zugangsdaten Ihres Cloud-Admins ein (`mika.varga@example.com`). Microsoft nutzt moderne Authentifizierung (MFA), halten Sie also Ihr Handy für die Bestätigung bereit.

### Verbindung mit Active Directory

Wählen Sie Ihren lokalen Forest `ad.example.com` aus.

- Wählen Sie **Neues AD-Konto erstellen**.
- Geben Sie die Zugangsdaten Ihres lokalen Enterprise-Admins (`adm-t0-mvarga`) ein.
- *Hinweis:* Entra Connect erstellt daraufhin im Hintergrund ein spezielles Dienstkonto (`MSOL_...`) im AD, das die Leserechte für die Synchronisation besitzt.

### OU-Filterung (Der Schutz-Mechanismus)

Dies ist der wichtigste Schritt des gesamten Projekts.

**1.** Wählen Sie **Ausgewählte Domänen und OUs synchronisieren**.

**2.** Klappen Sie den Baum `ad.example.com` auf.

**3.** Entfernen Sie den Haken ganz oben, um alle Standard-OUs abzuwählen.

**4.** Navigieren Sie zu *Tier2* und setzen Sie den Haken **AUSSCHLIESSLICH** bei der OU **`CloudSyncUsers`**.

**5. Ergebnis:** Nur Benutzer in dieser OU (wie Ihr Schulungs-Account) werden synchronisiert. Ihr Produktiv-Account in der Cloud bleibt sicher und unberührt.

### Optionale Features

Aktivieren Sie das **Kennwortrückschreiben (Password Writeback)**. Dies erlaubt Benutzern, ihr Passwort im Cloud-Portal (`myaccount.microsoft.com`) zu ändern, woraufhin es sofort sicher zurück in Ihr lokales Active Directory geschrieben wird.

## Verifizierung und Live-Monitoring

Nach Abschluss der Installation startet der erste Synchronisationszyklus.

### Der Synchronization Service Manager

Öffnen Sie im Startmenü die App **Synchronization Service**.

- Im Reiter *Operations* sehen Sie alle Sync-Vorgänge (*Full Import, Full Sync, Export*).
- Klicken Sie auf einen Eintrag vom Typ **Export** zum Ziel<em>...onmicrosoft.com</em>.
- Klicken Sie unter *Export Statistics* auf **Adds**. Hier muss nun Ihr Benutzer `schulung@example.com` erscheinen. Dies ist der Beweis, dass der User erfolgreich hochgeladen wurde.

### Cloud-Check & Lizenzierung

**1.** Loggen Sie sich unter `admin.microsoft.com` ein.

**2.** Unter **Aktive Benutzer** erscheint nun der User *Schulung* mit dem Status *Synchronisiert mit lokalem Active Directory*.

**3. Aktion:** Klicken Sie auf den Benutzer und weisen Sie ihm die zweite **Business Basic-Lizenz** zu. Erst jetzt wird das Postfach und der Teams-Zugang aktiviert.

> [!NOTE]
> **Portfolio-Highlight: Hybrid-Identity Troubleshooting**\
> Dokumentieren Sie für Ihr Portfolio, wie Sie den Erfolg des Syncs technisch nachgewiesen haben. Erwähnen Sie den *Synchronization Service Manager* und das *Soft-Matching* (falls der User vorher schon in der Cloud existierte). Erklären Sie zudem, warum das OU-Filtering die wichtigste Sicherheitsmaßnahme beim Betrieb von Test-Umgebungen in produktiven Tenants ist.
