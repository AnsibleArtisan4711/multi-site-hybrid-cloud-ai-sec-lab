# 6.6 Exchange Online Postfach-Test (End-to-End)

## Konzept: Verifizierung der Hybrid-Kette

Dieses Modul dient als finaler Funktionstest für die Phasen 3 und 6. Wir beweisen technisch, dass ein Benutzer, der im lokalen Active Directory (`ad.example.com`) erstellt wurde, nach der Synchronisation und Lizenzierung vollumfänglich auf die Microsoft 365 Cloud-Dienste zugreifen kann – und zwar mit seiner offiziellen E-Mail-Adresse `schulung@example.com` und seinem lokalen Kennwort.

## Schritt 1: Der Login in Outlook Web (OWA)

Wir testen den Zugriff von einem beliebigen Gerät mit Internetzugang (idealerweise vom physischen Host oder einem Smartphone), um die Unabhängigkeit vom lokalen Netzwerk zu demonstrieren.

**1.1** Öffnen Sie den Browser und rufen Sie `https://outlook.office.com` auf.

**1.2 Anmeldung:** Geben Sie den UPN des synchronisierten Benutzers ein: `schulung@example.com`.

**1.3 Passwort-Abfrage:** Geben Sie das Kennwort ein, das Sie lokal im Active Directory auf dem `SRV-DC-01` für diesen Benutzer vergeben haben.

**1.4 Bestätigung:** Da PHS (Modul 6.3) aktiv ist, akzeptiert Microsoft das lokale Passwort.

## Schritt 2: Erstmalige Postfach-Konfiguration

Beim ersten Aufruf müssen grundlegende Einstellungen vorgenommen werden.

- **Sprache:** Deutsch (Österreich/Deutschland).
- **Zeitzone:** (UTC+01:00) Amsterdam, Berlin, Bern, Rom, Wien.
- **Speichern:** Nach dem Speichern lädt die Outlook-Oberfläche.

## Schritt 3: Mail-Flow Test (Senden & Empfangen)

Ein aktives Postfach bedeutet noch nicht zwingend, dass E-Mails von außen ankommen (MX-Record Thematik).

### Test A: Interner Versand

Senden Sie eine E-Mail von `schulung@example.com` an Ihren Produktiv-Account (`mika.varga@example.com`).

- **Erwartung:** Die E-Mail kommt sofort an, da beide Konten im gleichen M365-Tenant liegen.

### Test B: Externer Empfang

Senden Sie eine E-Mail von einer privaten Adresse (z. B. Gmail, GMX) an `schulung@example.com`.

- **Voraussetzung:** Damit dies funktioniert, muss der MX-Record Ihrer Domain `example.com` im öffentlichen DNS (IONOS) auf Microsoft zeigen (z. B. `mvarga-at.mail.protection.outlook.com`).
- **Erwartung:** Die E-Mail erscheint im Posteingang des Web-Browsers.

## Schritt 4: Der „Härtetest“ – Passwortänderung

Um die Funktionalität des Entra Connect Sync-Agents (`SRV-SYNC-01`) final nachzuweisen:

**4.1** Loggen Sie sich auf dem lokalen `SRV-DC-01` ein.

**4.2** Ändern Sie das Passwort des Benutzers *Schulung* in *Active Directory-Benutzer und -Computer*.

**4.3** Warten Sie ca. 2-5 Minuten (oder erzwingen Sie einen Delta-Sync am Sync-Server).

**4.4** Versuchen Sie, sich erneut in Outlook Web anzumelden.

**4.5 Erfolg:** Das alte Passwort wird abgelehnt, das neue lokale Passwort funktioniert nun auch in der Cloud.

> [!NOTE]
> **Portfolio-Highlight: Single-Identity Strategie**\
> Dokumentieren Sie dieses Ergebnis als Beweis für Ihre **Single-Identity Strategie**. Der Benutzer muss sich nur noch ein einziges Passwort merken. Die IT-Abteilung muss Passwörter nur an einer zentralen Stelle (On-Premises AD) verwalten oder zurücksetzen. Dies reduziert Support-Aufwände und erhöht die Sicherheit, da Passwort-Richtlinien (Modul 5.3) zentral erzwungen werden.

> [!IMPORTANT]
> **Achtung beim Split-Brain DNS (Erinnerung):**\
> Falls Sie innerhalb Ihres Labors Outlook-Probleme haben, prüfen Sie Modul 3.5. Interne Clients müssen `autodiscover.example.com` korrekt auflösen können, um das Postfach automatisch einzurichten.
