# 6.4 Selektiver Sync (Organisationseinheiten-Filterung)

## Konzept: Scoping der Hybrid-Identität

In einer idealen Testumgebung, die denselben Microsoft 365 Tenant nutzt wie Ihr produktives System, ist das **OU-Filtering** (Organisationseinheiten-Filterung) die wichtigste Verteidigungslinie. Ohne selektiven Sync würde Microsoft Entra Connect jedes Objekt aus Ihrem lokalen Active Directory in die Cloud schieben.

**Ziele des selektiven Syncs:**

- **Schutz des Produktiv-Accounts:** Verhindert, dass lokale Lab-Daten Ihren Cloud-Admin (`mika.varga@example.com`) überschreiben.
- **Lizenz-Management:** Nur Benutzer, die wirklich in der Cloud arbeiten sollen (z. B. `schulung@example.com`), erhalten ein Cloud-Objekt und verbrauchen Lizenzen.
- **Übersichtlichkeit:** Vermeidung von „Datenmüll“ (Service-Accounts, Test-PCs, temporäre Gruppen) im Microsoft Entra ID Portal.

## Schritt 1: Den Konfigurations-Assistenten starten

Die Filterung wird direkt im Entra Connect Tool auf Ihrem dedizierten Sync-Server (`SRV-SYNC-01`) verwaltet.

**1.1** Starten Sie die App **Microsoft Entra Connect** auf dem Desktop.

**1.2** Klicken Sie auf **Konfigurieren** (Configure).

**1.3** Wählen Sie aus der Liste der Aufgaben: **Synchronisierungsoptionen anpassen** (Customize synchronization options) und klicken Sie auf *Weiter*.

**1.4** Authentifizieren Sie sich mit Ihrem Cloud-Global-Admin-Konto.

## Schritt 2: Domänen- und OU-Filterung anpassen

Nachdem Sie sich durch die Verzeichnisauswahl geklickt haben, erreichen Sie den entscheidenden Bildschirm.

**2.1** Wählen Sie die Option **Ausgewählte Domänen und OUs synchronisieren**.

**2.2** Klappen Sie den Baum Ihrer Domäne `ad.example.com` auf.

**2.3 Striktes Auswahl-Prinzip:**

- Entfernen Sie den Haken bei allen OUs, die keine Cloud-Identitäten enthalten sollen.

- Setzen Sie den Haken **nur** bei der in Modul 6.1 erstellten OU **`CloudSyncUsers`**.

**2.4** *Hinweis:* Wenn Sie später neue OUs erstellen (z. B. für eine neue Abteilung), müssen Sie diesen Assistenten erneut ausführen, um diese für den Sync freizuschalten.

## Schritt 3: Erzwungene Aktualisierung (Full Sync)

Wenn Sie OUs **entfernen**, die bereits synchronisiert wurden, löscht Entra Connect diese Benutzer in der Cloud (sie landen dort im „Papierkorb“ / Deleted Users). Um die Änderungen sofort wirksam zu machen:

**3.1** Schließen Sie den Assistenten ab und wählen Sie am Ende **Synchronisierungsvorgang starten...**.

**3.2** Alternativ können Sie einen vollständigen Abgleich per PowerShell erzwingen:

**PowerShell: Full Sync erzwingen**

```powershell
# Erzwingt einen kompletten Abgleich aller gefilterten OUs
Start-ADSyncSyncCycle -PolicyType Initial
```

## Schritt 4: Monitoring der Filterung

Um sicherzustellen, dass keine „unerwünschten“ Benutzer durchgerutscht sind, nutzen wir den **Synchronization Service Manager**.

**4.1** Öffnen Sie die App *Synchronization Service*.

**4.2** Gehen Sie in den Reiter **Connectors**.

**4.3** Wählen Sie den Connector *ad.example.com* aus.

**4.4** Klicken Sie rechts auf **Search Connector Space**.

**4.5** Wählen Sie unter *Scope* den Typ **Pending Import** oder **Disconnected Objects**. Hier sehen Sie genau, welche Objekte aufgrund Ihrer Filterung vom Sync ausgeschlossen wurden.

> [!TIP]
> **Sicherheits-Fazit für Ihr Portfolio:**\
> Durch das konsequente OU-Filtering haben Sie eine saubere Trennung zwischen lokaler Testumgebung und Cloud-Produktivumgebung geschaffen. Selbst wenn ein lokaler Benutzer den gleichen Namen wie ein Cloud-Benutzer hätte, würde Entra Connect diesen nicht synchronisieren, solange er sich in einer nicht markierten OU befindet. Dies reduziert die Komplexität und erhöht die Betriebssicherheit Ihres Hybrid-Setups massiv.
