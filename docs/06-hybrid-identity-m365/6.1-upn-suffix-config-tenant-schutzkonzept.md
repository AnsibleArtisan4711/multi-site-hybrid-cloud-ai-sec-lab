# 6.1 UPN-Suffix Config & Tenant-Schutzkonzept

## Architektur-Exkurs: Schutz des Produktiv-Tenants

Sie verfügen bereits über einen produktiven Microsoft 365 Tenant mit der verifizierten Domain `example.com` (Hauptbenutzer: `mika.varga@example.com`). Um die Produktivdaten nicht zu gefährden, die Testumgebung aber dennoch realitätsnah zu halten, nutzen wir eine **zweite M365 Business Basic-Lizenz** exklusiv für einen neuen Lab-Benutzer (`schulung@example.com`).

**Die Lösung (OU-Filtering):** Wir fügen der lokalen AD-Domäne (`ad.example.com`) das offizielle Suffix `example.com` hinzu. Anschließend erstellen wir den Testbenutzer lokal und beschränken das spätere Sync-Tool (Entra Connect) **strikt auf eine dedizierte Lab-OU**. Der Produktiv-Account wird vom Sync komplett ignoriert.

## Schritt 1: Das UPN-Suffix im Active Directory hinzufügen

Machen Sie das öffentliche Suffix im lokalen Active Directory bekannt. Führen Sie diese Schritte auf dem PDC (`SRV-DC-01`) aus:

**1.1** Öffnen Sie **Active Directory-Domänen und -Vertrauensstellungen**.

**1.2** Klicken Sie in der linken Spalte ganz oben mit der **rechten Maustaste** auf den Wurzelknoten (*Active Directory-Domänen...*) und wählen Sie **Eigenschaften**.

**1.3** Tragen Sie im Feld *Alternative UPN-Suffixe* Ihre öffentliche Domain ein: **`example.com`**

**1.4** Klicken Sie auf **Hinzufügen** und anschließend auf **OK**.

## Schritt 2: Den lokalen Lab-Benutzer (Schulung) erstellen

Nun erstellen wir den zweiten Benutzer und weisen ihm das neue Suffix zu.

**2.1** Öffnen Sie **Active Directory-Benutzer und -Computer**.

**2.2** Erstellen Sie in der OU *Tier 2* eine neue Unter-OU namens **`CloudSyncUsers`** (dies ist wichtig für das Filtering in Modul 6.2).

**2.3** Rechtsklick auf `CloudSyncUsers` → **Neu** → **Benutzer**.

**2.4 Vorname / Nachname:** z. B. `Lab` / `Schulung`.

**2.5 Benutzeranmeldename:** Tragen Sie im linken Feld **`schulung`** ein.

**2.6 Dropdown-Menü (Suffix):** Klicken Sie auf das Dropdown rechts daneben (wo `@ad.example.com` steht) und wählen Sie das soeben erstellte **`@example.com`** aus.

**2.7** Schließen Sie die Erstellung mit einem sicheren Passwort ab. *(Der Benutzer meldet sich fortan an allen lokalen Lab-Systemen mit* *`schulung@example.com`* *an!)*

## Schritt 3: Lizenz-Vorbereitung im M365 Admin Center

Bereiten Sie den Cloud-Tenant auf das Eintreffen des synchronisierten Benutzers vor.

**3.1** Loggen Sie sich mit Ihrem **Produktiv-Admin** (`mika.varga@...`) unter `admin.microsoft.com` ein.

**3.2 Lizenz kaufen:** Navigieren Sie zu **Abrechnung** → **Dienste kaufen**. Suchen Sie nach *Microsoft 365 Business Basic* und kaufen Sie **eine** weitere Lizenz für Ihr Abonnement.

**3.3 Benutzer anlegen (Optional vs. Empfohlen):**

- **Empfohlener Weg (Automatisierung):** Legen Sie den Benutzer in der Cloud *noch nicht* an. Warten Sie auf Modul 6.2. Der *Entra Connect Sync* wird das lokale Konto `schulung@example.com` vollautomatisch in Ihr M365 Admin Center hochladen. Nach dem erfolgreichen Sync weisen Sie dem neu erschienenen Benutzer einfach die gekaufte Business Basic Lizenz zu.
- **Soft-Matching Weg:** Falls Sie `schulung@example.com` in der Cloud bereits angelegt haben, ist das auch kein Problem. Der Sync erkennt die identischen Namen und „verschmilzt“ (Soft-Match) das Cloud-Konto mit Ihrem lokalen AD-Konto. Das lokale AD übernimmt dann die Passwort-Herrschaft.

> [!TIP]
> **Portfolio-Tipp: Hybrid Identity Management**\
> Dies ist der klassische Workflow in modernen Unternehmen: Die Personalabteilung legt einen neuen Mitarbeiter im lokalen AD an (inkl. E-Mail Suffix). Der Sync-Agent überträgt die Identität in die Cloud (Entra ID), und der IT-Administrator weist im M365 Portal nur noch die passende Lizenz zu, um Exchange-Postfach und Teams freizuschalten.
