# 6.3 Password Hash Sync (PHS) & Seamless SSO

## Konzept: Die nahtlose Benutzeranmeldung

Um eine moderne Hybrid-Cloud-Umgebung zu schaffen, müssen die lokale Authentifizierung (Active Directory) und die Cloud-Identität (Microsoft Entra ID) so gekoppelt werden, dass für den Benutzer keine Brüche entstehen. Wir implementieren hierfür zwei Kern-Technologien:

- **Password Hash Synchronization (PHS):** Sorgt dafür, dass Benutzer in der Cloud dasselbe Passwort wie lokal verwenden können.
- **Seamless Single Sign-On (SSO):** Sorgt dafür, dass Benutzer an Domänen-PCs beim Zugriff auf Cloud-Dienste (z. B. Teams oder OneDrive) gar kein Passwort mehr eingeben müssen.

## Teil 1: Password Hash Synchronization (PHS)

PHS ist das sicherste Verfahren, da die Identitätsprüfung direkt bei Microsoft erfolgt, aber auf Ihrem lokalen AD-Kennwort basiert.

### Der technische Sicherheits-Prozess

Entgegen verbreiteter Mythen überträgt der Sync-Server **keine Passwörter**.

1. Der lokale Domain Controller hält den Passwort-Hash (MD4-basiert).
2. Der Entra Connect Agent (`SRV-SYNC-01`) ruft diesen Hash ab.
3. Er wendet einen zusätzlichen *Salt* (Zufallswert) und eine **SHA256-Verschlüsselung** an (1000-faches Hashing).
4. Nur dieser neue „Cloud-Hash“ wird verschlüsselt an Microsoft gesendet.

## Teil 2: Seamless Single Sign-On (SSO)

Seamless SSO nutzt Kerberos-Tickets, um den Benutzer gegenüber der Cloud zu legitimieren.

### Voraussetzung: Das AD-Computerobjekt

Bei der Aktivierung von Seamless SSO erstellt Entra Connect im lokalen AD automatisch ein Computer-Objekt namens **`AZUREADSSOACC`**. Dieses Objekt fungiert als lokaler Kerberos-Endpunkt für die Cloud-Authentifizierung.

## Schritt 1: Aktivierung im Entra Connect Assistenten

Führen Sie diese Schritte auf dem dedizierten Sync-Server (`SRV-SYNC-01`) aus:

**1.1** Starten Sie *Microsoft Entra Connect* und wählen Sie **Konfigurieren**.

**1.2** Wählen Sie **Anmeldeoptionen für Benutzer ändern**.

**1.3** Geben Sie die Zugangsdaten Ihres M365 Global Admins (`mika.varga@example.com`) ein.

**1.4** Stellen Sie sicher, dass **Kennworthashsynchronisierung** ausgewählt ist.

**1.5** Setzen Sie den Haken bei **Einmaliges Anmelden aktivieren** (Enable single sign-on).

**1.6** Geben Sie die Zugangsdaten Ihres lokalen **Domänen-Admins** ein, um das SSO-Objekt im AD anzulegen.

## Schritt 2: GPO für die Intranet-Zonenzuweisung

Damit der Browser (Edge/Chrome) das SSO-Ticket automatisch an Microsoft sendet, muss die URL als sicher eingestuft werden.

**2.1** Erstellen Sie auf dem DC das GPO **`USR-Cloud-SSO-Settings`**.

**2.2** Pfad: *Benutzerkonfiguration* → *Richtlinien* → *Administrative Vorlagen* → *Windows-Komponenten* → *Internet Explorer* → *Internetsystemsteuerung* → *Sicherheitsseite*.

**2.3** Öffnen Sie **Liste der Site-zu-Zonenzuweisungen**.

**2.4** Fügen Sie folgendes Element hinzu:

- **Name:** `https://autologon.microsoftazuread-sso.com`
- **Wert:** `1` (Lokales Intranet)

## Schritt 3: Verifizierung & Test

Melden Sie sich als `schulung@example.com` an Ihrem Windows-Client an.

**3.1** Öffnen Sie den Browser und rufen Sie `https://portal.office.com` auf.

**3.2 Soll-Verhalten:** Das Portal erkennt Ihren Account und loggt Sie ohne Passwortabfrage ein.

**3.3 Sync-Check (PowerShell):** Führen Sie auf dem `SRV-SYNC-01` diesen Befehl aus:

```powershell
    Import-Module ADSync
    Get-ADSyncScheduler
```

Achten Sie darauf, dass der *PasswordHashSync* Status auf `True` steht.

> [!NOTE]
> **Portfolio-Check: Ausfallsicherheit (Survivability)**\
> Ein entscheidender Vorteil dieses PHS-Setups: Sollte Ihr lokales Labor oder der VPN-Tunnel komplett ausfallen (z. B. Brand im HQ), können sich Ihre Benutzer dennoch weiterhin an mobilen Geräten oder im Homeoffice bei M365 anmelden. Da der validierende Hash sicher in der Microsoft-Cloud liegt, ist die Anmeldung nicht von der Live-Verfügbarkeit Ihres Domain Controllers abhängig.
